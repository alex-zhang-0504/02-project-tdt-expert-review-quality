# TDRX评审表与评审专家打分表数据规范V0.1

> 状态：讨论稿｜日期：2026-08-03
> 目标：保证人使用的TDRX评审表能够稳定生成AI使用的评审专家打分表
> 本文只定义**字段、枚举、公式和校验**。评分规则、档位含义和业务口径以《TDT技术项目TDR评审专家质量考评与记录办法V0.1》（下称《办法》）为准，本文不重复叙述。

## 1．两表关系与ID

既有专家池提供专家身份和技术领域主数据。本项目新增两张表：

| 表 | 粒度 |
|---|---|
| TDRX评审表 | 一份表 ＝ 一次TDR评审场次 |
| 评审专家打分表 | 一行 ＝ 一位专家在一次评审场次中的一个角色记录 |

| ID | 格式 | 说明 |
|---|---|---|
| 评审ID | `项目编号-TDR节点-会议日期` | 两表关联主键 |
| 评审专家记录ID | `评审ID-专家ID` | 打分表主键 |

ID由系统生成并保持稳定，**禁止用专家姓名作为唯一标识**。

## 2．TDRX评审表

保持「会议信息 ＋ 评审范围与会签列表 ＋ 评审问题汇总」的人类可读结构。

### 2.1 会议信息区

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 评审ID | 是 | 文本 | 关联打分表 |
| 项目编号 | 是 | 文本 | — |
| 项目名称 | 是 | 文本 | — |
| TDR节点 | 是 | 枚举 | TDR1｜TDR2｜TDR3｜TDR1＋TDR2 |
| 会议日期 | 是 | 日期 | 评审实际发生时间 |
| PM | 是 | 人员 | — |
| 技术项目Owner | 是 | 人员 | 专业评分主评人 |
| 评审主席 | 是 | 人员 | 会议最终结论责任人 |
| 会议最终结论 | 是 | 枚举 | G｜GR｜NG |
| 最终结论说明 | 条件 | 长文本 | 最终GR、NG必填；最终G但处理过评委异议时必填 |

### 2.2 专家范围与预审区

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 专家ID | 是 | 关联 | 关联专家池 |
| 专家姓名 | 自动 | 文本 | 专家池带出 |
| 负责领域 | 是 | 多选 | 基带、射频、天线、质量等，可多选 |
| 是否主席 | 是 | 布尔 | 控制主席职责记录字段 |
| 主责范围 | 是 | 多选 | 最低责任领域，可多选 |
| 协审范围 | 否 | 多选 | 非主要责任领域 |
| 范围确认状态 | 是 | 枚举 | 已确认｜待确认｜材料不足 |
| 预审截止时间 | 是 | 日期时间 | 判断按时完成，也是改派类型的判定基准 |
| 预审状态 | 是 | 枚举 | 按时完成｜逾期完成｜未完成｜材料不足 |
| 预审记录链接 | 条件 | 链接 | 满分档／0分档必填 |

### 2.3 会签列表

改派部分**人工只填3个字段**（改派类型、改派确认时间、改派记录链接），有效性、应评归属和计次全部由公式推导（见 §3.5）。

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 专家ID | 是 | 关联 | 与范围区一致 |
| 负责领域 | 是 | 多选 | 与主责范围对应 |
| 参会状态 | 是 | 枚举 | 有效参加｜部分参加｜仅挂会无有效参与｜缺席 |
| **改派类型** | 否 | 枚举 | 无｜会前改派-原专家｜会前改派-接替｜临时改派-原专家｜临时支援｜组织原因调整 |
| **改派确认时间** | 条件 | 日期时间 | 改派类型≠「无」时必填；与预审截止时间比较 |
| **改派记录链接** | 条件 | 链接 | 改派类型≠「无」时必填；指向书面确认记录 |
| 关联专家ID | 自动 | 关联 | 由改派记录成对生成，不需人工两边录入 |
| 本人完成范围 | 是 | 枚举 | 全部｜部分｜未完成｜范围未确认 |
| 个人会签结论 | 是 | 枚举 | G｜GR｜NG |
| 评审意见 | 条件 | 长文本 | GR、NG必填；G可选 |
| 对应问题编号 | 条件 | 多值文本 | GR、NG至少关联一个问题编号 |
| 会签时间 | 是 | 日期时间 | — |

> **相比初版的变化**：原「缺席或改派状态（8值）＋改派原因类型（4值）＋改派有效标记＋计入应评场次标记＋计入个人改派次数标记」合并为上表3个人工字段，其余转为派生字段。组织调整、特殊豁免的处理规则仍待确认（《办法》§5.1）。

### 2.4 评审问题汇总区

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 问题编号 | 是 | 文本 | 场次内唯一 |
| 提出专家ID | 是 | 关联 | 关联会签记录 |
| 所属技术领域 | 是 | 枚举 | 证据与后验分析用 |
| 问题描述 | 是 | 长文本 | 明确问题、边界和对象 |
| 判断依据 | GR／NG必填 | 长文本 | 数据、标准、测试或技术逻辑 |
| 问题等级 | 是 | 枚举 | 一般建议｜风险｜阻断（枚举待试运行校准） |
| 是否需要修正 | 是 | 枚举 | 是｜否｜带风险推进 |
| 反馈／修改说明 | 是 | 长文本 | 项目侧处置说明 |
| 责任人 | 条件 | 人员 | 需要动作时必填 |
| 计划完成时间 | 条件 | 日期时间 | 需要动作时必填 |
| 指定复核专家ID | 否 | 关联 | 决定「问题闭环履约」是否适用 |
| 闭环状态 | 是 | 枚举 | 待处理｜处理中｜待复核｜已关闭｜不采纳 |
| 复核结论 | 条件 | 枚举／文本 | 指定复核后必填 |
| 复核时间 | 条件 | 日期时间 | 判断是否按期完成 |
| 闭环证据链接 | 条件 | 链接 | 测试、文档或变更证据 |

## 3．评审专家打分表

打分表是唯一评分数据源。长篇评审意见留在TDRX评审表，打分表只存评分、状态、证据引用和必要摘要。

### 3.1 识别与归属字段

| 字段 | 来源 |
|---|---|
| 评审专家记录ID | 系统（`评审ID-专家ID`） |
| 评审ID／项目编号／项目名称／TDR节点／会议日期 | 评审表 |
| PM／技术项目Owner | 评审表 |
| 评审表链接 | 系统 |

### 3.2 专家与会签字段

| 字段 | 来源 |
|---|---|
| 专家ID／专家姓名 | 专家池 |
| 负责领域 | 评审表（可多值，不拆分记录） |
| 是否主席 | 评审表（控制主席职责记录字段） |
| 主责范围摘要 | 评审表（不复制完整检查表） |
| 参会状态 | 评审表 |
| 改派类型／改派确认时间／改派记录链接 | 评审表 |
| 关联专家ID | 评审表 |
| 个人会签结论 | 评审表 |
| 评审意见摘要 | AI提取（保留原文链接和引用位置） |
| 对应问题编号 | 评审表 |

### 3.3 五项评分字段

每项至少保存 `档位`、`得分`、`证据`。档位含义见《办法》§3。

| 评分项 | 满分 | 允许档位 | 正式确认人 |
|---|---:|---|---|
| 会前预审 | 10 | 10｜5｜0｜不适用 | PM |
| 评审与会签履约 | 30 | 30｜15｜0｜不适用 | PM |
| 专业判断准确性 | 25 | 25｜15｜0<br>**初评仅可取 25｜15**；0分档初评只用于结论与当时材料存在事实性矛盾，其余0分由后验修正写入（《办法》§3.1） | 技术项目Owner主评，PM复核证据 |
| 判断依据与意见充分性 | 25 | 25｜15｜0 | 技术项目Owner主评，PM复核证据 |
| 问题闭环履约 | 10 | 10｜5｜0｜不适用 | PM |

专业两项的AI输出只能写入 `建议档位`，人工确认后才写入 `正式档位`。

### 3.4 主席职责记录字段

主席**不设独立评分字段**。两项附加职责按《办法》§2.4 纳入基础评分项判定，仅记录判定所需事实：

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 范围完整性确认结果 | 仅主席场次 | 枚举 | 全覆盖｜有维度标记不适用｜存在未覆盖维度 |
| 未覆盖维度说明 | 条件 | 长文本 | 「存在未覆盖维度」时必填；作为「评审与会签履约」判定证据 |
| 最终结论异议处理说明 | 条件 | 长文本 | 存在评委GR／NG异议时必填；作为「专业判断准确性」判定证据 |

### 3.5 派生字段与公式

**改派派生（人工不填）**：

| 字段 | 推导规则 |
|---|---|
| 改派有效标记 | 改派类型＝「会前改派-原专家」且 改派确认时间 ≤ 预审截止时间 且 接替专家记录满足（参会状态＝有效参加、本人完成范围＝全部、会签时间非空）→ 是；否则否 |
| 实际改派类别 | 改派有效标记＝是 → 会前正式改派；改派类型属改派类且改派有效标记＝否 → 临时改派；改派类型＝组织原因调整 → 组织原因 |
| 计入应评场次标记 | 实际改派类别＝会前正式改派（原专家）或 改派类型＝临时支援 → 否；其余 → 是 |
| 计入个人改派次数标记 | 实际改派类别∈{会前正式改派, 临时改派} 且 改派类型指向原专家 → 是；组织原因 → 否 |

**评分派生**：

| 字段 | 规则 |
|---|---|
| 适用项满分 | 五项中排除「不适用」后的满分合计（主席场次下限80，见《办法》§3.3） |
| 基础原始分 | 适用评分项得分合计 |
| 基础折算分 | `IFERROR(基础原始分 ÷ 适用项满分 × 100, "")`；适用项满分为0时不得输出数值，须触发异常 |
| 专业两项合计 | 准确性 ＋ 充分性 |
| 专业质量状态 | 专业两项合计 ＜ 30 → 未达标；≥30 → 达到门槛 |
| 缺席后台标记 | 计入应评场次标记＝是 且（参会状态∈{仅挂会无有效参与, 缺席} 或 实际改派类别＝临时改派）→ 真 |
| 本场综合分 | 缺席后台标记＝真 → 0；否则 ＝ 基础折算分 |
| 记录状态 | 草稿｜待PM确认｜待Owner确认｜已初评｜待修正｜已锁定 |
| 准确性兑现状态 | 记录状态≠「已锁定」→ 待后验兑现；＝「已锁定」→ 已兑现 |

### 3.6 修正字段

| 字段 | 说明 |
|---|---|
| 初评五项档位、初评分 | 评审当天形成并确认，**禁止覆盖** |
| 当前五项档位、当前分 | 反映已确认的后验修正 |
| 修正评分项 | 只允许选择受影响项 |
| 修正原因 | 误判｜漏检｜风险验证成立｜其他明确事实 |
| 修正证据链接 | 必填 |
| 修正提出人／确认人／日期 | 审计信息 |
| 锁定日期 | TDR3问题闭环并确认阶段结论的日期 |

专业项后验修正的档位规则见《办法》§3.5，本表不重复。

## 4．AI流程与校验

### 4.1 读取与预填

1. 校验评审ID、项目、TDR节点和会议日期。
2. 按会签列表为每位专家生成一行打分草稿。
3. 关联专家池，补充专家ID和技术领域。
4. 按 §3.5 推导改派派生字段。
5. 预填会前预审、评审与会签、问题闭环三项档位。
6. 对专业两项生成**建议档位**及引用证据。
7. 不满足结构化规则时只输出异常，**不擅自补值**。

### 4.2 自动校验

| 校验项 | 异常条件 |
|---|---|
| 会签完整性 | 专家存在但个人结论为空 |
| GR／NG意见 | 结论为GR或NG但评审意见为空 |
| 问题关联 | GR或NG未关联问题编号 |
| 主责范围 | 专家没有可确认的主责范围 |
| 改派完整性 | 改派类型≠「无」但缺确认时间或记录链接 |
| 改派时点 | 标记为会前改派，但确认时间晚于预审截止时间 |
| 改派有效性 | 标记为会前改派，但接替专家未完成预审／参会／会签 |
| 折算分母 | 适用项满分为0（应触发主席适用规则复核） |
| 最终结论异议处理 | 会议最终G，但存在未处置的专家GR或NG |
| 闭环完整性 | 指定复核专家但复核结论或复核时间为空 |
| 专业高分证据 | 专业项建议满分但无可引用证据 |

### 4.3 人工确认与锁定

PM处理结构化异常并确认三项履约记录 → 技术项目Owner确认专业两项 → PM复核证据 → AI重算分数和后台标记 → 记录置为「已初评」。后验修正必须追加证据；锁定后普通用户不得直接覆盖历史值。

## 5．专家汇总输出

汇总口径见《办法》§5.3。

| 指标 | 计算或展示方式 |
|---|---|
| 原始安排场次 | 改派前最初被安排承担责任的场次总数 |
| 应评场次 | 计入应评场次标记＝是 的场次总数 |
| 本人完成场次 | 计入应评场次＝是、参会状态∉{仅挂会无有效参与, 缺席}、且本人完成会签的场次 |
| **本人履约率**（主指标） | 本人完成场次 ÷ 应评场次 |
| 会前正式改派次数／临时改派次数 | 按 §3.5「实际改派类别」分别计数 |
| **质量分**（主指标） | 各维度得分合计 ÷ **本人完成场次**（必须标注分母场次数） |
| 汇总综合分（派生，排序用） | 应评场次最终分合计 ÷ **应评场次**；恒等于 `质量分 × 本人履约率`，展示时必须标注该乘积关系 |
| 专业质量均分 | 专业两项合计 ÷ **本人完成场次**；同时展示未达标场次数 |
| 主席场次 | 担任评审主席的场次总数（不含独立分值） |
| 高质量证据 | 满分档记录的证据摘要 |
| 待改进证据 | 0分档和后台异常摘要 |
| 历史修正 | 原分、修正分、原因和证据 |
| **评价等级** | 枚举 `A｜B｜C｜D｜记录不足`，按《办法》§5.5 四步推导；项目级和汇总级各出一次 |
| **定档过程** | 文本，格式 `质量分x→基础档Y；履约率z%→封顶W；硬否决：无/触发项`，与等级同时展示，不得省略 |
| **兑现状态** | 锁定前一律标注「未兑现」，锁定后取消（《办法》§5.5） |
| **样本量提示** | 本人完成场次 0–1 → 「当前记录不足以形成明确判断」；2–3 → 「样本量小」；≥4 → 空 |
| AI考核建议 | 仅供HRBP参考，不是人员决定 |

> **展示层级**：「本人履约率」和「质量分」为两个正交主指标，须同等突出展示；「汇总综合分」是二者乘积的派生排序值，不得与主指标并列解读（口径说明见《办法》§5.3）。
>
> 「汇总综合分」与「质量分／专业质量均分」**分母不同**，汇总视图必须在同一视图内标注各自场次数。

等级枚举固定为 `A｜B｜C｜D｜记录不足`（《办法》§5.5）；**阈值待试运行校准**，AI不得自行创造其他等级或调整阈值。

## 6．权限与审计

- PM只维护自己负责项目的评审事实和履约确认。
- 技术项目Owner只确认自己负责项目的专业评分。
- 专家可查看本人记录和证据，不能修改正式评分。
- HRBP和授权管理者可查看专家汇总结果。
- AI读取打分表生成汇总结果，不直接修改已锁定记录。
- 所有专业分和后验修正均保存确认人及时间。

## 7．待确认字段

1. 组织调整和特殊豁免的评分规则及对应枚举处理。
2. 改派次数提醒阈值。
3. 评价等级的质量分与履约率阈值（枚举已定，阈值待试运行校准）。
4. 问题等级和处置方式的最终枚举。
5. 实际工具载体及其字段、权限和自动化能力限制。
