# TDT技术项目TDR评审专家质量考评与记录办法V0.1

> 状态：讨论稿｜日期：2026-08-03
> 适用范围：TDT技术项目TDR1、TDR2、TDR3评审专家及评审主席
> 本文是**规则的唯一事实源**。字段、枚举、公式和AI校验见《TDRX评审表与评审专家打分表数据规范》；术语一句话定义见 `CONTEXT.md`。

## 1．目的与适用原则

**目的**：统一记录评审专家的履约表现和专业质量，为专家池管理和人才盘点提供数据，并牵引会前准备、现场判断、会签质量和问题闭环水平。

**七条原则**：

1. **一场一人一记录**——记录单元为「项目＋TDR节点＋专家」，一条记录可含一个或多个负责领域。
2. **统一五维评分**——普通评委和评审主席使用同一套五项基础评分。
3. **证据优先**——评价必须可追溯到评审表、预审记录、会议记录、问题台账或后验事实。
4. **初评及时、修正有限**——评审当天完成初评确认，只在出现明确新证据时修正受影响项。
5. **不按问题数量评价**——问题多不代表质量高，没有问题也不自动代表质量低。
6. **不奖励严厉结论**——G、GR、NG没有天然高低之分，评价的是判断和依据质量。
7. **AI预填、人工确认**——AI降低录入成本，但不能代替技术项目Owner确认专业质量。

## 2．评审基础

### 2.1 三个TDR节点的固化评审维度

评审维度是**专家主责范围划分、专业判断评分和主席范围把关的统一框架**，逐节点固化，不由单场会议临时增删。维度全部来自《技术开发流程说明V1.0》，出处见下表。

> 现行《技术开发-TR评审检查表》是研发团队自检工具，**不作为评委考评依据**。

| 节点 | 阶段目标 | 固化评审维度 | 《技术开发流程说明V1.0》出处 |
|---|---|---|---|
| **TDR1** | 确认技术是否可行，能否进入方案设计阶段 | ①目标分解准确与完整性 | §6 KCP TDR1-①；活动003任务1；《技术目标分解表》 |
| | | ②技术和架构方案合理性（问题与最优解） | §6 KCP TDR1-②；活动003任务1（含备选方案、方案难点与风险控制对策）、任务2 |
| | | ③成本与资源合理性 | §6 KCP TDR1-③；活动003任务5、任务8（人力投入、物料需求、NRE费用） |
| | | ④关键约束与限制条件 | 活动003任务3、4、6、7（可靠性测试性、制造可行性、需求一致性、知识产权）；活动004《技术项目质量标准》《技术项目风险评估与控制报告》 |
| **TDR2** | 确认方案是否成熟，能否进入开发验证阶段 | ①设计方案成熟度与目标支撑性 | §6 KCP TDR2-①；§4.2关注点①；活动101、活动102 |
| | | ②是否满足设计规范 | §6 KCP TDR2-②；§4.2关注点②（知识产权、安全隐私、榫卯、CBB）；活动102、活动107 |
| | | ③成本与资源合理性 | §6 KCP TDR2-③；活动104《资源供应计划》V1.0及成本估算 |
| | | ④测试方案合理性 | 活动106（测试方案、策略、计划及验收标准）；活动105可靠性测试方案；§4.2关注点③ |
| | | ⑤制造可行性 | 活动103《生产新工艺说明书》V0.1；§4.2关注点③ |
| **TDR3** | 确认技术成果是否达标，能否进入迁移阶段 | ①交付达成 | §6 KCP TDR3-①；活动210及其交付物 |
| | | ②测试质量验收 | §6 KCP TDR3-②前半；活动208、活动211 |
| | | ③风险闭环情况与遗留风险跟踪对策 | §6 KCP TDR3-②后半；活动211、活动212 |

**维度使用规则**：

1. **全覆盖**：本节点全部维度均须有专家承担，不区分主次。维度分配方式见 §2.3。
2. **风险内含于维度**，不单设风险维度。专家在每个负责维度上给出 `无风险｜有风险-可控｜有风险-阻断`，分别对应 G／GR／NG；判为有风险时须说明问题并给出验证策略或处置建议（记录要求见 §2.2、§3.1）。
3. **软硬件通用**：维度按抽象层定义，硬件项目落到器件、工艺、BOM、可靠性，软件项目落到架构、依赖、安全隐私合规、人力与测试覆盖，维度本身不变。
4. **本场不适用**：某维度确因项目性质不适用时（如纯软项目的制造可行性），由项目技术负责人在提出主责范围时标记「本场不适用」并说明理由，主席确认。**未标记且无人承担的维度按范围遗漏处理**（见 §2.3 及 §2.4）。
5. TDR1与TDR2正式合并举行时，合并场次覆盖两节点全部维度。
6. TDR4不纳入本办法考评范围。

### 2.2 G／GR／NG会签规则

专家个人会签和会议最终结论均采用G、GR、NG；评审主席根据评委意见确认会议最终结论。

| 结论 | 判断条件 | 记录要求 |
|---|---|---|
| G | 不存在影响进入下一阶段的未处置风险或问题 | 完成负责领域评审并选G，不强制填写正式问题；如存在评委GR／NG意见，会议记录其处理结果 |
| GR | 存在剩余风险，但风险可控并可带条件推进 | 个人记录风险、依据、影响、推进条件及后续动作；会议汇总剩余风险、责任人、计划时间和验证方式 |
| NG | 存在阻断项或关键证据缺失，当前不能进入下一阶段 | 个人记录阻断问题、依据、不能通过的原因及重新评审条件；会议汇总阻断项、判断依据和重新评审条件 |

G可以包含一般建议。不影响通过时可保留在会签意见中；需要整改、验证或持续跟踪时应进入评审问题汇总。

### 2.3 主责范围与开放评审

会前预审采用「主责范围＋开放补充」：项目技术负责人根据方案和现行TDR检查表提出适用技术领域 → 评审主席检查整体范围、专家构成和材料是否有明显遗漏 → 每位专家确认一个或多个主责范围。主责范围必须完成预审和会签，范围外问题允许提出；专家发现范围缺失时可提出新增领域或补充专家。PM负责记录最终范围和完成状态，**不负责凭自身技术判断创造评审范围**。

后续发现遗漏时的归责：

| 情况 | 归属 | 处理方式 |
|---|---|---|
| 技术领域会前未被列入整体范围 | 评审策划问题 | 不扣普通专家分；计入主席「评审与会签履约」判定或流程改进判断（见 §2.4） |
| 已分配给专家，但未完成检查 | 专家履约问题 | 修正「评审与会签履约」 |
| 已完成检查，但明显误判或漏检 | 专业质量问题 | 后验修正专业评分项（见 §3.5） |
| 当时关键材料不足 | 项目准备问题 | 不扣专家分，记录材料缺失 |
| 当时信息条件下无法合理预见 | 非专家责任 | 不修正专家分 |

### 2.4 评审主席的附加职责

评审主席**不单独设立评分项**，与普通评委使用同一套基础五项评分（见 §3）。主席在本人主责范围之外额外承担以下两项职责，纳入相应评分项判定，不增加分值：

| 附加职责 | 内容 | 纳入的评分项 |
|---|---|---|
| **整体评审范围完整性把关** | 检查本节点固化维度（§2.1）是否全部有专家承担或已标记「本场不适用」，识别专家能力和材料缺口并推动处置 | 「评审与会签履约」 |
| **会议最终结论质量** | 处理评委GR／NG异议，形成依据充分、推进条件和阻断标准完整的会议最终结论 | 「专业判断准确性」 |

边界：

- 主席本人主责范围的评审表现，与其他专家同口径评分。
- 主席不承担评价其他评委的权力和义务。
- 主席无个人主责范围时的适用项处理见 §3.3。

## 3．基础五项评分（满分100）

普通评委和评审主席使用同一套评分，**不设主席专属评分项**；主席的两项附加职责按 §2.4 纳入对应评分项判定。

| 维度 | 满分 | 满分档 | 中间档 | 0分档 | 不适用条件 |
|---|---:|---|---|---|---|
| 会前预审 | 10 | 按截止时间完成主责范围预审，10分 | 逾期但会前完成，或预审明显不完整，5分 | 未完成预审，0分 | 评审材料未按要求提供 |
| 评审与会签履约 | 30 | 本人有效参与关键议程，完成全部负责领域评审并按时会签；GR、NG意见记录完整，30分 | 参与不完整／只完成部分负责领域／会签逾期／GR、NG意见记录不完整，15分 | 缺席、仅挂会无有效参与、未完成负责领域评审或未会签，0分 | 会前未形成可确认负责领域 |
| 专业判断准确性 | 25 | 技术判断、风险识别、风险定级和结论准确，25分 | 基本正确，但深度或准确性不足，15分 | 明显误判、漏检或风险定级错误，0分 | 原则上不使用 |
| 判断依据与意见充分性 | 25 | 数据、标准、逻辑及必要意见充分、清晰、可执行，25分 | 基本能支撑判断，但依据或意见仍有不足，15分 | 缺乏依据，或意见无法支撑和执行，0分 | 原则上不使用 |
| 问题闭环履约 | 10 | 按期完成指定复核并给出明确结论，10分 | 逾期完成或复核结论需补充，5分 | 未完成指定复核，0分 | 未被指定复核任务 |

专家会上明确需要补查资料，并在约定时限内补充判断、完成会签的，可认定完成评审与会签；会前未完成预审的，「会前预审」仍评0分。

### 3.1 两项专业质量指标的判定

两项分别评价「判断是否正确」和「判断是否有充分支撑」，必须分别打分：不能因结论正确就默认依据充分，也不能因记录详细就默认判断准确。

| 指标 | 核心问题 | 判定内容 | 不作为判定依据 |
|---|---|---|---|
| 专业判断准确性 | 判断得对不对？ | 在评审当时可获得的信息下，专家对负责领域的技术状态、关键风险、风险等级及G／GR／NG结论是否符合事实，是否存在影响评审决策的明显误判或漏检 | 问题数量、意见篇幅、结论严格程度。给NG不自动高分，给G不自动低分 |
| 判断依据与意见充分性 | 为什么这样判断，他人能否复核并执行？ | 判断是否引用可追溯的数据、标准、需求、测试结果或技术逻辑；GR、NG意见是否说明风险对象及影响，并给出处置要求、验证方式或通过条件 | 文字多少、表达是否复杂。冗长但不能支撑判断或指导处置的，不评满分 |

档位边界：

- **专业判断准确性**看判断结果。25分＝关键判断准确、无影响决策的明显误判或漏检；15分＝主要方向正确但存在局部判断不准、深度不足或次要遗漏；0分＝出现影响评审决策的明显误判、漏检或风险定级错误。
- **判断依据与意见充分性**看支撑和可执行性。25分＝关键判断有可追溯依据、GR／NG意见能直接支持后续处置和复核；15分＝能基本支撑判断，但依据、风险边界、处置要求或验证条件有缺项；0分＝只有结论或笼统意见，缺少可复核依据，或意见无法转化为行动。
- 两项可以不同分。判断方向正确但只给出笼统结论、未提供数据、影响范围和验证要求的，可得准确性25分＋充分性15分。
- 初评只使用评审当时能获得的信息；后续测试或阶段结果用于验证和修正原判断。当时无法合理预见、由后续新增条件引发的问题，不倒推扣分。

**两项指标的时间属性不同**——充分性当场兑现，准确性事后兑现：

| | 专业判断准确性 | 判断依据与意见充分性 |
|---|---|---|
| 主要兑现环节 | **后验修正**（§3.5） | **初评当天** |
| 理由 | 判G还是判GR属判断宽严，当时无法证伪 | 有无引用数据、有无给出验证条件，当场可见 |

由此确定两条初评规则：

1. **初评时「专业判断准确性」只在 25／15 两档取值**。结论宽松（如材料存在余量偏小或数据缺失仍判G）**不等于误判**——凭工程经验放行是合法判断，不因结论宽严在初评扣分；仅在深度或覆盖明显不足时取15。**0分档在初评只用于一种情形：结论与当时材料存在事实性矛盾**（引用错误数据、遗漏材料中已明确给出的结果）。其余误判由后验修正兑现。
2. **「判断依据与意见充分性」的判定与结论对错无关**，只看有无可追溯依据、风险边界和可执行的处置要求。结论正确但无依据的，仍评0分。

**初评标注**：准确性在锁定前标注「待后验兑现」，评价等级在 TDR3 问题闭环锁定前一律标注「未兑现」（见 §5.5）。

### 3.2 评分示例（虚构）

某专家在TDR1负责「技术和架构方案合理性」维度。材料显示：主方案关键指标已有初步验证，但两项子指标余量偏小，一项关键子模块尚无数据，新引入的技术组件未完成极限条件验证。

**初评（评审当天）**

| 会签记录示例 | 准确性 | 充分性 | 判定说明 |
|---|---:|---:|---|
| 「GR。主方案关键指标初步验证通过，但不能代表整体可行：子指标A、B余量偏小，子模块C数据缺失，新组件极限条件未验证。进入TDR2前须补齐全项测试及极限验证；未达目标时重新评审方案。」 | 25 | 25 | 依据、风险边界、后续动作和通过条件完整，可复核、可执行 |
| 「GR。主方案可以继续，但其他子项和新组件可靠性仍有风险。」 | 25 | 15 | 判断方向正确，但未引用具体数据，未说明验证范围、处置要求和通过条件 |
| 「G。关键指标已达标，方案可直接进入下一阶段。」 | 25 或 15 | 0 | 判G不等于误判——凭工程经验放行是合法判断，初评不因结论宽松扣准确性，深度明显不足时取15；但只有结论、无可复核依据，充分性0 |

**后验兑现（以第三行为例，规则见 §3.5）**

| TDR2／TDR3 出现的事实 | 准确性 | 充分性 |
|---|---:|---:|
| 项目顺利，子模块C如期达标 | 维持 25／15 | 仍为 0 |
| 子模块C不达标并导致返工 | 降为 0 | 0 |

分数以技术项目Owner对评审材料和事实的确认为前提；PM负责核查引用记录是否存在、评分证据是否完整。

### 3.3 不适用折算

`基础分 ＝ 适用项实际得分 ÷ 适用项满分 × 100`

- 「不适用」只能因**流程或组织原因**触发（材料未提供、未定义主责范围、未指定复核任务），不能因专家自身未完成而标为不适用。
- 材料不足、未定义主责范围等流程问题必须单独标记，不能静默送满分，也不扣专家分。
- **主席无个人主责范围时**：会前预审、问题闭环履约可为不适用，但「评审与会签履约」和两项专业评分**始终适用**（主席对整场议程的主持与结论把关本身即评审行为），因此适用项满分下限为80，折算分母不会为0。

### 3.4 两条后台约束

1. **缺席归零**：专家缺席、仅挂会无有效参与或临时改派时，本场综合分为0，专业表现标记「未评价」。已提交有效预审意见的，「会前预审」仍按10／5／0记录并单独展示，但不改变本场综合分为0。
   **优先级**：缺席归零**优先于**五项档位计算，五项档位仍按实际记录保存以供追溯，但不参与本场综合分。避免「评审与会签履约」0分与缺席归零两条路径重复判定同一事实。
2. **专业质量门槛**：「专业判断准确性＋判断依据与意见充分性」**低于30分**（即＜30；15＋15＝30为可接受下限）时，标记「专业质量未达标」；累计≥2场触发 §5.5 硬否决，等级降为D。

### 3.5 后验修正规则

| 后验情况 | 专业判断准确性 | 判断依据与意见充分性 |
|---|---:|---:|
| 当时可合理识别的重大误判或重大风险遗漏；分析过程真实、可追溯，但技术推导错误 | 0分 | 15分（分析过程仍有记录价值，但不能评为充分） |
| 当时可合理识别的重大误判或重大风险遗漏；且关键依据缺失、选择性使用或与结论冲突 | 0分 | 0分 |
| 风险由评审后新增、当时无法合理预见的信息引发 | 不调整 | 不调整 |

修正只适用于专家已确认的负责领域，并保留原分、修正分和修正证据。

### 3.6 证据要求

- 满分档和0分档必须填写证据或引用记录；中间档可直接选择标准描述，必要时补充说明。
- G不强制填写评审问题；但没有预审记录、现场贡献或技术依据时，「判断依据与意见充分性」不能评满分档。
- 专业质量由技术项目Owner主评、PM核查证据并共同确认；发生利益冲突或争议时由领域TL或专家池负责人复核争议项。

## 4．评分流程与时间

### 4.1 会前与会上

PM和技术项目Owner使用统一TDRX评审表记录评委、负责领域、会签和问题；项目技术负责人提出主责范围，主席检查整体完整性，专家确认本人范围；专家给出个人G／GR／NG会签，GR、NG必须形成对应意见。

### 4.2 评审当天完成确认

1. AI读取TDRX评审表，生成每位专家的打分表草稿。
2. PM确认评审与会签、预审和闭环三项履约记录。
3. 技术项目Owner主评「专业判断准确性」和「判断依据与意见充分性」。
4. PM复核专业评价是否有证据，双方形成**唯一结果，不分别打分取平均**。
5. AI计算初评分、后台标记和异常提示。

主席场次的两项主席附加职责（见 §2.4）随所属评分项一并确认，**主席本人不参与自己记录的评分确认**。

**AI不得未经人工确认直接形成的正式分数**：专业判断准确性、判断依据与意见充分性。

### 4.3 后验修正与锁定

- TDR1记录可在TDR2方案结果出现后修正；TDR2记录可在TDR3开发、测试和质量结果出现后修正；TDR3记录在TDR3问题整改和复核完成后修正。
- TDR3评审问题闭环并确认最终阶段结论后，统一锁定TDR1至TDR3的常规修正。
- 技术迁移阶段后出现重大新证据时，可追加「重大后验事件」，但不重新评价整场。
- 修正只调整受影响项，并保留原分、修正分、原因、证据和时间。

## 5．多次记录与项目汇总

### 5.1 应评场次

- 被安排承担评审责任、且会议实际举行的场次进入应评分母；**缺席不会使应评场次消失**。
- 会前正式改派后，原专家不进入该场应评分母，正式接替专家按正常应评场次处理。
- 临时改派时，原专家仍进入该场应评分母；临时支援专家不进入本人履约率分母。
- TDR1和TDR2正式合并举行时，按一次「TDR1＋TDR2联合评审」记录。
- 会议取消或节点正式裁剪时，不产生应评记录。
- 组织调整和特殊豁免的最终规则**待确认**。

### 5.2 改派规则（暂定）

改派只区分三种类型，其余判定由系统按规则推导，不需人工填写：

| 类型 | 判定条件 | 对原专家的影响 |
|---|---|---|
| 会前正式改派 | 预审截止时间**前**经PM或技术项目Owner书面确认，且接替专家完成预审、参会和会签 | 不计缺席、不进入该场应评分母；计入「会前正式改派次数」 |
| 临时改派 | 预审截止时间**后**发生，或无可追溯书面确认；或虽会前确认但接替专家未完成预审／参会／会签 | 按缺席处理，本场综合分为0；计入「临时改派次数」。已提交的有效预审意见仍正常记录预审分 |
| 组织原因调整 | 组织安排变化或会议时间变更导致 | 不计入个人改派次数 |

补充说明：

- 临时支援专家按实际完成内容形成支援记录，用于评价其评审质量，但不计入其本人履约率分母。
- **改派次数本身不额外扣分**——临时改派的扣分已经通过「缺席归零」体现，改派次数只用于专家池适任性提示，不做二次惩罚。
- 专家汇总视图同时展示原始安排场次和两类改派次数；改派较多时AI可提示「建议复核专家池适任性」，是否更换由专家池负责人或HRBP判断。
- 改派次数的提醒阈值**暂不预设**，待试运行后确定。

### 5.3 汇总指标

汇总采用**两个正交主指标 ＋ 一个派生排序值**的结构：

| 层级 | 指标 | 计算方式 | 分母 | 回答的问题 |
|---|---|---|---|---|
| **主指标** | **本人履约率** | 本人完成场次÷应评场次 | 应评场次 | 该专家**来不来**？ |
| **主指标** | **质量分**（原「五项维度平均分」） | 各维度得分之和÷本人完成场次（**缺席场次不计入**） | 本人完成场次 | 该专家**参评时判得准不准**？ |
| 派生值 | 项目综合分 | 各应评场次综合分之和÷应评场次（**含0分场次**）<br>**≡ 质量分 × 本人履约率** | 应评场次 | 综合排序用，**不作为独立结论** |
| 辅助 | 专业质量均分 | 两项专业评分之和÷本人完成场次 | 本人完成场次 | 专业两项的单独视图 |
| 辅助 | 原始安排场次／应评场次／本人完成场次 | 见 §5.1 | — | 样本量 |
| 辅助 | 会前正式改派次数／临时改派次数 | 见 §5.2 | — | 专家池适任性提示 |

> **正交性说明**：履约率和质量分相互独立，处置方向也不同——履约率低指向排班或换人，质量分低指向培训或收窄主责范围。两者不得互相折抵。
>
> **项目综合分是派生量**：由定义可推出 `项目综合分 ＝ 质量分 × 本人履约率`（缺席场次记0）。它不携带前两个指标之外的新信息，**只用于排序，不得与履约率、质量分并列解读**，否则同一次缺席会被读者重复计入印象。展示时必须标注该乘积关系。
>
> **分母说明**：项目综合分以应评场次为分母；质量分和专业质量均分以本人完成场次为分母。汇总视图必须同时标注各自场次数，避免误读。

### 5.4 汇总示例

某专家在一个项目中：TDR1本人参加90分；TDR2临时改派0分（已提交有效预审意见，预审分单独保留）；TDR3本人参加86分。

| 指标 | 结果 |
|---|---|
| 原始安排场次 | 3 |
| 应评场次 | 3 |
| 本人完成场次 | 2 |
| **本人履约率**（主指标） | 2÷3 ＝ 66.7％ |
| **质量分**（主指标） | (90＋86)÷2 ＝ 88.0分（分母2） |
| 临时改派次数 | 1 |
| 项目综合分（派生） | (90＋0＋86)÷3 ＝ 58.7分（分母3）＝ 88.0 × 66.7％ |

**读法**：该专家**参评时水平良好（质量分88）**，但**出勤不稳定（履约率66.7%）**。综合分58.7是二者乘积，用于排序；解读时应看两个主指标，不应把58.7再理解为一次独立的低分。

对比：若TDR2在预审截止前完成**会前正式改派**，则原始安排场次3、应评场次2、会前正式改派次数1，不产生该场缺席分，项目综合分为 (90＋86)÷2 ＝ 88分。

### 5.5 评价等级

评价等级是**参考性结论**，供专家池管理和人才盘点使用，不是绩效、晋升或薪酬结论。等级采用**质量分定档、履约率封顶**的四档结构，保持两个主指标正交，不将其合并为单一数值。

> **阈值状态：待试运行校准。** 下表三个质量分阈值（90／75／60）和履约率阈值缺乏样本支撑，V0.1按经验设定，须在试运行后按实际分布回看调整。AI在阈值确认前不得自行创造其他等级。

**第一步——质量分定基础档**

| 基础档 | 名称 | 质量分 |
|---|---|---|
| **A** | 建议重点使用 | ≥ 90 |
| **B** | 建议继续承担现有领域评审 | 75 – 89 |
| **C** | 建议继续观察 | 60 – 74 |
| **D** | 建议复核专家池适任性 | ＜ 60 |

**第二步——履约率封顶（只降不升）**

| 本人履约率 | 等级上限 |
|---|---|
| ≥ 90％ | 不封顶 |
| 75 – 89％ | 最高 B |
| 60 – 74％ | 最高 C |
| ＜ 60％ | 最高 D |

**第三步——硬否决（直接降为D）**

| 触发条件 | 依据 |
|---|---|
| 「专业质量未达标」场次 ≥ 2 | §3.4 |
| 任一场次后验修正为 0＋0（重大误判且关键依据有缺陷） | §3.5 |
| 临时改派次数 ≥ 2 | §5.2 |

**第四步——样本量守门**

| 本人完成场次 | 处理 |
|---|---|
| 0 – 1 场 | **不给等级**，标记「当前记录不足以形成明确判断」 |
| 2 – 3 场 | 给等级，但必须并列标注「样本量小」 |
| ≥ 4 场 | 正常给等级 |

**兑现状态标注**：「专业判断准确性」主要由后验修正兑现（§3.1、§3.5），因此在 TDR3 问题闭环锁定前，等级一律并列标注「**未兑现**」；锁定后取消该标注。

**适用层级**：等级在**项目级**（单个项目内的全部应评场次）和**汇总级**（跨项目）各出一次；项目级用于当期反馈，汇总级用于专家池管理。

**展示要求**：等级必须与**定档过程**同时展示，即「基础档 → 封顶结果 → 硬否决触发项」，不得只给字母。项目综合分仅用于同档内排序。

**示例**（承 §5.4）：质量分88 → 基础档B；履约率66.7% → 封顶C；无硬否决 → **最终C（建议继续观察），并标注「样本量小（2场）」**。

## 6．两表关系与AI边界

既有专家池继续作为主数据，本项目新增两张表：

| 表 | 定位 | 使用方式 |
|---|---|---|
| TDRX评审表 | 人使用的**事实**来源 | 会上由PM和技术项目Owner记录，评委完成会签和意见 |
| 评审专家打分表 | AI使用的**评价**来源 | 一位专家在一个TDR评审场次中对应一行 |

自动化流程：AI读取评审表 → 按评审人生成打分草稿 → 按改派类型和确认时间推导应评标记及改派次数 → 预填可结构化判断的档位并标记异常 → PM确认履约类字段 → 技术项目Owner确认专业两项、PM复核证据 → 人工确认主席两项 → AI生成正式记录和项目汇总。

字段、枚举、公式和AI校验规则详见《TDRX评审表与评审专家打分表数据规范V0.1》。
