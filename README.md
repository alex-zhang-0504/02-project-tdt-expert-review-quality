# TDT评审人质量考评（试用版 v0.1）

用于批量读取TDRX评审报告、自动计算年度客观分数、收集主观分数问卷，并由后台生成年度总分与等级。

当前产品版本为**试用版 v0.1**。Python安装包内部版本使用 `0.1.0`；系统已实现按年度《考评办法V0.5》的客观分数，主观问卷继续沿用V0.3，待专项讨论后再细化。

## 当前能力

- 正式使用优先粘贴一个飞书归档文件夹URL，系统枚举第一层电子表格和表格快捷方式；单个电子表格或Wiki URL继续兼容。本地输入支持一次选择或拖入多份 `.xlsx` 评审报告，作为在线读取失败时的备用入口；两种来源进入同一解析和计分流程。
- 最新版有效Sheet至少需要3名不同评审人具有已记录会签结果；允许值为Go、Go with Risk、Redirect或`-`。`-`证明项目经理已记录该评审人未给结果，可计入Sheet有效性判断，但结果会签仍计0分。
- 基础信息、会签区和问题区按区块标题、标准字段名和表头动态定位，不绑定A3／B3等绝对坐标；区块内部增加空白行列或整体移动字段仍按语义读取。字段或表头缺失、重复会明确阻断，空白辅助Sheet跳过，隐藏有效Sheet照常解析且不产生提醒。
- 缺席名单命中但已有有效会签时按已履职计分并提醒；代理关系仍归原评审人计分，年度仅展示被代理次数、应参评场次数和代理率。
- 区块2评审意见与问题表中可归属专家的问题描述取并集、归一化去重；问题提出人与同一Sheet评审人名单取交集，名单外参与者的问题保留但不纳入专家考核。一格出现至少两项数字、字母或中文数字明确序号时自动拆分；逗号、分号等标点本身不触发拆分或提醒。自动拆分等系统容错不在用户质检界面展示。
- 同一项目既支持一册多Sheet，也支持TDR1／TDR2／TDR3分别成册；统一按项目编码＋Sheet内部阶段字段聚合，“评审阶段”和“项目阶段”作为等价字段名静默兼容。文件名和Sheet名称均不参与阶段识别或质检。
- 批量报告中若不同中文评审人姓名的名字拼音相同，且姓氏相同、同音或仅存在`n／ng`近音差异，系统按姓名组列出全部来源文件、Sheet和单元格位置并阻断进入评分；用户确认确为不同人员后，本批次按独立人员继续统计，系统不自动合并姓名。
- 支持一次会议合并评审多个项目：当“技术项目名和编码”以数字／字母序号列出多项，或以每行均含合法“项目名-项目编码”的一致结构分行填写时，只形成一次场次并取第一项作为项目归属。同一评审人因多个角色重复列出时合并为一人，角色和意见证据取并集，会签只计一次。
- 文档质检只对影响专家考核归属或计分的字段设卡；会议日期、会议评审结论、评审角色及问题编号、是否修正、等级、反馈和状态均作为项目跟踪辅助信息读取，缺失或格式不规范不报错，默认静默；确需提示时只允许非阻断提醒。
- 维度一客观分数共60分：评审过程表现48分（出勤`13／0`、会签`25／0`、评审意见`10／6／0`）＋年度服务贡献12分（评审参与度6分＋场次问题贡献6分）。
- 所选报告中能够正常解析的TDR1／TDR2／TDR3场次均进入当前评分，不要求项目已经完成TDR3，也不对未完成TDR3作提示；项目过程表现按当前已有计分场次平均，不同项目继续等权平均。
- 年度服务贡献以有效参评3场为共同资格门槛：评审参与度按有效参评场次数取前两个不同数量档`6／3／0`；场次问题贡献按有归属问题的场次数取前两个不同正数量档`6／3／0`。同一评审人同一场提出多个问题只计1个问题贡献场次。
- 维度二「主观分数考核」评价专业价值贡献，由技术项目经理完成三道单选题：履职与协作 `10／6／0`、专业判断与指导 `20／14／0`、突出贡献 `10／0`；系统不预选答案。
- 评审意见采用0分排除制：未给意见、只引用他人意见、只有泛化提醒计0，其余实质意见至少计6，三要素齐全计10；判定样本保存在本地`var/review-opinion-samples/`且不进入Git。
- 顶栏提供四个模块和专家横向导航；评审表检查通过后可自由切换模块和专家，未完成问卷也能返回，同一专家的问卷草稿会在页面切换时保留。
- 评审过程表现大表支持评审人三级模糊搜索：汉字可跳字匹配，拼音支持全拼和首字母，自动忽略大小写与空格。
- 客观分数和主观分数可以独立完成。没有评审表时可手工填写项目编码和评审人姓名，只计算主观分数，不生成虚假总分。
- 主观问卷可以暂存作答状态；只有点击「提交」且后台计算成功后，评审人分数才登记到评分结果。
- 页面每5秒核验本地服务的项目身份、源码构建和进程实例；服务停止、版本不一致或后台重启时会立即标红，并禁用读取、授权和提交等后台操作，避免把旧页面误当成可用系统。
- 专业判断与指导选择0分时必须勾选原因标签并填写100字以内的「0分原因和导致影响」；突出贡献默认0分，选择10分时必须填写100字以内的加分原因。
- 本地Excel支持点击选择和拖拽导入，不再提供容易混淆的本地绝对路径输入；损坏文件只在自己的报告卡片中报错，不吞掉同批其他报告的检查结果。
- 读取模块按最新年度V0.5规范为每份报告执行10个后端检查节点，只有真实检查完成后才推进进度并记录实际耗时；批量界面只显示每份报告的当前检查项、完成百分比和最终状态，不再陈列24张检查卡或播放固定延时动画。
- 评分结果以全员表格展示客观分数、主观分数、年度总分、等级和完成状态；任一专家的客观分数或主观分数未完成时，批次不排名，已生成年度总分的专家显示「待排名」。
- 本次考核的报告范围由部门在导入前人工圈定；系统不按日期筛选，并按照当前已完成的有效评审报告生成动态试算，年底冻结一次正式结果。
- 年度过程分先计算同一专家在每个项目内的有效TDR场次均分，再按项目等权平均；同一技术项目经理对同一专家只填写一次主观问卷。
- 年度等级只在同一批次全体评审人的维度一和维度二均完成后，按年度总分降序统一生成：满分为S；前15％为A、后15％为C、中间为B。边界人数向上取整，同分不拆分；上下边界同分时，除S外统一为B。

> 不计算同一场评审中多位评审人的横向平均分。事实卡主视图展示过程分、有效参评场次、场次问题贡献、代理事实、客观分数和阻断性异常。

## 运行

需要Python 3.12或更高版本。首次运行：

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m uvicorn tdt_scoring.api:app --host 127.0.0.1 --port 8865
```

浏览器打开 `http://127.0.0.1:8865/` 。

## 两种维度一操作方式

- **方案一｜集中评分**：由一名汇总人一次导入本年度全部TDRX报告，完成检查后直接查看「评审过程表现」批量大表，并可导出年度维度一结果。
- **方案二｜项目经理分别提交**：每位项目经理填写同一年度批次ID、本人ID和姓名，导入自己负责项目的TDRX报告后导出系统生成的 `.xlsx` 提交表；汇总人选择「汇总提交表」，一次导入全部提交表，系统校验批次、人数、项目归属、重复阶段和文件完整性，再从原始事实统一重算年度维度一，避免把各文件中的局部分数直接相加。

方案二的提交表同时包含可阅读明细和隐藏的校验载荷；人工改动载荷后会被拒绝。该过渡方案不依赖登录、数据库或在线服务，但项目经理身份属于提交元数据，不具备账号认证或电子签名效力。分布式流程暂不开放维度二，维度二仍按现有集中流程处理。

飞书批量读取只需粘贴一个归档文件夹URL。第一版只读取文件夹第一层，不递归子文件夹；第一层所有电子表格和指向电子表格的快捷方式都视为候选报告，因此归档目录只应放正式TDRX报告。系统会显示发现、候选、成功、失败和排除数量，任一候选报告读取或解析失败都会阻止完整年度结果，禁止静默跳过。单个电子表格或指向电子表格的Wiki URL继续兼容。首次使用点击页面中的「授权飞书读取」，按提示授予表格读取、文档导出、云盘只读和元数据只读权限。当前Windows用户需要已安装 `lark-cli` 且拥有目标文件夹及候选报告访问权，凭据不会写入项目。

Windows下也可以在完整项目文件夹中双击 `start.cmd`；macOS下可双击 `start.command`。如果拿到的是压缩包，必须先完整解压，不能在压缩包预览窗口中直接运行。脚本会自动选择可用的Python 3.12及以上版本，在项目内按需创建 `.venv`、安装依赖并打开系统。本项目固定使用项目身份 `tdt-expert-review-quality` 和专属端口段 `8865—8899`；只有运行中服务的项目身份与当前源码构建标识均一致时才会复用，不会占用其他项目已登记的端口。打开地址会携带当前构建标识，强制浏览器执行新导航。

使用期间必须保持启动窗口运行。服务日志追加到 `output/local-service.log`；如果后台退出，启动窗口会保留错误码和日志路径，不再直接消失。页面显示「服务已断开」「服务版本不匹配」或「服务已重新启动」时，重新双击 `start.cmd`，只使用新打开的页面，并重新导入评审表。当前分析和问卷登记保存在本地进程内，后台重启后不会沿用旧页面中的分析编号。

运行验证：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m compileall -q src tests
node --check src/web/app.js
```
