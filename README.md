# V0.6四维事实统计版

> 当前计分规则：[完整考核办法V0.8](docs/tdr-expert-review-assessment-v0.8.md) 。评审过程表现30分＋专业价值贡献70分＋超额意见奖励＋对策奖励，总分100分封顶。全量AI分析已接入，真实模型质量仍需实际报告验证。

从已归档TDRX评审报告提取评审人的出勤、会签、意见与含对策意见情况，按TDR1／TDR2／TDR3及全部阶段展示。第二模块「客观数据评价」统计事实并提供客观评分，第三模块「主观评价」填写问卷并提供主观评分，第四模块「总分统计」汇总，暂不排名、不评等级。

配置AI并验证通过后，可逐条分析全部待处理意见；结果回写统计，支持进度、失败重试、停止和人工确认。

## 启动

Windows双击项目中的`start.cmd`；当前目录处于哪个Git分支，就启动该分支的代码。多人开发分支为`codex/multi-user-assessment`，无需更换启动脚本。启动器校验项目、构建及工作区身份，端口段8865—8899；旧构建占用端口时会选择空闲端口，不会终止旧服务。macOS仍提供`start.command`，本轮实机验收为Windows。

首次进入登记管理员姓名和工号，在「账号登记与本机备份」登记经理账号。管理员「新建考核」导入报告、关联经理、确认名单；经理选择本人身份后只填写分配问卷。管理员从考核列表查看进度、调整问卷、退回、确认最终主观结果及导出。日常身份选择不设密码；既有评分参数修改仍保留独立解锁。

问卷显示「已保存」后已写入`var/multi-user/assessment.sqlite3`，刷新、关闭页面及重启电脑后可从考核列表继续。不要删除`var/multi-user/`；管理员可下载完整备份，另存到其他磁盘。恢复先预览、明确确认，并自动备份恢复前数据。Git分支保护代码，数据库备份保护填写记录。本机数据不会自动同步到妙搭。详见[多人本机版说明](docs/multi-user-local-v0.1.md) 。

## 使用

2026-09-27本机多人流程：管理员登录→统一导入报告→关联经理工号→确认考核名单→管理员客观评分→经理填写主观问卷→管理员检查进度及调整→确认并导出主观结果。评分参数见`config/scoring-policy-v0.1.json`；以下历史单人流程与新版冲突时，以[多人本机版说明](docs/multi-user-local-v0.1.md)为准。

飞书报告按原文件的`owner_id`识别项目经理，姓名从通讯录读取，快捷方式追溯原文件。检查结果会显示项目经理与所有者规则读取状态；待识别时可点击「重扫」，不会改用创建人或最后编辑人。规则文件为`config/report-owner-policy-v0.1.json`，读取版本、指纹和时间随分析及导出保留。导出中的「项目经理身份」页可核对归属；本地Excel仍需明确指定项目经理。

1. 选择集中统计，或项目经理分别提交／统一汇总。
2. 导入本地Excel或飞书归档文件夹，通过格式和身份检查。
   红色错误报告或有提醒的报告可点击「重扫」：飞书读取原报告的最新内容，本地重新选择修改后的文件，其他报告不重新读取且保持原进度与状态。扫描中点击「停止读取」，当前单次读取结束后停止，保留已完成结果；未扫描项可逐份继续检查。集中统计与项目经理个人提交均适用，复查后会重新核对整个批次的重复项目及姓名一致性。
3. 查看一人一行的三阶段数量＋比率表；可切换单阶段或全部阶段汇总。代理情况显示代理场次／应参场次。点击数字查看数量含义、公式和说明。
   扫描过程中，已检查文件即时显示错误或提醒，可以点选问题并重扫，其他文件继续读取。同一文件不能重复启动。全部扫描及重扫完成后统一进行跨文件姓名和重复场次检查，通过或完成必要确认后才能继续。
4. 点击详情打开「副表格」，每项目一行，分为项目名、项目编码、TDR1详情、TDR2详情、TDR3详情五列；三个阶段横向并排并自适应均分剩余宽度，大屏自动展开，窄屏表内滚动。意见与对策分开展示，来源、理由和人工记录直接展示。
5. 完成AI识别后，疑似项默认计入。详情可切换计入／不计入并保留人工记录。
6. 不再填写考核批次。在「考核评审人名单」上传名单，或输入姓名后点击「手动匹配名单」；上传按钮显示文件名后仍可点击替换，「还原导入名单」恢复最近成功导入的名单。姓名支持横写或逐行输入，允许换行、空格、顿号及中英文逗号、句号、分号分隔。点击居中的「读取评分参数」，实际读取成功后显示凭据并变为「下一步」；再次点击才确认交集名单及配置快照，进入客观数据评价。提醒不阻断任务，错误及未完成扫描仍阻断。导出统一命名为「报告名_截止YYYY年MM月DD日前的评审记录.xlsx」，日期默认导出当天；项目经理提交表仍可用于统一合并，原文、AI结果和复核记录随文件保存。

客观数据统计表下方右侧的「评分参数」入口默认只读，首次由本机管理员设置密码，无默认密码。解锁后可修改参数，预览变更再确认永久保存；写入并重新读取核验成功才显示成功。新考核读取新配置，已确认考核继续使用原快照。该权限只控制应用内配置修改，不是整个系统的登录权限。

无分母或缺失数据显示“—”。未接入AI时显示待AI识别，不生成虚假的对策数量。报告事实、AI成功结果、人工确认、评分快照及问卷保存在本机数据库；管理员可重新打开已保存考核。经理与管理员的访问范围由后台检查，身份选择遵循本人使用的约定。

## AI全量分析

判定规则及案例独立维护于[配置V0.1](docs/countermeasure-policy-v0.1.json) ，操作见[配置使用说明](docs/countermeasure-policy-v0.1-guide.md) 。AI设置及分析确认窗口显示实际读取状态、版本、时间和内容指纹；读取失败禁止分析。

「AI设置」→填写官方API Key→「保存并验证连接」→提示「配置成功」→关闭弹窗→「识别待处理对策」→确认发送→查看全部分析结果。

每条成功即写回；失败保留待识别，再次点击只处理未完成意见。详情支持计入、不计入和暂不判断，疑似默认计入。密钥仅存服务内存，关闭弹窗可继续使用；空闲1小时、刷新或重启后需重新配置。正式运行会向DeepSeek发送意见原文并产生API费用。

详细说明见[AI全量分析SOP](docs/ai-analysis-sop-v0.8.md) 。全量链路已用模拟模型验收，真实密钥连通性和真实报告识别质量须另行验证。

## 六维主观评价

经理登录后从考核列表进入本人问卷，选择评审人并逐维选档。题干、职责边界和选项解释直接展示；「查看评审过程详情」仅展示共同项目。第2—5题低档及第6题突出贡献高档须提供关联项目和依据；暂无法判断须填写原因。

实际修改自动保存，也可点击「保存问卷」；切换前保存，失败保留输入。每位经理同一评审人一票，前五题逐题有效等权平均，贡献取有效最高分。管理员调整后经理只读，退回后继续编辑，前后内容与操作人保留。全部任务回应闭合且各题都有有效评价后，管理员可确认正式主观结果；此前导出标记为过程结果。当前多人页面不使用离线问卷回收，以避免绕过修改历史和锁定状态。规则见[完整考核办法](docs/tdr-expert-review-assessment-v0.8.md) 。

## 分数统计

进入第四模块，确认本批次已包含应纳入报告后，查看阶段分、有效权重、客观分、主观分及总分；点击「查看明细」追溯分项。阶段内出勤／会签／意见／对策分别为7／7／14／7分，不适用阶段按剩余权重归一，未知或待识别数据不按0分处理。问卷未完成或必填依据未齐时不生成主观合计与总分。可单独导出分数统计Excel留档；当前均为试算，不代表真实规则识别准确率已验收。

## 验证

运行 `.venv/Scripts/python.exe -m unittest discover -s tests`，并在真实浏览器验收导入、数字公式、详情、切换和导出流程。AI准确率需要以新旧报告的人工标注样本单独验收。

评审参与度在过程主表TDR3之后单列展示全部阶段实参场次数；满3场后按本批次前两个不同数量档评5／3分，其余0分，并列同分。各阶段超额意见条数直接相加为奖励，不乘权重；分数导出保留参与度、阶段奖励、封顶前合计及最终总分。
