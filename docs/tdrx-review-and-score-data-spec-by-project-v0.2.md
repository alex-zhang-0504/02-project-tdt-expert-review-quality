# TDRX评审表与专家考评记录数据规范（按项目）V0.2

> 讨论稿｜2026-08-04
> 本文只定义**字段、枚举、公式和校验**。评分规则和业务口径以[《TDT技术项目TDR评审专家质量考评办法（按项目）V0.2》](tdr-expert-review-quality-assessment-by-project-v0.2.md)（下称《办法》）为准。
> V0.1 保留作为历史版本，不再维护。

---

## 1．数据结构与定位

评分由AI系统承接，**不再需要人工维护的打分表格**。本文定义两类数据：

| 数据 | 定位 | 粒度 |
|---|---|---|
| **TDRX评审表** | **人使用的事实来源**——技术项目经理维护，是唯一需要人维护的表 | **一个工作簿 ＝ 一个项目的全部TDR评审记录；一个TDR sheet ＝ 一次评审场次** |
| **专家考评记录** | **AI系统内部数据结构**——由系统生成与存储，不产出给人填写 | 一条 ＝ 一位专家在一个项目中的完整考评记录 |

### 1.1 数据来源

评审表支持以下两种**正式计分输入**：

1. **本地 Excel 文件**：技术项目经理选择或上传本地工作簿（当前模板为 `.xlsx`），AI 直接读取其中的 TDR sheet。
2. **飞书云文档 URL**：技术项目经理提供飞书电子表格 URL，AI 通过 URL 读取其中的 TDR sheet。

两种来源同等有效，不设默认优先级。AI须先识别输入类型并统一转换为工作簿解析对象，再按 §1.2 的同一套 sheet 规则和后续评分规则处理；不得因来源不同改变字段含义、计分口径或校验要求。

### 1.2 工作簿内的 sheet 解析规则

| 规则 | 说明 |
|---|---|
| **计分范围** | 只解析「评审会基本信息列表」中`项目阶段`有值的 TDR sheet |
| **跳过示例** | **sheet 名包含「示例」的一律跳过**，不参与任何计分（模板自带的 `TDR(书写示例)` 即属此类） |
| **跳过空表** | `项目阶段`有值但会签列表无任何评审人的 sheet 视为该节点未举行，不产生记录 |
| **有效场次数** | ＝ 工作簿中实际产生记录的 TDR sheet 数量，**不固定为 3**。TDR1与TDR2合并评审时工作簿只有两个 sheet（`项目阶段`＝`TDR1+TDR2` 与 `TDR3`），有效场次数为 2；节点被裁剪或会议取消时相应减少 |

### 1.3 主键

| ID | 格式 | 说明 |
|---|---|---|
| 评审ID | `项目编码-项目阶段-会议日期` | 场次主键，由AI从基本信息区生成 |
| 专家项目记录ID | `项目编码-专家ID` | 考评记录主键 |

**项目编码**取自基本信息区「技术项目+编号」字段，写法为 `项目名（项目编码）`，AI 取**最后一对括号内的内容**为编码，括号外为项目名。跨项目汇总（专家考核平均分 ÷ 参与项目数）一律以**项目编码**为主键，不用项目名。

**专家ID** 由专家池维护；评审表以**专家全名**作为关联键，AI 据全名反查专家ID。ID由系统生成，**禁止用专家姓名作为记录的唯一标识**。

> **相对V0.1的两处变化**：
> 1. 打分表不再是一张需要维护的表格，降为AI系统的数据模型；
> 2. 记录粒度由「场次×专家」改为「**项目×专家**」——专业价值贡献按项目评定一次，场次数据作为子结构。

## 2．TDRX评审表

> 字段定义以现行评审表的实际结构为准，样本见 `docs/展锐独立B3+中高频CA方案--TDRX 评审报告.xlsx` 的 TDR3 sheet。
> **AI 定位方式**：不依赖硬编码行号，靠区块标题文字定位——`评审会基本信息列表`、`评审结论和会签列表`、`评审问题&建议汇总表`；每个区块的表头行是其标题行的下一非空行，数据行自表头行下一行起至下一个空行或下一区块标题为止。

### 2.1 评审会基本信息列表

| 字段 | 必填 | 类型 | 说明 |
|---|---|---|---|
| 技术项目+编号 | 是 | 文本 | 写作 `项目名（项目编码）`，解析规则见 §1.3 |
| 项目阶段 | 是 | 枚举 | `TDR1｜TDR2｜TDR3｜TDR1+TDR2`（TDR1与TDR2合并评审时选最后一项） |
| 会议日期 | 是 | 日期 | Excel 日期序列号，AI 需转换为公历日期 |
| 技术项目经理 | 是 | 人员 | 会后与AI交互确认异常；TDR3后作答专业价值贡献问卷 |
| 评审结论 | 是 | 枚举 | Go｜Go with Risk｜Redirect｜TBD（会议级结论，**不参与专家计分**） |
| 评审意见 | 条件 | 长文本 | 会议级意见，不参与专家计分 |

- **评审ID** 与**项目编码**的生成规则见 §1.3，不单设字段。
- **评审主席**不单设字段，由会签列表中「评审角色」＝`评审主席` 的行识别。

### 2.2 评审结论和会签列表

**这是维度一计分的唯一入口**。不设预审字段（《办法》§4 备注2：不要求提交预审记录）。

| 列 | 字段 | 必填 | 枚举与说明 |
|---|---|---|---|
| A | 评审角色 | 是 | ＝《办法》的「主责范围」；值为 `评审主席` 的行即会议主席 |
| B | 评审人 | 是 | **全名**。发生改派时写 `原专家（代理：代理人）`，AI 剥离括号后缀取原专家为记录归属 |
| C | 参会状况 | 是 | `正常｜部分参加｜改派（正常）｜改派（部分）｜缺席未改派｜挂会` |
| D | 会签结果 | 是 | `Go｜Go with Risk｜Redirect｜TBD｜Go（逾期）｜Go with Risk（逾期）｜Redirect（逾期）` |
| E | 评审依据 | 条件 | 表头全称「评审依据（数据&标准&测试或技术逻辑等）」。Go with Risk／Redirect 必填；**允许引用式填写**（见 §4.4） |

**相对 V0.2 初稿删除的字段**（均可由上述列推导或由填写时点约定取代）：改派确认时间、代理人专家ID、会签时间、对应问题编号、拒绝补交标记、联系记录链接、是否主席。

**TBD 的语义**：`TBD` 表示尚未给出会签结论。**以评审表进入计分的时刻为准，此时仍为 TBD 即判定为拒绝会签**，结果会签与评审意见两项均计 0 分。

### 2.3 评审问题&建议汇总表

**这张表不是计分入口，只是被查证的地方**（判定策略见 §3.3）。表内允许同时存在会签遗留问题与纯技术交流问题，也允许由非评审专家（如团队成员）提出，无需人工区分。

| 列 | 字段 | 必填 | 说明 |
|---|---|---|---|
| A | 序号 | 是 | 格式 `TDR<节点号>-<序号>`，项目内全局唯一。**AI 只取匹配 `TDR\d+-\d+` 的行**；不匹配的行（如模板说明行 `TDRX-No.`）一律跳过 |
| B | 评审人 | 是 | **全名**；多人共同提出时用顿号分隔，该行对其中每一位都生效 |
| C | 问题描述 | 是 | — |
| D | 建议改善措施 | 条件 | 提出人本场会签为 Go with Risk／Redirect 时必填 |
| E | 验证方式与通过条件 | 条件 | 同上 |
| F | 进展（技术负责人跟踪） | 否 | 闭环过程记录，**不参与计分** |
| G | 问题状态 | 是 | `open｜closed` |

**跨节点沿用的问题**保留首次提出节点的编号（如 TDR3 表里沿用 TDR2 的问题仍编为 `TDR2-1`），AI 只对前缀等于本场节点的行计分，避免同一条意见被重复计入两个场次。

**已删除的字段**：问题等级、所属技术领域、责任人／计划完成时间、复核结论／复核时间、后验验证结果、闭环证据链接。经核，这些字段均不参与维度一的任何判定链路；维度二三个项目全部由人工选档，也不依赖结构化字段。

## 3．专家考评记录（AI系统内部数据结构）

### 3.1 识别字段

| 字段 | 来源 |
|---|---|
| 专家项目记录ID | 系统（`项目编码-专家ID`） |
| 专家ID／专家姓名 | 专家池（以评审表中的全名反查） |
| 项目编码／项目名 | 评审表「技术项目+编号」拆分所得 |
| 参与场次列表 | 评审表（各 TDR sheet 的评审ID） |
| 技术项目经理 | 评审表 |

### 3.2 评审过程会签字段（每场次一组，AI自动判定）

| 字段 | 允许档位 | 分值 | 判定来源 |
|---|---|---|---|
| 出勤表现 | 高｜中｜低 | 15／10／0 | 会签列表 C 列「参会状况」 |
| 结果会签 | 高｜中｜低 | 15／10／0 | 会签列表 D 列「会签结果」 |
| 评审意见 | 高｜中｜低 | 30／20／0 | 会签列表 E 列 ＋ 问题汇总表 D／E 列 |
| 场次过程表现分 | — | 0–60 | 三项之和 |

### 3.3 评审过程会签判定规则（AI推导，人工不填）

**总原则——入口在会签列表，问题汇总表只是被查证的地方。** 先从会签列表抓出会签结果为 Go with Risk 或 Redirect 的评审人，再回查这些人在关键字段中是否补全撰写。问题汇总表中其余所有行（非评审专家提出的、会签为 Go 的专家顺手提出的）一律不参与计分，**因此无需人工区分问题的来源类别**。

**Step 1｜剥离后缀**

- D 列去掉 `（逾期）` 后缀得到**结论本体**；是否带该后缀单独用于「结果会签」子项。
- B 列去掉 `（代理：X）` 后缀得到**记录归属人**；出勤、会签、意见三项均按代理人的实际表现计分，记录归属原专家。

**Step 2｜出勤表现档位**

| C 列参会状况 | 档位 | 分值 |
|---|:---:|---:|
| `正常`、`改派（正常）` | 高 | 15 |
| `部分参加`、`改派（部分）` | 中 | 10 |
| `缺席未改派`、`挂会` | 低 | 0 |

**Step 3｜结果会签档位**

| D 列会签结果 | 档位 | 分值 |
|---|:---:|---:|
| `Go`、`Go with Risk`、`Redirect` | 高 | 15 |
| 带 `（逾期）` 后缀的同三值 | 中 | 10 |
| `TBD` | 低 | 0 |

**Step 4｜评审意见档位**

按结论本体分流：

| 结论本体 | 判定 |
|---|---|
| `TBD` | 低档 0 分 |
| `Go` | **高档 30 分**（《办法》§3 备注1：判 Go 是否成立留到维度二一并考核，不在过程表现里追究） |
| `Go with Risk`、`Redirect` | 查三要素，见下 |

三要素及其取值位置：

| 要素 | 位置 |
|---|---|
| 判断依据 | 会签列表 E 列（同一行） |
| 建议改善措施 | 问题汇总表 D 列，该评审人名下的行 |
| 验证方式与通过条件 | 问题汇总表 E 列，该评审人名下的行 |

- 「该评审人名下的行」＝ 问题汇总表 B 列按顿号拆分后包含其姓名、且 A 列前缀等于本场节点的行。
- **多行时按「至少一行三要素齐全即算齐全」判定**。理由：Go with Risk 专家很可能在会签遗留问题之外还提了纯技术交流类问题（那类往往不写改善措施），按「所有行都要齐全」会将其误判为有缺项。

| 情形 | 档位 | 分值 |
|---|:---:|---:|
| E 列非空，且名下至少一行 D、E 两列均非空 | 高 | 30 |
| E 列为空 且 名下无任何行 | 低 | 0 |
| 其余（缺任一要素） | 中 | 20 |

**Step 5｜场次过程表现分** ＝ 三项之和，取值范围 0–60。

**已删除的规则**：原「拒绝补交归零」条目。拒绝补交的结果由现有规则自然推导——D 列 `TBD`（会签 0、意见 0）＋ C 列 `缺席未改派`（出勤 0）＝ 三项全 0，无需单设标记字段。

### 3.4 专业价值贡献字段（每项目一组，人工作答问卷）

| 字段 | 允许档位 | 分值 | 填写人 |
|---|---|---|---|
| ① 履职与协作 | 高｜中｜低 | 10／6／0 | 技术项目经理 |
| ② 专业判断与指导 | 高｜中｜低 | 20／14／0 | 技术项目经理 |
| ② 专业判断0分原因标签 | 多选枚举 | — | ②选择低档时至少选择1项；`严重技术误判｜重大风险遗漏｜竞争力误判｜其他` |
| ② 0分原因和导致影响 | 文本，1–100字 | — | ②选择低档时必填；其他档不保存 |
| ③ 突出贡献 | 有｜无 | 10／0 | 技术项目经理（**默认无**） |
| ③ 突出贡献加分原因 | 文本，1–100字 | — | ③选择有时必填；选择无时不保存 |
| 专业价值贡献分 | — | 0–40 | AI按档位换算 |

**问卷约束**：

- 技术项目经理**只作答档位，不接触分数**；分数由AI换算（《办法》§2 备注）。
- ②专业判断与指导选择低档时，必须至少选择一个0分原因标签，并手工填写100字以内的「0分原因和导致影响」；标签或说明缺失、说明为空白／纯空格／超过100字均阻止提交，后端须重复校验。其他档不保存这些审计字段。
- ③突出贡献选择有时，必须手工填写100字以内的加分原因；空白、纯空格或超过100字均阻止提交，后端须重复校验。选择无时不写入加分原因。
- 每位专家一次问卷，**约1分钟**；TDR3结束后统一作答。
- 专家TDR3未参会也照常作答。

### 3.5 派生字段与公式

| 字段 | 公式 |
|---|---|
| 项目过程均分 | `Σ(各场次过程表现分) ÷ 有效场次数`；有效场次数的判定见 §1.2（TDR1+TDR2 合并评审时为2，节点裁剪时相应减少） |
| 专业价值贡献分 | `①＋②＋③`，0–40 |
| **项目评审总分** | `项目过程均分 ＋ 专业价值贡献分`，0–100 |
| **专家考核平均分** | `Σ(各项目评审总分) ÷ 参与项目数`（**分母为项目数，非场次数**） |
| **等级** | ＝100 → S；≥90且＜100 → A；≥75且＜90 → B；≥60且＜75 → C；＜60 → D |
| 样本量提示 | 参与项目数 ＜2 → 「样本量小」，与等级并列展示 |
| 记录状态 | 草稿｜待技术项目经理确认｜待问卷作答｜已完成 |

## 4．AI流程与校验

### 4.1 每场评审后（AI＋技术项目经理，约10分钟）

1. 技术项目经理提供本地 Excel 文件或飞书云文档 URL；AI识别输入类型后，按 §1.2 确定参与解析的 TDR sheet，再按 §3.3 推导每位专家的三项档位并算出场次过程表现分。
2. AI输出异常清单。
3. 技术项目经理与AI交互，确认异常项、缺席与改派记录。
4. 记录置为「已确认」，**分数不需人工填写**。

### 4.2 TDR3结束后

1. AI向技术项目经理推送问卷（每位专家3题）。
2. 技术项目经理作答档位；②专业判断与指导选择0分时补充原因标签及100字以内的「0分原因和导致影响」，③突出贡献选择10分时补充100字以内的加分原因。
3. AI按档位换算专业价值贡献分，合并过程均分，算出项目评审总分与等级。
4. AI生成项目汇总与专家跨项目汇总。

### 4.3 自动校验

读取阶段以24张检查卡片承载以下底层规则。每张卡片检查动效不少于0.5秒；来源读取、飞书导出等操作耗时更长时按实际完成时间停留。**错误**阻止进入评分，**提醒**列出来源位置，技术项目经理勾选确认后可以继续。

| 类别 | 校验项 | 异常条件 | 处理 |
|---|---|---|---|
| 文件 | 文件类型与内容 | 非 `.xlsx`、空文件、超过30MB、不是有效XLSX压缩结构或工作簿无法解析 | 错误 |
| Sheet结构 | 业务区块 | TDR候选Sheet缺少基本信息、会签或问题汇总区块 | 错误 |
| Sheet结构 | 必要表头 | 会签列表或问题汇总表缺少规范要求的列 | 错误 |
| Sheet结构 | 有效场次 | 排除示例与无评审人的空表后没有正式评审场次 | 错误 |
| 基本信息 | 项目名称／编码 | 项目名称为空，或`技术项目+编号`无法提取项目编码 | 错误 |
| 基本信息 | 项目阶段 | 为空、不在`TDR1｜TDR2｜TDR3｜TDR1+TDR2`枚举，或同一工作簿内阶段重复 | 错误 |
| 基本信息 | 日期／项目经理 | 会议日期为空或无法识别，或技术项目经理为空 | 错误 |
| 基本信息 | 会议评审结论 | 为空或不在`Go｜Go with Risk｜Redirect｜TBD`枚举 | 错误 |
| 会签 | 角色与评审人 | 评审角色为空、评审人为空，或同一场会签列表中评审人重复 | 错误 |
| 会签 | 出勤枚举 | C列为空或不在§2.2词表内 | 错误 |
| 会签 | 会签结果 | D列为空，或去掉合法逾期后缀后不在§2.2词表内 | 错误 |
| 会签 | 依据缺失 | D列为Go with Risk／Redirect但E列为空 | 提醒 |
| 会签 | 缺席但有依据 | C列为`缺席未改派`／`挂会`，但E列有内容 | 提醒 |
| 会签 | 改派缺代理人 | C列为`改派（正常）`／`改派（部分）`，但B列无`（代理：X）`后缀 | 错误 |
| 问题 | 问题编号 | 为空、格式不匹配`TDR\d+-\d+`、同场重复，或项目内同编号对应不同问题描述 | 空值／重复／冲突为错误；格式异常为提醒 |
| 问题 | 必填字段 | 提出人、问题描述或问题状态为空，或问题状态不在`open｜closed`枚举 | 错误 |
| 问题 | 提出人匹配 | 问题提出人不在本场会签列表 | 提醒 |
| 问题 | 问题行缺失 | Go with Risk／Redirect没有该专家名下且前缀匹配本场节点的问题行 | 提醒 |
| 问题 | 意见三要素 | 对应问题行没有任何一行同时填写改善措施和验证方式与通过条件 | 提醒 |
| 计分 | 场次与项目边界 | 场次过程分不在0至60、项目过程均分不在0至60，或有效场次数与评分明细数不一致 | 错误 |

专业价值贡献的「依据缺失」与「评定和过程事实矛盾」属于问卷阶段校验，不计入本节24张评审报告检查卡片，仍按《办法》§4执行。

### 4.4 解析容错

评审表由人工填写，AI 读取时必须做以下容错，不得因书写差异判定失败：

| 容错项 | 要求 |
|---|---|
| **标点** | 全角与半角等价：`（）`＝`()`、`、`＝`,`＝`，`、`：`＝`:`。多人分隔符 `、`／`，`／`,` 一律按分隔符处理 |
| **空白** | 忽略首尾空格与单元格内的换行；连续空白折叠为一个 |
| **大小写** | 枚举值比对大小写不敏感（`go with risk` ＝ `Go with Risk`） |
| **引用式填写** | E 列「评审依据」写成 `同XXX的评审依据`、`同上` 等引用形式的，**视为已填写**。依据《办法》§3 备注3，意见完整性只判有没有写、不判内容质量 |
| **姓名匹配** | 以全名精确匹配；匹配不上时进入异常清单由人工确认，**不得做模糊猜测** |
| **日期** | Excel 日期序列号与文本日期均需支持 |
| **项目编码** | `技术项目+编号` 的括号支持全角 `（）` 与半角 `()`；取**最后一对**括号内的内容为编码，项目名本身含括号时不受影响（如 `展锐B3+中高频CA（B250074A）`） |
| **说明行** | 每个区块首行为填写说明行，内容以 `↓` 开头或 `A` 列不匹配数据格式，一律跳过不计分 |

### 4.5 AI边界

- **评审过程会签分**：AI全自动判定与计算，人工只确认异常。
- **专业价值贡献分**：档位必须由人工选定，AI**不得预填档位**。
- AI可提供参考素材：该专家提出的问题清单、被采纳情况、闭环记录、会上是否临时索要材料的记录。

## 5．权限与审计

- 技术项目经理只维护自己负责项目的评审事实和异常确认。
- 技术项目经理只作答自己负责项目的问卷。
- 专家可查看本人记录和依据说明，不能修改。
- AI读取考评记录生成汇总，不修改已完成记录。
- 所有问卷档位与依据说明保存作答人及时间。

## 7．未来优化遗留项

以下为已识别、当前版本**有意不处理**的问题，留待内部审核后或试运行阶段再议。

| # | 事项 | 现状与理由 |
|---|---|---|
| 1 | 缺席未改派但补交了 Go 结论的专家仍可得 45／60 分 | 「缺席未改派 → 出勤 0」与「会签 Go → 意见高档」两条规则叠加的结果，逻辑自洽。本版暂不加「缺席时意见不得给高档」的限制，因为考评核心价值在评审意见质量，主观部分由维度二问卷承担 |
| 2 | 「评审意见」30 分子项区分度低 | 有意为之：意见只判格式完整性、不判内容质量，是为了让维度一的AI自动化程度尽量高、判定结果稳定可复现。质量判断全部交给维度二的人工问卷，避免AI主观识别的一致性问题 |
| 3 | 档位线 90／75／60 是否合理待验证 | 单场中11位专家的横向均值不属于本系统指标，不能作为档位线锚点。需为每位虚拟专家分别构造同一项目的TDR1／TDR2／TDR3有效评审记录，以该专家的跨场次过程均分加一次专业价值贡献形成项目总分，再观察10位专家的项目总分分布 |
