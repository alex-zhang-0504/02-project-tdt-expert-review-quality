# 登录与本人项目统计交互草稿 V1

状态：2026-09-29交互预览，待用户确认。正式系统、真实账号与评分配置未修改。

## 本轮方案

- 本机首次输入姓名，精确匹配唯一启用账号；之后只显示本浏览器记住的姓名，点击登录。共用电脑可选择「不是本人」。记住账号不是身份认证，不能防止冒名。
- 工号继续作为内部编号，不在登录和业务界面显示，不要求操作者填写。
- 飞书自动识别入口仅模拟可信身份已确认的效果，没有接入飞书。未来应由服务端使用飞书登录身份映射运行账号；不能用手输姓名作为认证凭据。
- 项目经理只能查看本人报告对应的客观统计及详情，包括缺席、未会签记录，可修改本人项目的对策判定；不提供客观打分页。
- 管理员全量预览展示全部项目。切换身份、阶段、页面只影响展示；主动修改对策判定单独保存，并更新全量对策条数。正式实现须据此重新计算相应分数。
- 直接复用正式系统的样式、客观统计表及评审详情呈现；问卷采用当前配置文案，保留首次须知、条件依据和完成状态。

## 验证与限制

真实浏览器验证：停用姓名拒绝登录；经理甲、乙各自范围；管理员全量范围；本人范围保留缺席事实；切换统计阶段不改全量事实；甲将一条疑似对策计入后，全量对策条数从3变为4、原始事实保持不变；问卷六题完成、返回卡片显示6／6，刷新重登仍保留；账号记忆不显示人员下拉名单。

所有数据均为虚拟数据，保存到独立浏览器存储键 `tdt-identity-scope-draft-v1`。此草稿没有正式后端鉴权、实际飞书认证、配置合并或分数引擎，不能作为这些功能的完成验收。正式集成仍须验证服务端读写范围、越权请求拒绝和全量计分不受显示筛选影响。

统一账号配置及三位指定管理员属于后续正式方案，本草稿未修改真实名单。任务仍需要独立名单／参数历史快照。

未来身份接口依据：[飞书获取登录用户信息](https://open.feishu.cn/document/ukTMukTMukTM/uIDO4UjLygDO14iM4gTN) 。接口提供应用内稳定 `open_id`；`employee_no` 需要对应通讯录权限，不能预设所有环境均可取得。
