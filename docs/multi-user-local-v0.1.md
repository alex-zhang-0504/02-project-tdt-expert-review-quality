# 多人本机版功能与存储契约V0.1

2026-09-26用户确认并授权实施，仅本机验证，不部署妙搭。

## 2026-09-28正式集成契约

本节覆盖下方旧版流程中有冲突的页面入口和生命周期约定；实现验收状态以`ROADMAP.md`为准。

- 继续用根目录`start.cmd`启动当前检出代码。管理员登录需要密码，无默认密码；已有本机评分参数密码直接复用，首次设置须重复输入。密码以加盐哈希保存于`var/scoring-admin.json`，不写账号配置。项目经理无密码，角色由配置决定，其他三个模块显示锁且不可操作；后台同时校验权限。
- 「考核任务信息」的置顶卡片创建新任务：选择年份、年度／上半年／下半年，导入完整账号JSON。系统合并新增账号，拒绝与当前账号信息冲突的导入。任务按创建时间倒序，进行中卡片展示客观与主观进度；点击卡片进入原有读取与匹配页面。删除任务须二次确认，逻辑移除，不删除问卷备份。
- 日常账号管理使用`var/multi-user/accounts.json`，含`employee_id`、`name`、`role`、`enabled`和`owner_ids`。文件每次访问重新读取；页面创建任务导入及异常owner关联写回同一文件。此前账号编辑、备份等「管理设置」面板按确认设计取消，既有后台接口保留。人员离任停用，工号和历史记录不更换。
- 读取名单、人工匹配、错误／提醒、客观两页表格、主观题卡、详情和导出沿用main。读取底部只保留「读取→下一步」，移除成功参数凭据和返回任务信息按钮；顶部「读取评审表」返回任务清单。改名单或重读报告须重新确认范围，保留原任务的参数及问卷，不沿用旧范围统计。
- 管理员主观页保留项目经理选择和左侧评审人列表，底部只切换问卷／打分。管理员可直接代填所有归属项目经理的问卷，无须项目经理登录；仍按每位项目经理同一评审人一票，保留代填／调整历史，管理员调整后项目经理只读，可退回。首次进入须知沿用main，每次登录会话首次进入弹出。
- 项目经理先看到「我的问卷」和总人数，不罗列具体项目；打开问卷只展示当前评审人，姓名旁提示列出全部共同项目，并保留「查看评审过程详情」。完成后返回列表展示已保存及6／6；缺少必填依据或原因不能算完成。退出、刷新及服务重启后从SQLite恢复。
- 进行中任务分别提供「客观评分参数」「主观评分参数」，对应两份配置文件。沿用main只读、解锁、预览、保存后锁定的编辑器。后台校验范围、版本冲突，原子写入并重新读取；任务存储失败时恢复文件，不能报告虚假的同步成功。当前任务重算，其他任务快照不变，新任务用最新配置。
- 首份问卷保存答案、依据或原因即锁定题干、选项含义及依据要求，清空也不解除。管理员代填同样触发。数值参数可在正式完成本期考评之前调整；原答案保留、匹配新分值并重算，参数修改前后与操作者记入历史。
- 总分统计底部「完成本期考评」在客观评价、全部应评问卷或有效总分不齐时禁用。满足后需二次确认，归档参数、问卷和统计结果；此后后台也拒绝编辑。已完成卡片打开独立历史总分弹窗，没有导出入口，右下角关闭；第四模块仍服务进行中任务。
- 工作区自动每日备份SQLite。手动另存建议关闭本项目服务后，复制整份`var/multi-user/`及`config/`。问卷成功保存不依赖浏览器缓存。当前仅本机持久化，无妙搭、跨电脑实时同步或半年度自动沿用。

新增任务接口位于`/api/workspace/tasks`：创建、报告挂接、范围失效、完成、历史查看、逻辑删除，以及`/{id}/policy/objective`、`/{id}/policy/subjective`独立参数读取与修改。复用现有SQLite载荷字段，不为本次集成新建或迁移数据库表。

## 范围与身份

2026-09-27固定身份关联更新：账号使用`owner_ids`数组保存飞书原文件owner_id，与姓名和工号同列配置，一人通常填写一个ID，也兼容既有多个来源身份。旧数据库bindings在账号尚无`owner_ids`字段时自动迁入；迁入后只读账号配置，SQLite bindings仅为备份快照。正常匹配不显示关联控件，未知或停用身份只在扫描区下方显示异常；同一owner_id只确认一次并持久写入配置，不按同名自动绑定。本地Excel无稳定身份时仍需一次指定本次报告归属，不能伪造飞书owner_id。两页分页为底部居中「新建考核 →」／「← 返回考核列表」，保留原名单业务操作及主干名单布局。

2026-09-27账号配置解耦已获授权，包含现有账号迁移。账号权威来源为工作区内`accounts.json`，默认`var/multi-user/accounts.json`；页面和文件共用姓名、工号、角色、启用状态。工号保持稳定，人员更替使用新增与停用，已确认考核和历史姓名快照不随账号编辑改变。文件每次访问重新读取，刷新页面可更新展示；页面保存比较编辑前账号，冲突不覆盖。配置必须保留至少一个启用管理员，重复工号、非法角色或格式错误显性拒绝，不回退到旧名单。手工删除也执行关联保护；停用不删除历史。

首次升级从旧数据库提取账号并写入JSON；数据库升级前另存备份，账号配置快照仅供备份与校验，不作为日常第二份配置来源。已迁移后JSON丢失会报错，不从旧表静默复活账号。完整SQLite备份包含最近读取的有效账号配置（含停用状态），恢复同步恢复配置文件；兼容旧版备份。账号配置属于本机数据，不入Git；两端同步限当前工作区，不代表跨电脑或妙搭同步。

- 首次使用登记管理员姓名及工号；管理员建立经理账号，姓名用于显示，工号为字符串且唯一。管理员可以兼任经理。
- 管理员可在账号旁点击「编辑账号」修改姓名、角色、启用状态；工号不可修改。点击「删除账号」后核对姓名及工号再确认或取消。仅删除未关联报告、考核、问卷或操作历史的账号；当前登录账号及最后一个启用管理员不可删除。删除后不再出现在登录列表，旧登录身份失效；不删除考核数据。
- 入口选择已有姓名与工号，不要求密码，信任使用者选择本人身份；角色与任务范围仍由后台检查。
- 管理员统一导入报告，确认名单及归属后冻结任务与评分参数快照。经理只填写本人问卷，可查看共同项目的过程依据，不读取其他经理答案或全局分数。
- 飞书原文件owner_id保持事实来源，管理员明确绑定到工号；本地报告明确指定工号。一个账号的多个来源身份合并为同一经理一票。

## 存储与问卷

- SQLite采用Python标准库，新建于`var/multi-user/assessment.sqlite3`；`TDT_WORKSPACE_DIR`可指定独立验证目录，不覆盖既有var数据或凭据。
- 账号由`accounts.json`管理，数据库保存用于备份的账号快照、owner_id绑定、报告解析事实、考核范围、问卷及参数快照、问卷修订和管理员调整历史。原始上传工作簿不作为恢复必要条件，保存的是解析事实及原始摘录、来源位置。
- 写入成功后才显示已保存；每份问卷检查修订号，过时修改返回冲突，不静默覆盖。离开问卷先保存，失败保留输入。刷新、重新选择身份及重启后从数据库恢复。
- 管理员调整他人问卷不增加票数；保留原经理、修改人及前后内容，经理只读；退回仍保留调整版本，经理可继续编辑。
- 自动按日备份已有数据库，支持下载完整数据库快照；恢复先预览、明确确认，并先备份当前数据。恢复后重新选择身份。

## 验收

### 本机启动验证步骤

1. 当前目录已切到`codex/multi-user-assessment`，直接双击项目根目录的`start.cmd`，使用它新打开的页面，不沿用旧版标签页。
2. 首次登记管理员姓名、工号；展开「账号登记与本机备份」登记经理，工号保留前导零。
3. 「新建考核」导入所有报告。本地报告在各行选择经理；飞书原文件owner_id须明确关联已有账号。填写考核名单、读取评分参数并确认。
4. 管理员进入客观数据评价完成识别、人工确认及导出。切换身份后，经理从考核列表进入问卷，只看到本人的评审人和共同项目。
5. 填写后等待「已保存」。关闭浏览器，重新双击`start.cmd`，登录后可继续原问卷，无须重新导入报告。只有未保存输入会触发离开提醒。
6. 管理员在列表查看每人进度，进入具体问卷调整或退回；全部有效结果齐备后点击「确认最终主观结果」，导出正式结果。需修改时先「重新开放问卷」，历史快照保留。
7. 定期下载完整备份并另存一处。恢复选择`.sqlite3`文件，核对账号及考核数量，再点击「确认恢复并重新登录」。恢复前副本保存在`var/multi-user/backups/`。

### 直接管理账号配置

使用新版本`start.cmd`打开的页面，首次读取账号时自动生成`var/multi-user/accounts.json`，不必重复登记。页面账号区显示实际路径；指定独立工作区时文件也放在对应工作区中。

文件格式示例（仅示意，请在原名单上编辑，不要用示例覆盖）：

```json
{
  "version": 1,
  "users": [
    {"employee_id": "0001", "name": "虚拟管理员", "role": "admin", "enabled": true},
    {"employee_id": "0010", "name": "虚拟经理", "role": "manager", "enabled": true}
  ]
}
```

- 工号必须带双引号，保留前导零；`role`只能是`admin`或`manager`，`enabled`为`true`或`false`。
- 页面新增或编辑成功后，系统原子替换文件并重新读取；面板保持展开。手工保存文件后点击「刷新账号配置」或刷新页面，无需重启服务。
- 已打开的页面不定时轮询文件，但后台每次操作都会读取最新身份权限。管理员把自己降为经理或停用后，页面重新进入对应身份界面或登录页。
- 页面编辑与文件编辑冲突时拒绝覆盖，保留输入；先复制所需修改，再刷新名单重新编辑。非法JSON、重复工号、移除最后一个管理员会显性报错，请修正文件后刷新，不静默使用旧名单。
- 人员更替保留原账号并设`enabled: false`，新增接任人员的新工号；需要重新分配已固定任务属于另一个业务操作，不会通过改名或换角色自动转移。
- 配置文件丢失时，从完整备份提取`account_config`快照可恢复；日常优先保留整份工作区备份，勿直接编辑数据库。迁移前原始数据库保存在`backups/before-accounts-*.sqlite3`，新版工作区备份仍是单个SQLite文件。

工作区备份包含既有考核的配置快照；新考核使用的全局评分配置仍来自`config/`，不随工作区恢复而替换。AI密钥及参数编辑解锁凭据不进入工作区备份。验证数据使用独立`TDT_WORKSPACE_DIR`；启动器同时检查工作区标识，正常双击不会复用隔离测试工作区。

### 服务端接口

- `/api/workspace/session`、`/bootstrap`、`/login`、`/logout`负责本机身份；`/users`登记账号，`/bindings`关联原文件owner_id。
- `DELETE /api/workspace/users/{employee_id}`仅管理员可用，按上述关联保护规则删除未使用账号；报告读取或AI分析过程中暂不允许删除。
- `PUT /api/workspace/users/{employee_id}`修改姓名、角色与启用状态，须携带编辑时的`expected`账号内容；服务端重读文件并检查冲突及当前管理员权限。`/session`返回配置文件路径，管理员名单包含停用账号，登录名单仅含启用账号。
- `/api/workspace/analyses`及`/analyses/{id}`按角色读取考核；既有`/api/assessment/tasks`仅返回本人任务和问卷，管理员可查看全部。
- 既有`/api/subjective/review`增加修订检查；`/api/workspace/history`与`/return`提供历史及退回。
- `/api/workspace/finalize`确认或重新开放；`/export`导出带结果状态的主观Excel。
- `/api/workspace/backup`下载SQLite快照；`/restore-preview`校验并预览，`/restore`明确确认后恢复。报告读取或AI任务进行中禁止恢复。

### 验收目标

- 两名经理看到各自任务，管理员看到完整进度；改查询编号不能读写其他经理问卷。
- 同一经理多项目仍一票，全部无法判断的题目阻止最终分；已回应与有效评价分别展示。
- 管理员修改、只读、退回、并发冲突、保存失败及重新加载均有对应验证。
- 全新进程及真实浏览器验证重启恢复、备份恢复与实际Excel下载；数据库及配置使用隔离测试副本。
