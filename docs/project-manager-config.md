# 项目经理名单配置

本机文件：`config/project-managers.json`。管理员修改后，在「新建考评任务」的「导入项目经理名单」选择这个 JSON 文件，再点击下一步。修改文件本身不会自动改变运行账号；导入成功才生效。Excel 是这次生成配置的数据来源，页面仍选择 JSON。

文件结构如下，仅使用虚拟人员举例：

```json
{
  "version": 1,
  "users": [
    {"name": "虚拟项目经理甲", "employee_id": "001001", "enabled": true},
    {"name": "虚拟项目经理乙", "employee_id": "001002", "enabled": false}
  ]
}
```

- `name`：姓名，须与飞书原文件所有者姓名一致。启用的人员不能重名。
- `employee_id`：工号，必须带英文双引号，保留前导零。同一人的工号保持不变；人员替换时新增工号并停用旧人，不把旧工号改成另一个人。
- `enabled`：`true` 表示启用，`false` 表示停用，不加引号。

新任务只纳入本次清单中启用的项目经理。清单中停用或未列出的既有项目经理账号会停用，不能继续登录，但不会删除问卷、历史考评、姓名快照或内部报告关联。管理员账号的角色及登录启用状态不由项目经理清单改变；管理员兼任项目经理时，仍按清单决定是否纳入新任务。

飞书报告仍从原文件所有者获取姓名。姓名唯一匹配本任务启用人员时自动关联工号；已建立的内部关联继续保留。缺失姓名、重名、停用、未纳入等异常需要确认。本地 Excel 报告无飞书原文件所有者，仍需指定归属。

导入后运行账号写入 `var/multi-user/accounts.json`，管理员无需维护其中自动保存的 `owner_ids`。已确认任务的归属与问卷不随新任务名单重新分配。真实配置已排除 Git，请随本机数据备份保存；不会跨电脑自动同步。

## 已有任务修改名单

管理员在未完成任务卡片点击「修改项目经理名单」，选择更新后的 `project-managers.json`，核对人员及启用状态后点击「确认更新名单」。新建任务时的导入入口继续保留。

名单修改仅调整本期主观问卷任务及其汇总：取消人员的原问卷、修改历史保留，但不计入本期有效主观结果；不转交问卷或继承他人答案。客观报告、评审人范围、名单确认和客观得分保持不变，评分参数也不变。没有有效主观评价时不能生成完整总分，不以零分补齐。

名单导入沿用账号同步规则，账号停用会影响登录；其他任务的历史名单快照不被改写。已完成任务只读。页面更新运行账号及任务名单，不自动反写电脑上的导入源文件。
