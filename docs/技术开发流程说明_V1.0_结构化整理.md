## 1. 流程全景概览

### 1.1 流程定位
技术开发是技术规划&技术charter和产品开发中间的位置，承接技术charter或价值决策输出的技术需求（含技术指标、进度要求等）实现，并在产品开发段完成技术迁移，为技术成果在产品上转化起到指导作用，实现技术价值。

### 1.2 流程目的
保障各部门可以共同协作、高效完成技术项目开发，且职责明确，关键阶段和活动定义清晰。

### 1.3 流程框架

| 维度 | 内容 |
|------|------|
| **五个阶段** | 概念阶段 → 计划阶段 → 开发验证阶段 → 技术迁移阶段 → 技术维护阶段 |
| **四个TDR** | TDR1(概念阶段评审) → TDR2(计划阶段评审) → TDR3(开发验证评审) → TDR4(技术迁移评审) |
| **三个DCP** | PDCP(计划决策检查点) → TDCP(迁移决策检查点) → END-DCP(关闭决策检查点) |

> **⚠️ 实际执行情况备注**：**DCP活动实际未执行**，以**TDR**为重要评审节点进行技术评审和阶段决策。

### 1.4 适用范围
- **适用对象**：通过技术charter或价值决策后，需要进行技术项目开发的过程指导
- **项目类型**：研发级技术项目、部门级技术项目

### 1.5 触发条件与终点

| 触发场景 | 场景条件 | 流程终点 |
|----------|----------|----------|
| 技术项目通过技术charter、价值决策 | 研发级项目向TMT申请立项批准；部门级项目向一级部门申请立项批准 | 完成技术成果向产品项目转化，通过END-DCP或PDCP/TDCP/END-DCP决策后项目终止 |

> **⚠️ 实际执行情况备注**：由于人力因素，**charter环节实际未执行**。项目启动的实际输入只有《商业计划书》和《技术项目价值KPI》。

## 2. 核心术语定义

| 术语 | 定义 |
|------|------|
| **概念阶段** | 清晰定义技术开发目标并论证方案可行性，确定一个当前最优的技术方案 |
| **计划阶段** | 完成系统、软件、ID、硬件、整机及其他子系统的方案设计，确保匹配技术需求与技术规范；制定测试方案、测试计划和技术项目开发验证计划 |
| **开发验证阶段** | 完成技术开发活动、迁移准备活动、测试验收活动等，准备向产品或者平台进行迁移 |
| **技术迁移阶段** | 按迁移计划，将技术开发项目技术成果迁移到产品/平台，支撑产品/平台的设计/开发、系统联调、生产验证调试以及支撑问题解决等 |
| **技术维护阶段** | 仅保留技术接口，持续关注技术在产品上的使用表现，支撑并建立技术成果共享渠道 |
| **TDR** | Technical Development Review，技术开发评审 |
| **TDR1** | 概念阶段技术开发评审，关注：技术目标分解分配是否准确完整、技术实现是否可行且是当前最优设计方案、成本评估是否合理 |
| **TDR2** | 计划阶段技术开发评审，关注：方案设计是否支撑技术目标、方案设计是否满足技术规范、成本估算是否合理 |
| **TDR3** | 开发验证阶段技术开发评审，关注：技术交付成果是否达成、测试/质量验收是否通过、是否有遗留重大技术风险未解决 |
| **TDR4** | 技术迁移阶段技术开发评审，关注：技术成果在产品上的使用情况 |
| **PDCP** | Plan Decision Check Point，计划决策检查点 |
| **TDCP** | Transfer Decision Check Point，迁移决策检查点 |
| **END-DCP** | End Decision Check Point，关闭决策检查点 |
| **质量目标** | 明确项目各关键节点的质量达成条件，确保项目阶段性结果满足质量要求，内容包含质量标准、国家标准及部分质量需求 |
| **质量标准** | 将各类技术的关键考核指标转化为可测量的验收标准，通过测试手段确保各项指标的符合度 |

## 4. 阶段活动详述

### 4.1 概念阶段

**阶段目的**：清晰定义技术开发目标并论证方案可行性，确定一个当前最优的技术方案；制定项目计划，确保技术风险可以被有效管理

**关注点**：
1. 明确技术需求，包括需求目标和应用场景；进行需求的分解分配，明确到具体责任人
2. 评估技术的多个备选概念，确定一个最优的概念（成本等），保证竞争力
3. 制定初版项目计划，如有迁移对象，需完成与迁移对象的计划咬合
4. 识别技术、测试、采购、制造等维度风险并给出应对措施

### 4.2 计划阶段

**阶段目的**：完成系统、软件、ID、硬件、整机及其他子系统的方案设计，确保匹配技术需求与技术规范；完成除技术外其他维度匹配的方案与设计

**关注点**：
1. 技术需求如何通过技术方案实现
2. 设计方案需符合知识产权、安全隐私、榫卯、CBB等要求
3. 测试、采购、质量、制造、项目管理维度输出匹配技术方案的设计与计划
4. 如有迁移对象，需完成初版迁移方案

#### 活动101：完成技术方案设计

| 项目 | 内容 |
|------|------|

## 5. 流程裁剪规则

### 5.1 裁剪原则

1. 流程裁剪规则的目的是为了适配各类型技术项目需求，对小型技术项目裁剪冗余的步骤，使流程更加灵活和适应性强，以提高工作效率
2. 裁剪原则包含对团队构成、关键节点
3. 交付物没有单独裁剪规则，只是连同角色和节点被裁剪而已
4. 没有活动裁剪规则，不同模块设计的活动差异在流程活动中已经分类说明，根据具体技术项目情况选择所属模块活动描述内容即可

### 5.2 裁剪步骤

技术项目立项时由TCDT leader根据技术项目实际特点和裁剪指南中规定的裁剪原则，对流程中的**团队成员、评审决策点、交付物**进行调整（合并或裁剪），并在技术Charter报告中进行呈现，由决策组织（TMT/一级部门负责人）进行决策后生效，技术开发阶段按照决策内容实施裁剪。

### 5.3 关键控制点裁剪标准

| 裁剪标准 | 说明 |
|----------|------|
| **无迁移计划项目** | 迁移阶段、维护阶段可以裁减，需在开发验证阶段完成项目总结复盘、资料归档；若在TDCP后明确迁移对象可进入技术开发迁移阶段，并完成迁移方案变更 |
| **TDR1评审** | 在原TDT流程中可行性评审的扩展，对技术项目很重要故TDR1不能裁剪 |
| **TDR4和END-DCP** | 常规技术项目可合并，但TDR4如有重大遗留问题需要过END-DCP决策才能关闭项目 |
| **TDR1和TDR2** | 根据项目任务情况可以合并，由技术PM和技术负责人判断 |

## 6. 关键控制点(KCP)

| KCP点 | 关键交付物 | 控制要素说明（关注点） |
|-------|------------|------------------------|
| **TDR1** | 技术目标分解表、可行性报告 | 1. 技术目标分解分配是否准确和完整<br>2. 技术实现是否可行且是当前最优设计方案<br>3. 成本评估是否合理 |
| **TDR2** | 技术方案 | 1. 方案设计是否支撑技术目标<br>2. 方案设计是否满足技术规范<br>3. 成本估算是否合理 |
| **PDCP** | 项目范围、计划、可行性、迁移方案（刷新） | **思考阶段和实施阶段的分界点**：基于TDR评审输出的技术风险与结论进行业务决策，通过意味着概念阶段和计划阶段目标已达成，同意进入开发验证阶段并同意资源投入<br>1. 技术方案和需求（价值）的符合性、技术竞争力<br>2. 技术方案是否还有竞争力，对应风险是否有措施<br>3. 设计成本（BOM成本）、资源投入、迁移计划可行性 |
| **TDR3** | 技术交付成果（代码、原理图、样机、PCB）、测试报告、质量评估、迁移计划、技术应用指导书 | 1. 技术交付成果是否达成<br>2. 测试、质量验收是否通过，是否有遗留的重大技术风险未解决 |
| **TDCP** | 测试报告、迁移方案（终稿） | **是否达到技术目标，技术向用户产品迁移是否达到要求**：<br>1. TDCP存在三种结论：①挂起（等待迁移对象ready）、②关闭（无迁移对象）、③正常迁移<br>2. 技术目标可达成性<br>3. 迁移技术准备度 |
| **TDR4** | 产品项目测试报告、技术项目复盘报告 | 1. 技术成果在产品上的使用情况 |
| **END-DCP** | 技术项目复盘报告、技术项目维护方案 | **对技术成果转化后的评判和对后续应用范围的明确**：如不满足关闭条件，可以继续迁移<br>1. 技术迁移成果达成性<br>2. 项目经验总结<br>3. 技术项目是否可以关闭<br>4. 维护阶段资源投入 |

   - 《技术项目质量策划》
   - 软件PD/影像PD
   - 《TDR1评审检查表》

2. **确定评审团队**
   - 根据各领域评审主责人表，确定评审主席
   - 评委主席确认评委团
   - 评审团队成员包含：本技术领域专家、关联领域技术专家（采购、制造、温升、性能、功耗等）、CBB管理代表、技术规划代表、测试专家、质量代表、SE
   - 视需要协调相关人员作为评委参与评审

3. **组织评审会议**
   - 拉通评审团队确定评审时间、地点以及评审形式

#### 配合其他活动

- **无质量代表参与时**：负责《技术项目风险评估与控制报告》的收集和管理
- **成本分析**：结合各领域输出的人力投入、物料需求、NRE费用等，完成技术项目成本分析（含人力和非人力费用）

### 7.2 计划阶段职责

#### 制定详细开发计划（活动108）

1. **整合输出详细开发计划**
   - 根据《软件详细设计》
   - 《测试计划》
   - 迁移策略（原专项导入计划）

2. **收集样机需求**
   - 组织项目团队收集样机需求
   - 输出《样机资源统计表》

#### 制定初版迁移方案（活动109）

依据charter中确定的迁移产品（首导项目）制定迁移方案初版：

1. **组建迁移核心团队**
   - 和迁移基线开发经理/SE/产品线项目经理共同组建迁移核心团队
   - 明确迁移阶段的产品主导人

2. **明确迁移支持内容**
   - 技术负责人输出迁移阶段支持活动
   - 明确哪些是技术团队支撑范围并和产品开发成员达成一致意见

3. **制定迁移计划**
   - 根据迁移产品项目计划制定迁移的启动时间和结束时间
   - 制定关键任务计划

   > **注**：迁移基线项目，迁移计划可分阶段输出，如果在基线开发阶段可以先输出基线开发迁移计划

#### 组织TDR2评审（活动110）

1. **收集汇总评审资料**
   - 《软件概要设计》
   - 原理图、堆叠、摆件、ID设计
   - 《软件详细设计》
   - 《交互设计》V1.0
   - 《测试策略及方案》
   - 《项目质量标准》V1.0
   - 《资源供应计划》V1.0
   - 《技术项目关键器件选型》V1.0
   - 《生产新工艺说明书》V0.1
   - 《XXX技术项目迁移方案》V0.1

2. **确定评审团队**
   - 根据各领域评审主责人表确定评审主席
   - 评委主席确认评委团构成
   - 评审团队成员包含：本技术领域专家、关联领域技术专家（采购、制造、温升、性能、功耗等）、CBB管理代表、技术规划代表、测试专家、质量代表
   - 如有迁移计划的项目，需要邀请迁移产品开发核心人员（SE、基线开发经理、PQA）参与评审

3. **组织评审会议**
   - 拉通评审团队确定评审时间、地点以及评审形式

#### PDCP决策支持（活动112）

1. **确定决策层级**
   - 按照《技术体系分层决策机制》（待发布）确定技术项目PDCP的决策层级

2. **上会准备**
   - 若技术开发项目需要上会TMT决策，则参照《TMT上会标准指南-V1.2》执行上会流程并获得决策结论

### 7.3 开发验证阶段职责

#### 召开KO会议（活动201）

- 邀请项目团队成员及CBB管理代表参加KO会议
- 介绍项目背景、技术项目目标、技术项目计划、技术项目风险等

#### 发起物料备料&试产申请（活动204）

1. **发起备料申请**
   - 根据技术项目计划、《样机资源统计表》和BOM清单发起备料申请给采购代表和PMC

2. **发起试产申请**
   - 在试产前3天发起试产申请
   - 释放试产申请、试产需求、分配表给制造代表

#### 组织TDR3评审（活动209）

1. **协调技术应用指导书评审**
   - 技术负责人组织项目团队输出《技术应用指导书》
   - 和CBB管理代表完成会前评审

2. **收集汇总评审资料**
   - 《技术开发项目测试报告》
   - 《技术应用指导书》
   - 《迁移方案》

3. **确定评审团队**
   - 根据各领域评审主责人表确定评审主席
   - 评委主席确认评委团
   - 团队成员包含：本领域技术专家、CBB管理代表、技术项目经理、技术规划代表、产品代表、关联领域专家
   - 如有迁移计划的项目，需要邀请迁移产品开发核心人员（PPM/SPM、SE/基线开发经理、SPP/影像产品经理、PQA）参与评审

4. **组织评审会议**
   - 拉通评审团队确定评审时间、地点以及评审形式

#### 制定终版迁移方案（活动212）

1. **协调刷新**
   - 技术负责人依据TDR3评审结论刷新技术应用指导书
   - 组织项目团队及CBB管理代表刷新《迁移方案》V1.0

#### TDCP决策支持（活动213）

1. **确定决策层级**
   - 按照《技术体系分层决策机制》确定决策层级

2. **上会准备**
   - 若需上会TMT决策，参照《TMT上会标准指南-V1.2》执行上会流程

### 7.4 技术迁移阶段职责

#### 接收技术迁移触发邮件（活动301）

- 接收产品开发项目（迁移项目PM/SPM/影像PM）发出的技术迁移触发邮件

#### 制定/刷新迁移方案（活动302）

- 依据触发邮件信息制定或刷新迁移方案V1.0
- 包含：迁移团队组建、迁移计划制定、迁移支持内容确定

#### 同频迁移技术成果（活动303）

- 组织技术迁移团队（含产品开发团队成员）和CBB管理代表同频迁移阶段信息
- 信息包含：技术方案、技术目标分解表、遗留问题、项目风险、测试策略、测试计划、测试验收报告、迁移团队表、迁移计划、迁移阶段支持内容等

#### 组织技术项目总结（活动306）

1. **组织项目复盘**
   - 负责组织项目团队及CBB管理代表进行技术开发复盘
   - 召开复盘会议
   - 输出复盘报告（包含开发过程中问题、亮点、不足改善对策等）

2. **协调指导书刷新**
   - 配合技术负责人根据迁移阶段的技术表现刷新技术应用指导书

#### 组织TDR4评审（活动307）

1. **收集汇总评审资料**
   - 《技术项目复盘报告》
   - 《XXX技术项目维护方案》
   - 《产品项目测试报告》
   - 《技术应用指导书》

2. **确定评审团队**
   - 根据各领域评审主责人表确定评审主席
   - 评委主席确认评委团名单
   - 团队成员包含：本领域技术专家、CBB管理代表、技术项目经理、技术规划代表、产品代表、迁移产品开发核心人员（产品线PM/PM/SPM、SE/基线开发经理、SPP/影像产品经理、PQA）、关联领域专家

3. **组织评审会议**
   - 拉通评审团队确定评审时间、地点以及评审形式

#### END-DCP决策支持（活动309）

1. **确定决策层级**
   - 按照《技术体系分层决策机制》确定技术项目结束的决策层级

2. **上会准备**
   - 若需要上会TMT决策，参照《TMT上会标准指南-V1.2》执行上会流程并获得决策结论

#### 刷新技术项目复盘&正式版本归档（活动310）

1. **复盘刷新**
   - 根据END-DCP的内容判断是否需要刷新复盘报告

2. **知识产权成果输出**
   - 对于需要有软著、专利的技术项目输出知识产权成果，并归档

3. **项目资料归档**
   - 对项目资料进行归档
   - 完成技术成果转换

4. **CBB更新通知**
   - 告知CBB管理代表更新CBB清单
   - 根据CBB在迁移项目的应用质量结果来更新CBB选用属性

### 7.5 全程贯穿职责

1. **团队组建与协调**
