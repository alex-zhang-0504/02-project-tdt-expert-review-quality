# TDRX评审事实与年度考评数据规范（按年度）V0.4

> 阶段讨论稿｜2026-08-31｜适用口径：by year
>
> 本文只定义字段、枚举、公式和AI校验。评分规则以[《TDT技术项目TDR评审专家质量考评办法（按年度）V0.4》](tdr-expert-review-quality-assessment-by-year-v0.4.md)（下称《办法》）为准。
>
> V0.4已同步客观分数60分、主观分数40分及简版事实卡口径；主观问卷字段和档位暂时沿用V0.3。

## 1．数据来源与解析入口

| 数据 | 来源 | 用途 |
|---|---|---|
| TDR事实 | 飞书归档文件夹URL、单个飞书电子表格URL或本地Excel文件 | 计算评审过程表现、年度服务贡献和简版事实卡 |
| 专业价值贡献 | 年度三题问卷 | 计算主观分数 |
| 考核报告范围 | 部门人工圈定的归档文件夹或本地报告集合 | 确定本次纳入考核的候选报告 |

TDRX评审表是评审事实的唯一来源。飞书URL和本地Excel进入同一套结构识别、文本归一化、事实提取和计分规则；不得因输入载体不同产生不同结果。正式在线批量入口为一个飞书归档文件夹URL，不提供多个在线文档URL输入框。

每场所需评审人以该场TDRX评审人列表为准；TDR1／TDR2／TDR3名单可以不同。项目评审专家需求表只用于模拟数据准备，不进入正式考评或缺失校验。

### 1.1 飞书归档文件夹批次

1. 一个评分任务对应一个飞书归档文件夹，只枚举直接子项，不递归子文件夹。
2. 电子表格及目标为电子表格的快捷方式均为候选报告；其他类型计入排除资源。归档文件夹第一层应只放正式TDRX报告，系统不得仅凭文件名排除候选报告。
3. 同一工作簿可包含多个阶段Sheet，也可按阶段拆为多个工作簿，最终均按`项目编码＋阶段`聚合。同一目标工作簿重复出现时不重复计分，并阻止正式年度结果。
4. 批次必须返回`发现资源数`、`候选报告数`、`成功报告数`、`失败报告数`、`排除资源数`和`批次是否完整`。
5. 文件夹枚举、候选识别、XLSX导出或工作簿解析任一步失败，批次均为不完整。系统可以展示成功报告的质检结果，但不得生成正式年度结果。

### 1.2 项目信息与Sheet识别

1. 解析器采用三级语义定位：`区块标题 → 区块内字段名／表头 → 字段对应内容`。单元格坐标只保存为证据，不作为字段识别条件；增加或移动行列、调整空白行、扩展会签或问题行均不得改变字段归属。
2. 基础信息区位于“评审结论和会签列表”之前。考核关键字段为“技术项目名和编码”“缺席评审人姓名”和阶段字段；阶段字段名允许“评审阶段”或“项目阶段”，两者表达同一事实并静默归一。“TDR会议日期”和“评审结论”仅作为项目跟踪辅助字段读取，缺失、重复、为空或格式不规范均不阻断考核，默认静默；确需提示时只允许非阻断提醒。解析器读取字段同一行右侧、下一个字段之前的非空内容；合并单元格只读取左上角值；A1及第一区块其他灰色区域不参与任何关键字段识别。
3. “技术项目名和编码”通常为`完整项目名称-项目编码`，以最后一个连接符为边界提取项目编码，前部完整保留为项目名称。项目名称内部允许包含连接符，不强制拆分大TDT名与子任务名。若同一单元格含至少两项数字／字母等明确序号，或含至少两条非空行且每行都能独立解析出合法的项目名称和项目编码，则视为多项目合并评审：该Sheet只生成一次场次事实，仅取第一项解析项目名称和编码，其余项保留在源表但不生成项目或场次记录。无序号多行中任一行不能独立解析出合法项目编码时，不做多项目推断，整格仍按单项目处理。
4. “缺席评审人姓名”按`原评审人姓名（角色）`填写，多人使用`、`分隔；存在代理人时不计缺席，无缺席填写`无`。若误写代理人姓名，且会签区存在唯一的`原评审人（代理人）`映射，则归一到原评审人并保留原文与一条处理记录；无法唯一映射时不猜测。“评审阶段”／“项目阶段”的字段值只允许TDR1／TDR2／TDR3，不接受`+`、`~`等合并阶段写法。
5. 会签区通过“评审结论和会签列表”定位；考核关键表头为“评审人姓名”“会签结果”“评审意见”，“评审角色”是辅助表头。问题区通过“评审问题汇总表”定位；考核关键表头为“评审人”“问题描述”，“序号”“是否要修正”“问题等级”“反馈/修改说明”“问题状态”均是辅助表头。辅助表头或对应内容缺失、重复、为空或格式不规范时继续解析，不得产生阻断；默认静默，确需提示时只允许非阻断提醒。区块标题、表头和数据行均不得绑定固定行列；空白行列不改变数据范围和字段归属。
   - 同一姓名因承担多个角色出现多行时，按姓名归一为一名评审人：角色去重合并，评审意见候选和证据位置取并集，会签只计一次，不触发重复评审人错误。
   - 重复行中只要至少一行具有有效会签，即按已会签统计；多个有效会签结论不同只产生事实冲突提醒，不改变会签得分，也不重复计分。
   - 同一批次内不同评审人姓名符合以下任一条件时，生成一组“疑似同一评审人”待确认项：姓相同且名字逐字拼音相同；或名字逐字拼音相同，姓氏拼音相同或仅存在`n／ng`鼻音差异。常见复姓按完整复姓识别，其他中文姓名默认首字为姓。系统必须按序号逐行列出每个姓名对应的来源文件、Sheet和姓名单元格位置，不自动合并或改写姓名。
   - 用户确认该姓名组均为不同人员后，各姓名继续独立统计，该待确认项在当前分析批次解除阻断并保留确认时间；重新导入或新建批次时重新检查。用户未确认且未修正源报告时，不得进入正式评分或导出维度一结果。
6. 同一业务区块内出现重复的区块标题、考核关键字段或考核关键表头时，系统不得自行选择；考核关键字段名缺失、无法识别或内容为空时，必须指出具体字段和证据位置。项目跟踪辅助字段不参与本项校验。
7. 模板说明行和示例行不得生成场次事实。文件名、Sheet名称及A1只用于展示，不参与阶段识别、核对、项目身份、有效Sheet判断或质检；评审阶段只读取Sheet内部“评审阶段”或“项目阶段”字段。
8. 有效Sheet必须同时满足：项目名称和项目编码合法、评审阶段完整，会签区和问题区及其考核关键表头存在，至少3名不同评审人具有已记录会签结果。已记录值允许Go、Go with Risk、Redirect或`-`；`-`计入3人门槛但会签计0分，空白不计入门槛。
9. 完全不含业务字段和区块的辅助Sheet直接跳过；已出现关键业务区块或多项基础字段但结构不完整的Sheet按模板错误处理，不得静默跳过。隐藏Sheet按同一内容规则正常解析，不要求删除，也不产生提醒。

### 1.3 符号与文本容错

解析时先归一化并保存原文：

- 中文／英文括号：`（ ）`与`( )`；
- 连接符：`-`、`－`、`—`、`–`；
- 名单分隔符：`、`、`，`、`,`、`；`、`;`、`／`、`/`和换行；
- 大小写和多余空格：如`Go`／`GO`，以及连续或前后空格；
- 评审意见去重时，中英文标点按等价形式归一化。

容错不得用于猜测项目、人员、阶段、会签结论或评审意见要素；标识符和枚举值只接受本规范明确允许的形式。

## 2．主键与统计范围

| 对象 | 主键 |
|---|---|
| TDR场次 | `项目编码＋项目阶段` |
| 专家场次事实 | `TDR场次＋专家ID` |
| 专家项目事实 | `本次考核ID＋项目编码＋专家ID` |
| 年度问卷 | `本次考核ID＋技术项目经理ID＋专家ID` |
| 年度专家结果 | `本次考核ID＋专家ID` |

- 本次报告范围由部门在导入前人工圈定，系统不按会议日期自动筛选。
- 只纳入所选报告中已完成TDR3的项目；该项目的TDR1／TDR2事实随项目一并参与计算。
- 同一项目在本次考核中只计1个参与项目或问题贡献项目。
- 专家ID和技术项目经理ID应使用组织身份ID，姓名与角色只用于展示。组织身份映射未提供时，只能按姓名生成试算结果，不得用于跨同名人员去重或生成正式问卷。

## 3．场次事实字段

每场TDR导入后，为当场评审人列表中的每位专家生成一条记录。未出现在当场列表中的人员不生成专家场次事实，也不判定为遗漏。

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 本次考核ID／报告批次 | 是 | 由本次导入任务生成，不从TDRX猜测 |
| 项目编码／项目名称 | 是 | 从“技术项目名和编码”的关联内容提取；项目编码用于去重 |
| 项目阶段 | 是 | 读取“评审阶段”或“项目阶段”，两种字段名等价；字段值只允许TDR1／TDR2／TDR3，Sheet名称不参与识别或校验 |
| 会议日期／会议评审结论 | 否 | 仅作项目跟踪和展示，不参与场次主键或专家计分 |
| 专家ID／姓名／专业角色 | 姓名必填 | 姓名来自当场评审人列表；专业角色仅展示；专家ID由组织身份映射提供 |
| 缺席名单原文／归一名单 | 否 | 读取“缺席评审人姓名”；误写代理人时仅按唯一代理关系归一 |
| 出勤判定／得分 | 是 | 按§3.1计算，0或15分 |
| 会签结果原文／标准值／得分 | 是 | 按§3.2计算，0或25分 |
| 评审意见候选集／原文 | 否 | 会签区“评审意见”与问题区可归属的“问题描述”取并集后去重；保留全部来源位置和原文 |
| 意见判定事实 | 条件产生 | 0分排除原因、技术对象、专业动作、具体细节及其证据片段 |
| 评审意见档位／得分 | 是 | 具体10／一般6／无意见0 |
| 评审意见证据位置 | 是 | Sheet名称、全部来源单元格坐标及原文 |
| 问题提出人／描述 | 否 | 来自问题区；提出人可归属且描述非空时用于问题贡献项目统计 |
| 问题编号／是否修正／问题等级／反馈说明／状态 | 否 | 项目跟踪辅助字段，不参与专家计分或质检设卡 |
| 场次过程表现分 | 是 | 0—50分 |
| 来源文件 | 是 | 用于追溯 |

### 3.1 出勤表现

| 归一缺席名单 | 唯一代理关系 | 个人会签 | 出勤分 |
|---|---|---|---:|
| 未命中 | 无 | Go／Go with Risk／Redirect | 15 |
| 命中 | 无 | `-`或空白 | 0 |
| 未命中 | 无 | `-`或空白 | 15 |
| 命中 | 无 | Go／Go with Risk／Redirect | 15，并生成事实冲突提醒 |
| 任意 | 有 | 任意已记录值 | 15；记录仍归原评审人 |

当前模板不记录“部分参加”，不生成10分中档。缺席名单误写代理人时，先按唯一的`原评审人（代理人）`关系归一；无法关联的姓名保留原文并提醒，不得猜测。

### 3.2 结果会签

```text
Go／Go with Risk／Redirect：25分
“-”、空白或无法归一为以上三个标准值：0分
```

三种标准结论同分。会签结论与评审意见独立计分。当前模板不记录会签时间，因此不设置逾期中档。

### 3.3 评审意见

候选集按以下顺序构建：

1. 读取会签区中该专家的“评审意见”；同一单元格中的不同意见按换行或明确序号拆分。
2. 读取问题区的“问题描述”。标准填写为一行一个问题；若同一单元格使用至少两项明确序号，则拆为多条问题事实，继承原行其他字段，证据记为`原单元格-第N项`。明确序号兼容阿拉伯数字、英文字母或中文数字加点号、顿号、右括号或冒号，如`1.`、`1、`、`a.`、`a、`、`（1）`、`（a）`、`一、`、`①`；大小写、全角半角视为相同语义。只有逗号、分号等标点而无至少两项明确序号时，不拆分、不提醒，按一条问题保留。
3. “评审人”先按名单分隔符拆分，再按代理关系归一，最后与同一Sheet会签区的原评审人名单取交集。仅将交集人员关联到该问题；名单外人员保留为项目问题提出人，不报错、不进入专家考核。
4. 将两类来源文本取并集；归一化序号、空格、换行和中英文标点后内容相同的记录只保留一条评分事实，同时保留全部来源位置和原文。
5. 任一来源为空时继续使用另一来源；两处均无可归属文本时评审意见计0分。多个不同候选分别执行0分排除和三要素提取，以其中分值最高、证据最完整的一条确定意见档位，不得把不同候选中的要素拼接成一条高档意见。

先对每条候选执行0分排除，只允许以下三类原因：

| 0分排除原因 | 判定条件 |
|---|---|
| 未给意见 | 空白，或只写`-`、Go、同意、无意见、没问题等结论或态度 |
| 只引用他人意见 | 只写“与某人相同”“参考某人／某条意见”等，未补充本人判断、问题、风险或建议 |
| 只有泛化提醒 | 只写注意、风险、KPI、市场、价格、竞品、用户场景、技术可行性等宽泛提醒，没有具体对象、判断、问题、影响、条件或建议 |

引用文本和本人补充内容同时存在时，只对本人补充内容判分。不得仅因出现“注意”“风险”“KPI”“价格”等词就判0分；包含数值、条件、变化、影响或具体建议时应继续判定为实质意见。

未触发0分排除的候选为实质意见，继续提取以下事实：

| 提取事实 | 判定为“是”的最低条件 |
|---|---|
| 有技术对象 | 能定位模块、方案、接口、参数、指标、场景、数据、证据或其他具体评审对象 |
| 有专业动作 | 能识别判断、质疑、风险提示、问题指出、建议、验证要求或补证要求 |
| 有具体细节 | 能识别依据、现象、条件、场景、影响、因果、证据缺口、建议动作或验证关注点中的至少一项 |

```text
未触发0分排除 且 有技术对象 且 有专业动作 且 有具体细节：具体意见，10分
未触发0分排除 且 三要素未全部识别：一般意见，6分
触发任一0分排除原因：无意见，0分
```

- 只引用他人意见不得复制或继承被引用意见的事实与分数。
- 不使用字数、意见数量、角色或专业深度作为直接判据。
- 质量、测试等角色可用测试场景、现象、影响、证据缺口或验证建议构成具体细节，不要求写底层技术机理。
- AI无法确认对象、动作或细节时不得补全；只要未触发0分排除，即判一般意见。
- 每次判定必须保存规则版本、0分排除原因、三要素、证据片段和原始单元格位置，支持人工复核。

### 3.4 场次过程表现分

```text
场次过程表现分＝出勤表现＋结果会签＋评审意见
```

范围为0—50分。

### 3.5 评审意见样本池

系统在每次成功解析后，将有文本的评审意见判定写入本地样本池`var/review-opinion-samples/opinion-samples.jsonl`。样本至少保存来源文件、Sheet、项目编码、阶段、评审人、原文与位置、AI分数、判定理由、0分排除原因、三要素、规则版本和人工复核状态；相同来源和内容重复导入时不得重复追加。

样本池包含真实姓名和内部技术内容，`var/`必须被Git忽略，不得提交到远端。样本用于后续人工复核和规则迭代，不自动改变线上判分；规则调整仍须先更新《办法》和本规范，并通过回归测试后生效。

## 4．年度事实卡字段

年度事实卡按专家生成，主视图只保留直接参与计分或影响正式出分的字段。

| 字段 | 计算方式 |
|---|---|
| 专家ID／姓名／专业角色 | 当场TDRX评审人列表和组织身份映射 |
| 本次考核批次 | 部门人工圈定并由系统成功读取的正式报告集合 |
| 评审过程表现 | 0—50分；展示年度分和逐项目分 |
| 评审参与度 | 有效参评项目数、项目编码清单、0／3／6分 |
| 问题贡献度 | 问题贡献项目数、项目／问题编号清单、0／2／4分 |
| 年度代理事实 | 年度应参评场次数、被代理次数、代理率；不参与计分 |
| 客观分数 | 评审过程表现＋评审参与度＋问题贡献度，0—60分 |
| 阻断性异常 | 会导致无法正式出分的缺失或冲突 |

逐场出勤、会签、评审意见0分排除原因、三要素、原文和单元格位置放入展开明细。事实卡只展示事实，不输出问卷推荐档位。

`年度应参评场次数＝直接参评场次＋被代理场次`，`代理率＝被代理次数÷年度应参评场次数`。“被代理”以会签区的`原评审人（代理人）`记录为准。系统不设置代理率阈值，不自动评价或扣分。

## 6．派生字段与公式

### 6.1 过程表现

```text
专家项目过程分
＝该专家在该项目各有效TDR场次过程表现分之和
 ÷该项目有效TDR场次数

年度过程表现分
＝各专家项目过程分之和÷本次纳入项目数
```

### 6.2 专业价值贡献

```text
年度专业价值贡献分
＝Σ（技术项目经理问卷分×共同项目数）÷本次纳入项目数
```

每个项目只能对应一位技术项目经理问卷权重。项目经理归属与变更规则确认前，不得自行选择问卷或生成正式主观分数。

### 6.3 客观分数与年度总分

```text
有效参评项目：
  三场项目＝专家实际参加TDR1且实际参加TDR3
  一场或两场项目＝项目记录包含TDR3且专家实际参加TDR3

问题贡献项目：
  同一Sheet中，问题区“评审人”与会签区原评审人名单取交集后才可归属
  专家在问题区至少有1条可归属的有效问题＝1个项目
  同一项目多条问题仍只计1个项目

单项排名分：
  项目数≤2＝0分，不进入排序
  项目数＞2时，按两个不同的项目数量档从高到低映射
  评审参与度＝6／3／0分；问题贡献度＝4／2／0分
  相同项目数得分相同

年度服务贡献分＝评审参与度分＋问题贡献度分
客观分数＝年度过程表现分＋年度服务贡献分
年度总分＝客观分数＋年度专业价值贡献分
```

例：项目数为8、8、6、5、2时，评审参与度依次计6、6、3、0、0分，问题贡献度依次计4、4、2、0、0分。两个子项独立排序、独立计分。

可归属的有效问题必须同时满足：提出人命中同一Sheet会签区原评审人名单，问题描述非空，所在项目属于本次报告批次且已完成TDR3。名单外人员的问题保留为项目事实，不报错、不计入专家考核；问题提出人或描述缺失时该行不归属专家、不计入问题贡献，并生成非阻断提醒。问题编号、是否修正、问题等级、反馈说明和问题状态不参与归属、计分或质检设卡。

### 6.4 等级

等级必须在同一年度批次全体专家的维度一客观分数和维度二主观分数均完成、全部生成年度总分后统一计算。任一专家的任一维度未完成时，已经生成年度总分的专家等级写为`待排名`，尚未生成年度总分的专家等级为空。

```text
N＝本批次全部专家人数
边界人数＝ceil（N×15％）
按年度总分从高到低排序
年度总分＝100：S
排名前“边界人数”：A，其中满分人员仍显示S
排名后“边界人数”：C
其余：B
```

S保留其排名位置并占用A档的前15％名额。等级边界遇到同分时不得拆分，同分人员进入同一等级，因此A或C的实际人数可以超过边界人数。若上下边界分数相同，除S外统一记为B。年度V0.4不设置D级。

参与项目数或问题贡献项目数小于3，只使对应服务贡献子项计0，不影响其他分数。

## 7．自动校验

### 7.1 单份报告检查节点与进度

批量导入时，每一份候选TDRX评审报告独立执行以下10个检查节点。进度只能在后端完成对应真实检查后推进，不得使用固定延时、前端动画或结果回放模拟检查过程。每个完成节点记录实际耗时；单份报告进度＝已完成节点数÷10。某节点失败时，该报告停留在失败节点并保留已完成节点、失败原因和证据位置。

| 顺序 | 检查节点 | 实际检查内容 |
|---|---|---|
| 1 | 获取报告 | 飞书文件夹候选识别与去重，或本地文件名、扩展名、非空和30MB上限检查 |
| 2 | 获取XLSX | 在线报告完成整册XLSX导出；本地报告完成XLSX压缩结构校验 |
| 3 | 解析工作簿 | 打开Excel工作簿，读取可见与隐藏Sheet清单，排除示例和空白占位Sheet |
| 4 | 检查模板结构 | 按区块标题、字段名和表头动态定位基础信息区、会签区和问题区；检查缺失、重复及区块顺序 |
| 5 | 检查场次身份 | 从Sheet内部“评审阶段”或“项目阶段”字段提取并归一评审阶段，同时提取完整项目名称和末尾项目编码；会议日期、会议评审结论、文件名和Sheet名称不参与考核校验 |
| 6 | 检查评审名单 | 检查至少3名不同评审人具有`Go／Go with Risk／Redirect／-`之一的已记录会签结果 |
| 7 | 检查出勤与会签 | 归一缺席名单、`原评审人（代理人）`和会签结果，执行出勤及会签计分事实校验 |
| 8 | 检查意见与问题 | 合并评审意见和问题描述并去重；拆分带明确序号的多问题；问题提出人与同一Sheet评审人名单取交集；仅检查影响归属的提出人和问题描述 |
| 9 | 检查场次唯一性 | 按`项目编码＋评审阶段`检查同册及跨报告重复，不重复计分 |
| 10 | 检查评分边界 | 生成报告内专家过程分，检查场次、项目、年度服务贡献及客观分数的数量一致性和分值上限 |

文件夹枚举是批次级前置步骤。只有文件夹第一层全部分页完成后，才能确认候选报告全集并建立报告进度列表；任一候选报告失败仍按本节下表阻断完整年度结果。界面不展开陈列全部检查节点，只逐份显示报告名称、当前检查节点、真实完成百分比和最终状态；检查完成后再按报告查看错误、提醒和证据。

| 条件 | 级别 | 处理 |
|---|---|---|
| 飞书文件夹无法完整枚举，或候选报告无法识别、导出、打开或解析 | 阻断 | 保留批次与报告失败信息，不使用不完整批次生成正式年度结果 |
| 同一目标工作簿重复出现 | 阻断 | 不重复计分，列出重复资源 |
| 文件夹第一层存在非电子表格资源 | 排除 | 计入排除资源数，不解析、不递归 |
| 项目没有TDR3 | 排除 | 不纳入本次考核，不产生服务贡献项目数 |
| 标准区块、考核关键字段或关键表头缺失／重复，或关键字段内容为空 | 阻断 | 指出具体名称和证据位置，不按绝对坐标猜测；辅助字段不适用本项 |
| 项目名称、项目编码或阶段无法有效提取 | 阻断 | 不生成该场正式结果 |
| “技术项目名和编码”含至少两项明确序号，或至少两条可独立解析的同结构项目行 | 后台容错 | 只取第一项作为项目归属，整张Sheet只生成一次场次，不在质检界面展示 |
| 隐藏Sheet满足有效Sheet条件 | 正常 | 正常解析，无需删除，不产生提醒 |
| 已记录会签结果的不同评审人不足3名 | 阻断 | 不解析该Sheet，不得按辅助Sheet静默跳过 |
| “评审阶段”／“项目阶段”的字段值不是TDR1／TDR2／TDR3 | 阻断 | 不做合并阶段容错，要求修改为一个标准阶段 |
| 各阶段评审人名单不同 | 正常 | 按各场实际名单处理 |
| 同一评审人因多个角色出现多行且有效会签一致 | 后台容错 | 合并角色、意见和证据，只保留一名评审人及一次会签，不在质检界面展示 |
| 同一评审人的重复行存在不同有效会签结论 | 提醒 | 合并为一名评审人并只计一次；因各有效结论得分相同，继续计分并要求核实源表 |
| 不同评审人姓名的名字逐字拼音相同，且姓相同、同音或仅存在`n／ng`鼻音差异 | 待确认 | 按姓名组和序号逐行列出全部“来源文件／Sheet／姓名单元格”；不自动合并。用户修改源报告后重新读取，或确认均为不同人员后按独立人员继续当前批次 |
| 缺席名单误写代理人且存在唯一代理映射 | 后台容错 | 归一到原评审人，并与代理履职事实合并；不在质检界面展示 |
| 缺席名单姓名无法关联原评审人或唯一代理映射 | 提醒 | 保留原文，不猜测人员 |
| 缺席名单命中原评审人，但存在有效会签 | 提醒 | 明确告知按出席统计；出勤计15分、会签计25分，并要求核实缺席名单 |
| 会签为`-` | 正常 | 视为已记录但未给结果，会签计0分；计入有效Sheet的3人门槛，不产生提醒 |
| 会签为空或无法识别 | 提醒 | 会签计0分；不计入有效Sheet的3人门槛 |
| 问题行只有预填序号，其余字段均为空 | 跳过 | 视为空白占位行 |
| 一格问题描述含至少两项明确序号 | 后台容错 | 自动拆分并继承原行字段，证据增加“第N项”；不在质检界面展示 |
| 一格问题描述无至少两项明确序号 | 正常 | 不依据逗号、分号等标点猜测多项，按一条问题保留 |
| 会议日期、会议评审结论、评审角色或问题跟踪辅助字段缺失／重复／为空／格式不规范 | 正常 | 尽量读取并保留原文；不阻断、不影响专家计分，默认静默，确需提示时仅给非阻断提醒 |
| 问题提出人或问题描述缺失 | 提醒 | 该问题行不归属专家、不计入问题贡献；其他专家考核事实继续评分 |
| 问题提出人未命中同一Sheet会签区原评审人名单 | 正常 | 保留为项目问题事实，不归属专家、不计入考核 |
| 评审意见为空 | 正常 | 计0分，不作为数据缺失 |
| 意见判定无法提供原文证据 | 降档 | 只按可确认要素判定，不得补全 |
| 两类来源的意见归一化后相同 | 合并 | 只计一次，保留全部来源位置 |
| 同一场次、同一专家重复 | 阻断 | 不重复计分 |
| 有效参评／问题贡献项目数与清单去重数不一致 | 阻断 | 不计算客观分数 |
| 客观分数、主观分数或年度总分超出各自上限 | 阻断 | 不生成正式结果，检查计分公式或来源数据 |
| 批次仍有专家的客观分数或主观分数未完成 | 待处理 | 已生成年度总分的人员显示`待排名`，不得提前输出A／B／C |

## 8．结果状态与输出

| 状态 | 条件 |
|---|---|
| 事实待补全 | TDRX存在阻断性缺失／异常，或飞书归档批次不完整 |
| 待问卷 | 事实完整，但仍有必填问卷未提交 |
| 已完成 | 事实与问卷完整，已生成年度结果 |

正式保存的“已完成”结果至少包含：客观分数及三项构成、主观分数、年度总分、等级、两类服务贡献项目清单、逐场证据、来源文件、问卷版本和计算时间。

## 9．AI处理边界

AI可以读取TDRX、归一化允许的文本形式、提取事实与证据、执行客观分数固定规则、生成事实卡、检查遗漏、换算人工问卷和执行公式。

AI不得把会签结论当成意见质量，不得按字数或角色直接定档，不得补写对象、动作或细节，不得预选问卷档位或替代技术项目经理作答，也不得跳过缺失校验直接生成正式分数。
