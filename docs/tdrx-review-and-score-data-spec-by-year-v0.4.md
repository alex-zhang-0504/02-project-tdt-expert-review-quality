# TDRX评审事实与年度考评数据规范（按年度）V0.4

> 阶段讨论稿｜2026-08-28｜适用口径：by year
>
> 本文只定义字段、枚举、公式和AI校验。评分规则以[《TDT技术项目TDR评审专家质量考评办法（按年度）V0.4》](tdr-expert-review-quality-assessment-by-year-v0.4.md)（下称《办法》）为准。
>
> V0.4已同步客观分数61分、主观分数40分及简版事实卡口径；主观问卷字段和档位暂时沿用V0.3。

## 1．数据来源与解析入口

| 数据 | 来源 | 用途 |
|---|---|---|
| TDR事实 | 飞书归档文件夹URL、单个飞书电子表格URL或本地Excel文件 | 计算评审过程表现、年度服务贡献和简版事实卡 |
| 专业价值贡献 | 年度三题问卷 | 计算主观分数 |
| 数据冻结时间 | 本次考核配置 | 确定前开后闭的项目统计窗口 |

TDRX评审表仍是评审事实的唯一来源。飞书URL和下载后的Excel进入同一套结构识别、文本归一化、事实提取和计分规则；不得因为输入载体不同产生不同结果。正式在线批量入口为一个飞书归档文件夹URL，不提供多个在线文档URL输入框。

每场所需评审人以该场TDRX评审人列表为准；TDR1／TDR2／TDR3名单可以不同，均视为项目实际需求。项目评审专家需求表只用于模拟数据准备，不进入正式考评或缺失校验。

年度事实卡和年度结果均由系统生成，不要求人工维护独立打分表。

### 1.1 飞书归档文件夹批次

1. 一个评分任务对应一个飞书归档文件夹；第一版只枚举该文件夹的直接子项，不递归子文件夹。
2. 直接子项中的电子表格，以及目标类型为电子表格的快捷方式，均视为候选报告；其他类型记录为已排除资源。
3. 如果快捷方式响应未提供目标信息，系统可以从其访问URL解析电子表格目标；两种方式都无法确认时，该资源记为候选失败，不得静默排除。
4. 归档文件夹第一层只允许放正式TDRX报告。系统不以文件名是否包含“TDRX”作为排除条件，避免把名称不统一的正式报告漏掉。
5. 同一工作簿可以包含TDR1／TDR2／TDR3多个有效Sheet；不同阶段也可以拆成多个独立工作簿。两种形式最终都按`项目编码＋阶段`聚合。
6. 同一目标工作簿被多个快捷方式或文件条目重复引用时，视为批次异常，不重复计分并阻止正式年度结果。
7. 系统必须返回批次清单与统计：`发现资源数`、`候选报告数`、`成功报告数`、`失败报告数`、`排除资源数`、`批次是否完整`。
8. 文件夹枚举、分页、快捷方式解析、XLSX导出或工作簿解析任一步失败，`批次是否完整＝否`；允许展示已成功报告的质检结果，但禁止生成完整年度结果。

### 1.2 项目信息与Sheet识别

1. 除当前模板明确固定的项目信息单元格外，按区块标题和字段名称定位数据，不硬编码绝对行号；合并单元格读取其左上角值，其余空白格不判为字段缺失。
2. 当前模板第一区块的 `B3:C3` 为合并单元格，左上角 `B3` 是项目名称与项目编码的唯一识别来源。填写格式为 `技术项目名-项目编码`，项目编码必须置于末尾；项目名称本身可以包含连接符，解析时从末尾识别项目编码，前部完整保留为项目名称。
3. 当前模板 `B4:C4` 为缺席人员填写区。按 `姓名（角色）` 填写，多人使用 `、` 分隔；改派参会不计缺席，无缺席填写 `无`。
4. 当前模板 `B5:C5` 为会议日期填写区，使用 `YYYY/MM/DD`，不得改变日期格式。
5. 第一区块其他灰色填写区域不参与项目名称和项目编码识别，其内容及书写格式不作为项目身份校验条件。
6. `TDR1+TDR2`不再作为有效阶段；合并评审按TDR2记录。
7. 模板说明行和书写示例行不得生成专家场次事实。
8. 有效Sheet必须同时满足：`B3`项目名称和项目编码合法、阶段完整、会签与问题区块存在、至少3名不同评审人具有已记录会签结果。
9. 已记录会签结果允许为Go、Go with Risk、Redirect或`-`。`-`表示技术项目经理已记录“评审人未给会签结果”，计入有效Sheet的3人门槛，但该专家结果会签计0分；空白不计入3人门槛。
10. 无日期、会议结论、评审意见、问题或已记录会签结果的空白占位Sheet直接跳过；存在上述正式评审事实但不足3名有效评审人的Sheet报错并阻止正式年度结果，不得静默跳过。

### 1.3 符号与文本容错

以下形式表达相同意图，解析时先归一化、保存原文，再进入规则判断：

- 中文／英文括号：`（ ）`与`( )`；
- 连接符：`-`、`－`、`—`、`–`；
- 名单分隔符：`、`、`，`、`,`、`；`、`;`、`／`、`/`和换行；
- 大小写和多余空格：如`Go`／`GO`、`Go with Risk`中连续或前后空格；
- 中文／英文冒号、问号和感叹号不改变语义分类。

容错只用于识别同一意图，不得把无法确定的内容猜成项目、人员、阶段、会签结论或评审意见要素。

## 2．主键与统计窗口

| 对象 | 主键 |
|---|---|
| TDR场次 | `项目编码＋项目阶段＋会议日期` |
| 专家场次事实 | `TDR场次＋专家ID` |
| 专家项目事实 | `本次考核ID＋项目编码＋专家ID` |
| 年度问卷 | `本次考核ID＋技术项目经理ID＋专家ID` |
| 年度专家结果 | `本次考核ID＋专家ID` |

规则：

- 本次窗口为“上一次考核数据冻结时间之后，至本次考核数据冻结时间”，即`上次冻结时间＜TDR3日期≤本次冻结时间`。
- 只纳入窗口内已完成TDR3的项目；该项目的TDR1／TDR2事实随项目一并参与计算。
- 同一项目在本次考核中只计1个参与项目或问题贡献项目。
- 专家ID优先使用组织身份ID；姓名和专业角色只用于展示，不作为唯一主键。

## 3．场次事实字段

每场TDR导入后，为当场评审人列表中的每位专家生成一条记录。未出现在当场列表中的专家不生成记录，也不判定为遗漏。

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 本次考核ID／数据窗口 | 是 | 由考核配置提供，不从TDRX猜测 |
| 项目编码／项目名称 | 是 | 从当前模板 `B3` 提取，格式为 `技术项目名-项目编码`；项目编码用于去重 |
| 项目阶段／会议日期 | 是 | 项目阶段只允许`TDR1｜TDR2｜TDR3`；会议日期读取当前模板 `B5`，填写格式为`YYYY/MM/DD` |
| 技术项目经理ID／姓名 | 系统上下文必填 | 当前TDRX模板不含此字段，不得从表内猜测；由年度操作人上下文归属问卷 |
| 专家ID／姓名／专业角色 | 姓名与角色必填 | 姓名与角色来自当场评审人列表；专家ID属于后续组织身份补充，不从TDRX猜测 |
| 缺席评审人姓名列表 | 否 | 读取当前模板 `B4`；格式为`姓名（角色）`，多人用`、`分隔；空白或“无”均按无人缺席处理，改派参会不计缺席 |
| 是否缺席 | 是 | 专家姓名命中缺席名单＝是，否则＝否 |
| 会签结果原文／标准值 | 否 | 标准值为Go／Go with Risk／Redirect；`-`保留为“已记录但评审人未给结果”的原文状态，空白或无法识别时标准值为空 |
| 评审意见候选集／原文 | 否 | 区块2对应专家行D列评审意见，与问题汇总表C列中可归属该专家的问题描述取并集后去重；允许为空 |
| 技术对象 | 条件产生 | AI从去重后的评审意见候选集提取，并保留原文证据 |
| 专业动作 | 条件产生 | 判断／质疑／风险／问题／建议／验证要求等 |
| 具体细节 | 条件产生 | 依据、现象、条件、场景、影响、因果、证据缺口、建议动作或验证关注点 |
| 评审意见档位／得分 | 是 | 具体25／一般15／无意见0 |
| 评审意见证据位置 | 是 | Sheet名称、D列／C列全部来源单元格坐标及原文 |
| 问题提出人／编号／描述 | 否 | 来自问题汇总表；问题提出人与区块2评审人姓名名单取交集后归属，用于问题贡献项目统计及主观评价回溯 |
| 场次过程表现分 | 是 | 0—55 |
| 来源文件／来源版本 | 是 | 用于追溯 |
| 导入时间 | 是 | 系统时间 |

### 3.1 出勤表现

```text
专家姓名命中“缺席评审人姓名”列表：0分
专家姓名未命中：15分
```

当前模板不记录“部分参加”，因此不生成10分中档。缺席名单中的姓名若无法关联当场评审人，应保留原文并生成异常提醒，不得猜测对应人员。

### 3.2 结果会签

```text
标准值为Go／Go with Risk／Redirect：15分
原文为“-”、空白或无法归一化为三个标准值：0分
```

三种结论同分。会签结论不决定评审意见档位；评审意见也不反向改变会签得分。当前模板不记录会签时间，因此不设置逾期中档。

### 3.3 评审意见

系统先按以下顺序构建每位专家的评审意见候选集：

1. 读取区块2中该专家对应行D列的评审意见；同一单元格中的不同意见按换行及`1．`、`2．`等序号拆分。
2. 读取问题汇总表C列的问题描述；一行只生成一条问题事实。B列问题评审人按名单分隔符拆分后，与区块2评审人姓名名单取交集，只将交集中的姓名关联到该问题。
3. 将该专家从D列和C列获得的文本取并集；归一化序号、首尾空格和标点形式后内容相同的记录只保留一条评分事实，但保存全部来源单元格坐标和原文。
4. 任一来源为空时继续使用另一来源；两处均无可归属文本时评审意见计0分。

AI再从去重后的候选集提取三个布尔事实，并执行固定映射：

| 提取事实 | 判定为“是”的最低条件 |
|---|---|
| 有技术对象 | 能定位模块、方案、接口、参数、指标、场景、数据、证据或其他具体评审对象 |
| 有专业动作 | 能识别判断、质疑、风险提示、问题指出、建议、验证要求或补证要求 |
| 有具体细节 | 能识别依据、现象、条件、场景、影响、因果、证据缺口、建议动作或验证关注点中的至少一项 |

```text
有技术对象 且 有专业动作 且 有具体细节：具体意见，25分
有技术对象 且 有专业动作 且 无具体细节：一般意见，15分
其他情况：无意见，0分
```

补充约束：

- 空白，以及只写Go、同意、无意见、没问题等会签结论或态度，均为0分。
- 不使用字数、意见数量、角色或专业深度作为直接判据。
- 质量、测试等角色可用测试场景、现象、影响、证据缺口或验证建议构成具体细节，不要求写底层技术机理。
- AI无法确认对象或动作时不得补全；对象和动作明确但细节存疑时只判一般意见。
- 每次判定必须保存三个提取结果、证据片段和原始单元格位置，支持人工复核。
- 同一内容同时出现在D列和C列时只判定一次；不得因重复填写提高档位或增加得分。

### 3.4 场次过程表现分

```text
场次过程表现分＝出勤表现＋结果会签＋评审意见
```

取值由三个子项组合产生，范围为0—55分。

## 4．年度事实卡字段

年度事实卡按专家生成，供技术项目经理作答前查看。主视图只保留直接参与计分或影响正式出分的字段。

| 字段 | 计算方式 |
|---|---|
| 专家ID／姓名／专业角色 | 当场TDRX评审人列表；组织身份仅用于补充专家ID |
| 本次考核窗口 | 上次数据冻结时间之后至本次数据冻结时间 |
| 评审过程表现 | 0—55分；主视图展示年度分和逐项目分 |
| 评审参与度 | 有效参评项目数、项目编码清单、0—3分 |
| 问题贡献度 | 问题贡献项目数、项目／问题编号清单、0—3分 |
| 客观分数 | 评审过程表现＋评审参与度＋问题贡献度，0—61分 |
| 阻断性异常 | 仅展示会导致无法正式出分的缺失或冲突 |

逐场出勤、会签、评审意见三要素、原文和单元格位置放入展开明细，不占用主视图。事实卡不展示年度TDR场次数、合作技术项目经理数、上／下半年项目数和open／closed汇总；这些字段不直接参与本版计分。事实卡只展示事实，不输出问卷推荐档位。

## 5．年度问卷字段

> 问卷档位与分值沿用V0.3，待主观分数专项讨论后再更新。

每个有效“技术项目经理—专家”合作关系只生成1份问卷。

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 本次考核ID／数据窗口 | 是 | 与客观分数使用同一冻结窗口 |
| 技术项目经理ID／姓名 | 是 | 问卷作答人 |
| 专家ID／姓名 | 是 | 被评价专家 |
| 共同项目清单 | 是 | 项目编码去重 |
| 共同项目数 | 是 | 年度贡献分的权重 |
| 履职与协作档位／得分 | 是 | 10／6／0 |
| 专业判断与指导档位／得分 | 是 | 20／14／0 |
| 专业判断0分原因 | 条件必填 | 原因标签＋100字以内说明 |
| 突出贡献档位／得分 | 是 | 10／0 |
| 突出贡献原因 | 条件必填 | 10分时填写，100字以内并关联项目或问题编号 |
| 提交时间 | 是 | 系统时间 |

```text
技术项目经理问卷分＝履职与协作＋专业判断与指导＋突出贡献
```

AI不得预填三个档位。

## 6．派生字段与公式

### 6.1 过程表现

```text
专家项目过程分
＝该专家在该项目各有效TDR场次过程表现分之和
 ÷该项目有效TDR场次数

年度过程表现分
＝各专家项目过程分之和÷本次纳入项目数
```

### 6.2 专业价值贡献

```text
年度专业价值贡献分
＝Σ（技术项目经理问卷分×共同项目数）÷本次纳入项目数
```

每个项目只能对应一位技术项目经理问卷权重。项目经理发生变更时，按该项目年度最后一次有效TDR记录中的技术项目经理归属。

### 6.3 客观分数与年度总分

```text
有效参评项目：
  三场项目＝专家实际参加TDR1且实际参加TDR3
  一场或两场项目＝项目记录包含TDR3且专家实际参加TDR3

问题贡献项目：
  专家在问题汇总表中至少有1条可归属的有效问题＝1个项目
  问题评审人姓名与同一Sheet区块2评审人名单取交集后才可归属
  同一项目多条问题仍只计1个项目

单项排名分：
  项目数≤2＝0分，不进入排序
  项目数＞2时，按三个不同的项目数量档从高到低映射3／2／1分
  其余＝0分；相同项目数得分相同

年度服务贡献分＝评审参与度分＋问题贡献度分
客观分数＝年度过程表现分＋年度服务贡献分
年度总分＝min（100，客观分数＋年度专业价值贡献分）
```

例：某子项项目数为8、8、6、5、2，分别计3、3、2、1、0分。两个子项独立排序、独立计分。

“可归属的有效问题”至少要求问题提出人命中同一Sheet区块2评审人名单、问题编号和问题描述非空，且所在项目已进入本次考核窗口。相关必填校验未通过时，正式年度结果保持“事实待补全”，系统不得猜测归属。

### 6.4 等级

| 等级 | 条件 |
|---|---|
| S | 年度总分＝100 |
| A | 90≤年度总分＜100 |
| B | 75≤年度总分＜90 |
| C | 60≤年度总分＜75 |
| D | 年度总分＜60 |

参与项目数或问题贡献项目数小于3只使相应服务贡献子项计0，不影响其他分数。

## 7．自动校验

| 校验 | 处理 |
|---|---|
| 飞书文件夹无法完整枚举或分页 | 整个批次读取失败，不使用已返回的部分清单生成结果 |
| 候选报告快捷方式无法解析、XLSX导出失败或工作簿解析失败 | 保留该报告失败卡；批次标为不完整并阻止正式年度结果 |
| 同一飞书工作簿在归档文件夹中重复出现 | 不重复计分，标记批次异常并阻止正式年度结果 |
| 归档文件夹第一层存在非电子表格资源 | 明确计入排除资源数，不递归、不解析 |
| 飞书URL与下载Excel的关键字段或评分结果不一致 | 阻止生成正式年度结果，并输出差异位置 |
| 上次或本次数据冻结时间缺失，或本次时间早于上次时间 | 允许解析试算，但阻止生成正式年度结果 |
| 项目没有TDR3，或TDR3日期不在本次窗口 | 不纳入本次考核，不产生服务贡献项目数 |
| `B3`无法提取项目名称或项目编码，或TDR阶段缺失 | 阻止生成该场正式结果 |
| 正式TDR Sheet中具有已记录会签结果的不同评审人不足3名 | 阻止解析该Sheet并生成错误；不得按无用Sheet静默跳过 |
| 阶段为`TDR1+TDR2` | 兼容读取为TDR2并生成提醒，要求后续把源表改为TDR2 |
| TDR1／TDR2／TDR3评审人名单不同 | 视为项目实际需求，不报异常 |
| 缺席名单姓名无法关联当场评审人 | 生成异常提醒，不猜测对应人员 |
| 列表内专家会签为`-` | 视为技术项目经理已记录“评审人未给结果”；评审记录有效，会签计0并进入提醒清单 |
| 列表内专家会签为空或无法识别 | 会签计0，并进入缺失／异常清单；空白和无法识别值不计入有效Sheet的3人门槛 |
| 评审意见为空 | 正常计0，不作为数据缺失 |
| 评审意见AI提取结果无法提供原文证据 | 不得判为具体意见；按可确认要素降档 |
| 问题汇总表评审人姓名未命中区块2评审人名单 | 不归属任何专家，不进入意见候选集或问题贡献统计；保留原文并生成异常提醒 |
| D列与C列归一化后为同一条内容 | 合并为一条评分事实，保留全部来源位置，不重复计分 |
| 项目编码或评审人姓名缺失 | 阻止生成正式年度结果 |
| 技术项目经理上下文或专家组织身份未补充 | 不阻断TDRX解析与客观分数试算；正式年度问卷和身份去重前必须补齐 |
| 同一场次、同一专家重复 | 阻止重复计分 |
| 同一技术项目经理—专家重复提交问卷 | 只保留当前有效版本并记录审计历史 |
| 非合作技术项目经理提交问卷 | 拒绝提交 |
| 应填问卷未完成 | 年度结果保持“待问卷” |
| ②选0分但缺原因 | 拒绝提交 |
| ③选10分但缺原因或事实无法定位 | 拒绝提交 |
| 有效参评／问题贡献项目数与清单去重数不一致 | 阻止计算客观分数 |
| 客观分数＋主观分数超过100 | 强制封顶为100并保留未封顶原始分 |

## 8．结果状态与输出

| 状态 | 条件 |
|---|---|
| 事实待补全 | TDRX存在阻断性缺失／异常，或飞书归档批次不完整 |
| 待问卷 | 事实完整，但仍有必填问卷未提交 |
| 已完成 | 事实与问卷完整，已生成年度结果 |

“已完成”结果至少保存：

- 评审过程表现分、评审参与度分、问题贡献度分和客观分数；
- 主观分数、年度总分和等级；
- 有效参评项目数与问题贡献项目数及对应项目清单；
- 展开明细中的逐场三子项得分、意见三要素证据和原始位置；
- 事实卡、问卷版本、来源文件和计算时间。

不设置专家最终确认字段。

## 9．AI边界与实施状态

AI可以：读取TDRX、归一化中英文符号、提取原文事实、执行客观分数固定规则、留存证据、检查遗漏、生成简版事实卡、换算问卷、执行公式和生成说明。

AI不可以：把会签结论当成意见质量、按文字长度或专家角色直接定档、补写不存在的对象／动作／细节、预选主观问卷档位、替代技术项目经理作答、因印象修改原始事实、跳过缺失校验直接给正式分数。

本规范是V0.4年度方案的数据设计。解析器与评分系统已实现客观分数、批量导入、逐报告质检、年度项目等权和简版事实卡；主观问卷仍沿用V0.3。14份此前模板报告已完成在线导出与Excel解析验证；2026-08-27定稿的 `B3` 项目信息来源，以及2026-08-28确认的D列／C列评审意见并集去重和评审人名单交集规则，已同步《办法》与本规范，但解析器和回归样本尚未适配，不能把此前验证外推为定稿模板已可正式计分。14份报告同时上传时的动态切换与聚合页面仍待补验，因此不得描述为正式上线。
