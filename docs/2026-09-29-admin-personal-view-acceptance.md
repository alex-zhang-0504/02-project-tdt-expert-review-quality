# 管理员本人考评视图验收

## 行为

- 有本人报告的管理员显示「考核管理／我的考评」；没有本人报告时隐藏切换组。依据后台当前任务的稳定编号、启用名单和已校验报告归属判断，不按姓名写死。
- 考核管理保持全量功能；我的考评沿用技术项目经理的问卷卡片、本人客观统计、过程详情和对策判定，只显示统计页、不提供打分页和导出。
- 请求携带个人视图标识，后台仍验证真实管理员登录，保留真实角色和操作人。个人视图对读取、问卷、对策写入都应用本人范围；普通账号不能通过管理视图标识获得管理员权限。
- 对策判定写入原意见并持久化，全量结果随原有计算逻辑更新。个人裁剪只影响展示，不覆盖完整任务。
- 切换先检查管理员代填退出状态、导入及对策写入，再保存问卷；失败或请求未结束时不切换。切换清理旧视图的分析、问卷及得分缓存，重新读取当前范围。

## 自动验证

340 项 Python 测试、14 个 Node 回归脚本通过。新增回归先复现个人范围读取、跨范围对策及他人问卷未限制，再验证以下结果：

- 管理员个人读取仅返回本人报告，完整载荷和原始得分不因查看改变。
- 本人对策判定成功，他人项目拒绝；全量统计变化，新服务实例重读保持一致。
- 本人问卷正常保存且不触发代填锁，修改记录中的真实角色仍为管理员。
- 个人视图禁止管理接口与全量分数读取，返回管理视图恢复原权限。
- 无报告管理员的个人报告数为零，个人任务列表为空、直接打开他人任务拒绝。
- 代填锁、保存失败、读取和对策更新过程中禁止视图切换；成功切换清理缓存。

## 真实浏览器验证

独立工作区 `var/admin-view-ui-20260929/`，`http://localhost:8896/`，全部使用虚拟人员和报告，复用已有隔离测试凭据，未修改密码。

1. 有报告管理员显示切换组；我的考评仅一位应评价评审人。
2. 个人统计两场、全量统计三场，个人页隐藏客观打分和导出。
3. 在个人详情实际确认一条疑似对策，个人及全量含对策统计同步变为一条，显示人工确认。
4. 首次主观须知保留；六题填写后切换管理视图，问卷保存成功。
5. 重启独立服务并重新登录，本人问卷仍显示六题完成；管理全量统计仍保留三场和一条已确认对策。
6. 无本人报告的第二位虚拟管理员登录后，切换组不可见，管理任务与新建入口保持可用。
7. 浏览器控制台无错误。

## 正式运行与限制

正式数据只读核验：三位管理员的本人报告数分别为九、零、零，对应显示、隐藏、隐藏；未修改正式报告、名单、密码或答案。

自动审批拒绝停止旧 8865 服务，返回策略阻止，未执行该重启命令。改用实际 `start.cmd` 并行启动新版于 `http://127.0.0.1:8866/?build=583f7c0dbfef0381`，健康接口的项目、构建和正式工作区身份一致，启动器再次查询正确复用新版。8865 仍为旧版。

启动器已打开新版浏览器标签，但浏览器保存的用户权限禁止工具访问 8866，未绕过限制。最终采用用户手动验收：用户在正式新版确认，张思远登录后显示双视图入口，进入「我的考评 → 客观数据评价」只看本人项目且详情可判断疑似对策，切回「考核管理」恢复全部项目；用户回复「确认正常」。这三项为用户确认的正式页面证据，不表述为工具亲自操作通过，也不据此声称已实际修改真实判定。

本次功能验收由自动回归、隔离浏览器实操及上述正式账号手动核验共同完成。其他两位正式管理员隐藏入口的证据为正式归属只读核对与同条件虚拟账号浏览器验证，未冒用其身份登录。未提交或推送 Git。
