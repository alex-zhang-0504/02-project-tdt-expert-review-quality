# TDRX评审事实与年度考评数据规范（按年度）V0.3

> 讨论稿｜2026-08-18｜适用口径：by year
>
> 本文只定义字段、公式和校验。评分规则以[《TDT技术项目TDR评审专家质量考评办法（按年度）V0.3》](tdr-expert-review-quality-assessment-by-year-v0.3.md)（下称《办法》）为准。

---

## 1．数据来源

| 数据 | 来源 | 用途 |
|---|---|---|
| TDR事实 | TDRX评审表或本地Excel | 确定当场评审人，计算评审过程会签，生成事实卡 |
| 专业价值贡献 | 年度三题问卷 | 计算维度二 |
| 服务贡献 | 年度参与项目清单 | 计算项目数排名与加分 |

TDRX评审表仍是评审事实的唯一来源。年度事实卡和年度结果均由系统生成，不要求人工维护独立打分表。

每场所需评审人以该场TDRX评审人列表为准；TDR1／TDR2／TDR3名单可以不同，均视为项目实际需求。项目评审专家需求表只用于模拟数据准备，不进入正式考评或缺失校验。

---

## 2．主键与统计窗口

| 对象 | 主键 |
|---|---|
| TDR场次 | `项目编码＋项目阶段＋会议日期` |
| 专家场次事实 | `TDR场次＋专家ID` |
| 专家项目事实 | `考评年度＋项目编码＋专家ID` |
| 年度问卷 | `考评年度＋技术项目经理ID＋专家ID` |
| 年度专家结果 | `考评年度＋专家ID` |

规则：

- 考评年度取TDR会议日期所在自然年。
- 同一项目同一年度只计1个参与项目，TDR场次数单独统计。
- 跨年项目按各年度实际发生的TDR分别形成事实；同一项目可出现在不同年度。
- 专家ID优先使用组织身份ID；姓名和专业角色只用于展示，不作为唯一主键。

---

## 3．场次事实字段

每场TDR导入后，为每位评审人生成一条记录。

系统只处理当场TDRX评审人列表中的专家；未出现在该场列表中的专家，不生成记录，也不判定为遗漏。

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 考评年度 | 是 | 从会议日期派生 |
| 项目编码／项目名称 | 是 | 项目编码用于去重 |
| 项目阶段／会议日期 | 是 | `TDR1｜TDR2｜TDR3｜TDR1+TDR2` |
| 技术项目经理ID／姓名 | 是 | 归属年度问卷 |
| 专家ID／姓名／专业角色 | 是 | 代理参会时记录仍归属原专家 |
| 参会状况 | 是 | `正常｜部分参加｜改派（正常）｜改派（部分）｜缺席未改派｜挂会` |
| 会签结果 | 是 | Go／Go with Risk／Redirect／TBD及逾期后缀 |
| 评审依据完整性 | 是 | AI判定完整／缺项／无意见 |
| 问题编号列表 | 否 | 关联问题汇总表 |
| 问题状态 | 否 | open／closed |
| 场次过程表现分 | 是 | 0—60 |
| 来源文件／来源版本 | 是 | 用于追溯 |
| 导入时间 | 是 | 系统时间 |

场次过程表现分沿用按项目版V0.2：出勤15／10／0、会签15／10／0、意见30／20／0。

---

## 4．年度事实卡字段

年度事实卡按专家生成，供技术项目经理作答前查看。

| 字段 | 计算方式 |
|---|---|
| 专家ID／姓名／专业角色 | 当场TDRX评审人列表；组织身份仅用于补充专家ID |
| 年度参与项目数 | 项目编码去重计数 |
| 年度TDR场次数 | 专家场次事实条数 |
| 合作技术项目经理数 | 技术项目经理ID去重计数 |
| 上半年／下半年项目数 | 按会议日期分组后，项目编码去重 |
| 项目清单 | 项目编码、名称、技术项目经理 |
| 参会事实 | 各参会状况计数 |
| 会签事实 | 各会签结果计数及逾期次数 |
| 风险意见事实 | Go with Risk／Redirect对应问题编号及摘要 |
| 闭环事实 | open／closed数量及证据链接 |
| 数据异常 | 缺失、重复、来源不一致清单 |

事实卡只展示事实，不输出问卷推荐档位。

---

## 5．年度问卷字段

每个有效“技术项目经理—专家”合作关系只生成1份问卷。

| 字段 | 必填 | 说明 |
|---|:---:|---|
| 考评年度 | 是 | 自然年 |
| 技术项目经理ID／姓名 | 是 | 问卷作答人 |
| 专家ID／姓名 | 是 | 被评价专家 |
| 共同项目清单 | 是 | 项目编码去重 |
| 共同项目数 | 是 | 年度贡献分的权重 |
| 履职与协作档位／得分 | 是 | 10／6／0 |
| 专业判断与指导档位／得分 | 是 | 20／14／0 |
| 专业判断0分原因 | 条件必填 | 原因标签＋100字以内说明 |
| 突出贡献档位／得分 | 是 | 10／0 |
| 突出贡献原因 | 条件必填 | 10分时填写，100字以内并关联项目或问题编号 |
| 提交时间 | 是 | 系统时间 |

```text
技术项目经理问卷分＝履职与协作＋专业判断与指导＋突出贡献
```

AI不得预填三个档位。

## 6．派生字段与公式

### 6.1 过程会签

```text
专家项目过程分
＝该专家在该项目、该年度内各有效TDR场次过程表现分之和
 ÷该项目、该年度有效TDR场次数

年度过程会签分
＝各专家项目过程分之和÷年度参与项目数
```

### 6.2 专业价值贡献

```text
年度专业价值贡献分
＝Σ（技术项目经理问卷分×共同项目数）÷年度参与项目数
```

每个项目只能对应一位技术项目经理问卷权重。项目经理发生变更时，按该项目年度最后一次有效TDR记录中的技术项目经理归属。

### 6.3 服务贡献与总分

```text
年度基础分＝年度过程会签分＋年度专业价值贡献分

年度服务贡献分：
  参与项目数第一名＝2
  参与项目数第二名＝1
  其他＝0

年度总分＝min（100，年度基础分＋年度服务贡献分）
```

并列使用竞赛排名：同名次同加分，后续名次跳位。该口径在《办法》正式发布前保持“待确认”。

### 6.4 等级

| 等级 | 条件 |
|---|---|
| S | 年度总分＝100 |
| A | 90≤年度总分＜100 |
| B | 75≤年度总分＜90 |
| C | 60≤年度总分＜75 |
| D | 年度总分＜60 |

年度参与项目数＜2时，增加“样本量小”标记。

## 7．自动校验

| 校验 | 处理 |
|---|---|
| TDR1／TDR2／TDR3评审人名单不同 | 视为项目实际需求，不报异常 |
| TDRX列表内专家的参会、会签或必填意见缺失 | 加入缺失清单，年度结果标记“待补全” |
| 项目编码、专家ID或技术项目经理缺失 | 阻止生成正式年度结果 |
| 同一场次、同一专家重复 | 阻止重复计分 |
| 同一技术项目经理—专家重复提交问卷 | 只保留当前有效版本并记录审计历史 |
| 非合作技术项目经理提交问卷 | 拒绝提交 |
| 应填问卷未完成 | 年度结果保持“待问卷” |
| ②选0分但缺原因 | 拒绝提交 |
| ③选10分但缺原因或事实无法定位 | 拒绝提交 |
| 项目数与项目清单去重数不一致 | 阻止计算服务贡献分 |
| 年度总分超过100 | 强制封顶为100并保留加分前分数 |

---

## 8．结果状态与输出

| 状态 | 条件 |
|---|---|
| 事实待补全 | TDRX或安排关系存在缺失／异常 |
| 待问卷 | 事实完整，但仍有必填问卷未提交 |
| 已完成 | 事实与问卷完整，已生成年度结果 |

“已完成”结果至少保存：

- 年度过程会签分、年度专业价值贡献分；
- 年度基础分、服务贡献分、年度总分和等级；
- 项目数、场次数、合作技术项目经理数和样本量标记；
- 事实卡、问卷版本、来源文件和计算时间。

不设置专家最终确认字段。

---

## 9．AI边界

AI可以：读取TDRX、留存事实、检查遗漏、生成事实卡、换算问卷、执行公式和生成说明。

AI不可以：预选问卷档位、补写不存在的贡献、替代技术项目经理作答、因印象修改原始事实、跳过缺失校验直接给正式分数。

本规范确认前只作为年度方案的数据设计，不代表现有试用系统已实现这些字段和流程。
