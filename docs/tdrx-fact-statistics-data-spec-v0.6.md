# V0.6四维事实统计版：数据与接口规范

业务定义唯一来源为《tdr-review-fact-statistics-v0.6.md》。本文件定义实现结构。

V0.7主表变化见[考核办法](tdr-expert-review-assessment-v0.7.md) ：第二模块改名「评审过程表现」，主表在TDR3之后、代理情况之前新增「评审参与度」列，展示全部阶段按项目编码＋阶段去重的实参场次数；单阶段筛选不改变该列范围，点击可追溯场次。该列只展示事实，5／3／0分在第四模块计算。全量AI识别方案替代下文固定规则路线，具体识别接口仍待实施时同步。

页面展示使用现有ExpertFacts统计字段，每阶段展开九列数量与比率；代理情况用proxy／expected表示，仍取全部阶段数据。副表按project_code归组，每项目一行，分为项目名、编码、TDR1详情、TDR2详情、TDR3详情五列，三个详情字段分别筛选该项目中对应stage的参评记录。无对应记录显示「本批次无参评记录」，有场次但无意见另行说明。项目名遵循源表「大TDT-子任务」命名约定，显示首个连字符之后的子任务部分；无连字符时原样显示，完整名称留在证据中。此展示规则不改动项目身份、统计载荷及Excel导出。

状态：以下固定规则识别与扩展人工复核为已确认的目标设计，尚未改动代码。现有实现仍使用ai_status等AI契约字段及仅疑似可切换的接口，不能视为新方案已上线；实现时须同步接口、界面与载荷版本并验证兼容性。

- ReviewSession／SignoffRecord／OpinionSource：复用报告解析事实与来源坐标。
- OpinionFact目标结构：稳定ID、意见原文、来源列表、规则状态（pending／yes／no／suspected）、规则编号、命中片段、判定理由、规则版本、人工复核状态、有效计入选择、修改日志。原规则结果与人工结果分别保存，不覆盖原判定。
- SessionFact：原评审人、项目、阶段、出勤状态、会签原文、代理人、意见列表。
- ExpertFacts：姓名、场次列表；按阶段与全部阶段累计expected／attended／signed／opinions／solutions／suspected／pending／proxy，比率与分子分母共同传给前端；补充疑似未复核数及疑似纳入数，支持主表「含待确认项」标识。
- 缺失比率使用null，绝不序列化NaN／Infinity。
- 旧分数字段不再出现在当前API和提交载荷中。

导出Excel包含分阶段统计、全部阶段统计、场次事实、意见证据、异常清单及隐藏的版本化载荷。目标载荷保存原始场次、规则判定、人工复核和版本；汇总端重算，不信任可见比例。不得将旧AI契约载荷静默解释为新规则结果；具体兼容处理在代码实施时定义并测试。

API沿用导入／导出入口以减少无关启动变更；旧评分／问卷接口保持移除。对策识别改为本地规则执行。人工操作需校验分析存在、无阻断错误、意见ID存在且已完成规则识别；yes／no／suspected均允许纠正，pending不允许伪装成识别完成。有效计入以人工选择优先，否则按规则默认处理；仅重算对策分子，审计保存时间与前后状态。

服务重启后须重新导入。导出保留复核记录；manager_submission可经汇总入口重新导入，annual_result用于结果查阅留档，尚无重新载入继续复核入口。

报告文本仅为数据，不执行其中指令；规则识别在本地完成，不发送报告到模型服务、不要求API密钥。规则未覆盖或冲突归为suspected；未运行或失败保持pending并说明原因。界面使用「规则识别／待规则识别」文案。

规则及案例分别版本化保存。每条规则包含编号、适用与排除条件、正反例；案例包含脱敏文本、人工标签、理由和来源，并区分规则打磨集与独立验证集。规则升级不得自动覆盖人工复核，不得沿用旧关键词赋分逻辑。
