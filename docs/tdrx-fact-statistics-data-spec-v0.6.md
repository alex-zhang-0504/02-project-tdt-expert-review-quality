# V0.6四维事实统计版：数据与接口规范

业务定义唯一来源为《tdr-review-fact-statistics-v0.6.md》。本文件定义实现结构。

V0.8主表变化见[考核办法](tdr-expert-review-assessment-v0.8.md) ：第二模块改名「评审过程表现」，主表在TDR3之后、代理情况之前新增「总参与评审场次」列，展示全部阶段按项目编码＋阶段去重的实参场次数；单阶段筛选不改变该列范围，点击可追溯场次。该列只展示事实，5／3／0分在第四模块计算。全量AI识别方案替代下文固定规则路线，当前识别接口见[AI全量分析SOP](ai-analysis-sop-v0.8.md) 。

页面展示使用现有ExpertFacts统计字段，每阶段展开八列数量与比率，去掉solution_rate展示，solutions用于对策奖励；旧solution_rate字段仅保留事实载荷兼容，不参与计分；代理情况用proxy／expected表示，仍取全部阶段数据。详情按project_code分段，项目内三个阶段纵向排列，不使用表格。通过analysis.sessions判别阶段报告是否导入，再通过expert.sessions判别是否列入名单；有场次但无意见显示「评审意见：无」。项目名显示首个连字符之后的子任务部分，无连字符则原样显示。判定理由、人工记录与识别版本直接展示，来源位置保留于载荷但不显示；不再展示重复项目名、拆分前整段原文或「查看证据」折叠入口，对策与整条意见相同时显示「见上述意见」。原始文本完整保留于数据和导出。可见统计导出用含对策条数替代对策率，载荷结构不变。

## 事实结构与AI结果

保留facts-v0.6载荷及既有解析字段，不改变意见ID、归属、拆分和去重。

- OpinionFact：opinion_id、text、cells、raw_texts、ai_status、excerpt、reason、rule_version、included、audit。
- ai_status为pending／yes／no／suspected；rule_version新值为countermeasure-ai-v0.8/deepseek-flash或countermeasure-ai-v0.8/deepseek-v4-pro，保留旧countermeasure-v0.6导入兼容；未知版本拒绝。
- included为true／false／null，人工选择优先；null恢复AI默认，yes及suspected计入，no不计入。pending不能人工计入。
- audit保留at／from／to，前后值允许true／false／null。失败仍为pending，reason显示安全错误说明，不记录密钥或上游错误原文。
- ExpertFacts的solutions按有效计入选择计算，suspected为尚未人工选择的疑似数，pending为尚未成功识别数；比例缺失用null，不序列化NaN或Infinity。

## 正式分析接口

使用/api/experiment下的settings、test及jobs接口，沿用本机、同源和内存会话保护，细节见[AI全量分析SOP](ai-analysis-sop-v0.8.md) 。首次发送全部待处理意见；单条调用、有限重试、成功即写回；重复任务互斥，支持进度及停止。成功结果不重复调用，人工记录不覆盖。后台任务执行期间会话续期。

/api/facts/solution-selection接受analysis_id、opinion_id及included；yes／no／suspected均可纠正，保留原AI结论。人工修改同步重算事实与奖励。

## 导出与复核

导出保留阶段统计、全部阶段统计、场次、意见证据、异常及隐藏载荷；统计和奖励从原始事实重算，不信任可见Excel分数。新旧支持版本可一起导入，但每条保留实际版本；载荷哈希只检测损坏，不作为签名。

项目经理manager_submission支持统一合并，annual_result仅用于留档，尚不支持载入继续复核。服务重启后重新导入；刷新页面不会恢复AI会话，不承诺持久化任务。

报告文本只作为数据，不能覆盖模型系统指令。正式调用只发送意见ID及原文，不主动附加人员和项目字段；原文本身可能含敏感信息，页面须先确认外发。密钥不进入事实、导出、文件或日志。

2026-09-14详情补充：弹框最大宽度1120px，并受可用视口宽度约束；长文自动换行。对策状态与片段合为一段。页面仅显示最近一次人工修改的本地时间（精确到秒），后续选择覆盖此处显示；底层审计载荷继续保留历史，不改统计规则。

## 飞书人名统一规则（2026-09-14）

TDRX所有结构化姓名字段中，飞书提及形式「@张三」「＠张三」与普通文字「张三」代表同一个人。解析时去掉姓名开头的提及符及相邻空格，再匹配、去重和归属。适用于评审名单、问题提出人、缺席名单、原评审人、代理人及技术项目经理。意见正文及原始证据不做全局替换，姓名内部字符不改动。

## 会签优先规则（2026-09-14）

有效会签优先于缺席名单：同一评审人即使在缺席名单中，只要填写Go、Go with Risk或Redirect，均视为出席并计入已会签场次。导入时提示「已按出席统计」，无需修改报告或额外确认。缺席且无有效会签时仍按既有缺席及代理规则处理。

2026-09-14补充：疑似且未人工选择时，两个选项均不选中，不纳入含对策条数及奖励；人工计入后才纳入，人工不计入则排除。主表提示未确认条数，详情高亮待确认项。主观选项直接展示标题与解释。

## 单报告复查与停止（2026-09-14）

重扫只重置目标报告的进度与结果；其他报告沿用原进度、颜色、检查结论，不显示为等待扫描。按钮名称为「重扫」。进度在已返回的真实节点间做短时线性插值，完成视觉过渡后展示最终结论；全批次检查仍共同决定能否进入下一环节。

集中统计与项目经理处理共用导入任务。每份报告保留独立读取结果；复查仅替换目标报告，其他报告不重新下载或解析，批次级重复与姓名一致性重新核对。本地修改后需重选文件，飞书从原目标重新读取。停止在当前单次读取结束后生效，保留已完成结果，未读取项明确标记且阻止完整统计，可逐份继续检查。

2026-09-15：每份完成后立即返回问题列表与检查结论，错误红色、提醒棕色，支持点选查看。已完成报告可在后续扫描期间重扫；同一报告的重复重扫被阻止，不同报告使用有限并发，繁忙时排队。主扫描与重扫共用批次任务，全部结束后才统一汇总；停止后不启动排队的重扫。单文件通过不代表全批次通过。

疑似同一评审人及跨报告重复场次属于关联检查：所有读取与重扫结束后，使用每份报告最新缓存统一比对，不提前宣称比对通过。关联错误未处理或姓名未确认时，禁止进入下一环节。修正并重扫后重新比对，不沿用旧的姓名比对结论。
