## 三个关键判断

| 页面状态 | 含义 |
|---|---|
| 实验未开启 | 当前页面没有可用配置 |
| 已配置 deepseek-flash，尚未测试 | 已暂存密钥，尚未请求 DeepSeek，不能视为接入成功 |
| 连接及结果格式验证通过 | 这一条虚拟文本已经完成请求、返回和格式校验；不代表整批意见已分析，也不证明判断准确 |

密钥只存于内存，所以关闭弹窗再打开不需要重填；同一页面一小时内可以重复调用。刷新、关闭页面、重启服务、主动清除或配置满一小时后，需要重新输入。输入框清空是为了不回显，不表示配置已丢失。这是当前实验设计，并非 DeepSeek 要求每次输入密钥。

「前10条」是本项目实验代码设置的上限，不是模型上限。前期只用于检查识别效果，结果不会更新主表、分数或导出。当前不能通过换模型或填密钥直接启用全量正式分析；需要继续实现已记录的全量 AI 方案。

## 操作

1. 重启到最新本地服务，点击页面顶部「个人实验设置」。
2. 选择「DeepSeek V4.1 Flash」，实际模型名为 `deepseek-flash`；服务地址固定为 `https://api.deepseek.com`。使用自己在 DeepSeek 开放平台创建的 API Key，并确认 API 账户有可用余额；不要把密钥发到聊天中。
3. 点击「开启本次实验」只在本地暂存配置，不调用模型；输入框随即清空，不回显密钥。
4. 点击「测试连接（虚拟文本）」。看到「连接及结果格式验证通过」及 `deepseek-flash` 的判定结果，才确认本次调用成功。此操作可能产生API费用；如果报错，按下面的提示处理。
5. 读取报告并通过质检，打开实验设置，点击「预览本批次前10条意见」；最多10条、共12000字，不自动发送整份报告。
6. 核对预览内容，确认允许外发后勾选并点击「发送预览意见并试验」。文本本身可能包含姓名或技术机密，系统不声称自动脱敏。
7. 查看模型判定、原文片段及理由。结果不写回主表、复核记录或Excel，不影响部门结果。
8. 用完点击「关闭并清除密钥」。关闭弹窗只是隐藏窗口，不等于关闭实验；已发出的请求不能撤回。

## 报错处理

| 提示 | 下一步 |
|---|---|
| 密钥无效 | 检查是否使用 API Key，重新配置 |
| 账户余额不足 | 检查 DeepSeek API 账户余额后重试 |
| 调用过于频繁／服务繁忙 | 稍后手动重试 |
| 等待响应超时 | 本次等待超过45秒；稍后重试，不等于密钥无效 |
| 无法连接 DeepSeek | 检查网络；当前代码直连，不使用系统代理 |
| 返回空内容／不是有效 JSON | 服务有返回，但内容无法使用；重试虚拟文本测试 |
| 输出达到长度上限 | 本次输出被截断；先测试虚拟文本，较大报告可缩小导入批次 |
| 意见结果不完整或原文片段不匹配 | 请求已返回，但没通过逐条结果校验；保留原统计，反馈报错排查 |
| 请求参数或格式被拒绝 | 先确认正在使用最新本地服务，再反馈提示；反复更换密钥不能解决参数问题 |

失败不自动重试，不会覆盖统计。不要把「试验成功但统计没变化」当作调用失败：这是当前实验入口的明确边界。

## 配置与安全边界

- 默认关闭，不预置密钥，不改.env，不增加全局依赖或系统设置。
- API Key保存在本地后端内存，不在URL、响应、项目文件或导出中出现；会话凭证仅在当前页面内存保存，不使用浏览器持久化存储。
- 配置有效期1小时；过期后不可继续调用。刷新页面需重新配置，旧会话会失效到期，建议刷新前主动清除；服务退出后全部丢失。
- 仅允许本机地址和同源实验请求；页面会话凭证隔离各实验配置。此防护不等于多用户登录权限，不防本机恶意程序或页面被篡改。
- 只向固定官方域名发送意见文本和不含姓名的内部标识；禁用重定向及环境代理，超时45秒，不自动重试计费请求。需代理的网络目前不支持，不能静默改变系统代理。
- 同一会话同时只执行一次调用。未配置、密钥无效、余额不足、限流、网络错误或结构化结果不合格时提示失败，不覆盖原统计。

## 技术依据

按 [DeepSeek Chat Completions 接口](https://api-docs.deepseek.com/api/create-chat-completion/) 调用，POST `/chat/completions`，使用 Bearer 鉴权、JSON 输出及关闭思考模式。
据 [官方 V4.1 Flash 发布说明](https://www.deepseek.com/en/news/deepseek-v4-1-flash/) ，2026-09-10 发布的 V4.1 Flash 使用 `deepseek-flash`；旧 `deepseek-v4-flash` 暂时兼容映射，所以不能仅凭旧名称认定连接失败。保留的 Pro 是过渡入口，官方宣布从2026-09-14 04:00 UTC起路由至 V4.1 Flash；本 SOP 使用 Flash。
结构化输出使用 [官方JSON Output说明](https://api-docs.deepseek.com/guides/json_mode/) 的json_object模式，结果再校验意见ID、完整性及原文片段；JSON合法不等于判定正确。
