# AI全量分析与使用说明

本功能按用户2026-09-13确认执行，替代前10条个人实验流程。实施及验收状态见ROADMAP。

## 使用步骤

2026-09-15新增：先查看「AI设置」中的判定配置读取状态。生效文件为`docs/countermeasure-policy-v0.1.json`，规则、角色关键词与已确认案例自动随每次分析请求发送。加载失败阻止分析；每批固定版本与内容指纹。维护方法见[countermeasure-policy-v0.1-guide.md](countermeasure-policy-v0.1-guide.md) 。

1. 打开「AI设置」，填写DeepSeek官方API Key，点击「保存并验证连接」；只有虚拟文本调用及结果校验通过，才提示「配置成功」。
2. 读取评审表，点击「识别待处理对策」，核对数量并确认向DeepSeek发送意见文本。
3. 系统逐条分析全部待处理意见，显示总数、成功、待确认、失败和剩余数量。成功结果即时写回，详情可查看原文片段及理由。
4. 失败时点击同一按钮只重试未完成意见；已成功条目不会重复调用。疑似默认不计入，须人工确认，所有已识别结果均可人工纠正，页面仅提供「计入统计／不计入统计」两种选择。

## 执行规则

- 默认使用官方`deepseek-flash`模型；每次只发送一条意见的ID和完整文本，不附加人员、项目或源文件字段。文本中原有信息仍会发送，调用产生API费用。
- 识别建议、改善措施及技术决策，只需有处理方向，不要求完整责任人、时间或参数；不补写原文没有的措施。通用动作只作提示，不作为关键词打分。
- 逐条验证ID、三类状态、理由和连续原文片段。无效返回、网络失败不能算「不包含」。暂时故障最多重试一次，之后继续其他意见；鉴权或余额错误停止后续调用。
- 一条意见多个动作只计一条。疑似默认不计入，须人工确认，含对策每条加2分；沿用V0.8计分，不改变意见数或归属。
- 同一分析不能重复启动任务。停止后保留成功结果，未完成项仍待识别；已发出的请求无法撤回，但停止后返回的结果不写入。
- 密钥只保留在服务内存，不写项目文件、浏览器持久存储、导出或日志。关闭设置弹窗不会清除配置；空闲有效期1小时，执行中续期，刷新页面或重启后需重新配置。
- 任务和结果沿用内存存储；刷新不会取消后台任务，但当前页面无法自动恢复会话。刷新前应等待任务结束并导出结果。服务重启不保留任务。

## 接口

沿用`/api/experiment`命名空间集中保护密钥会话；页面统一称「AI设置」。

- `settings`保存内存配置，`test`验证虚拟文本并标记配置可用。
- `jobs`建立全量任务，要求有效且验证通过的会话、有效analysis_id和confirmed=true。
- `jobs/{id}`查询进度及当前分析，`jobs/{id}/cancel`停止任务；仅创建任务的会话可操作。
- 成功意见保存状态、原文片段、理由、模型和提示版本；失败意见保持pending并显示原因。人工修改保留审计记录。

官方参数依据：[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 。使用Bearer认证、JSON对象输出和关闭思考模式；返回截断或片段不匹配时不写入该条结果。

直接提出明确方案也计为意见及对策；「方案」「对策」等标注辅助理解，没有标注也由AI逐条分析。本次提示规则更新不会自动重跑已有识别结果。

2026-09-14补充：疑似且未人工选择时，两个选项均不选中，不纳入含对策条数及奖励；人工计入后才纳入，人工不计入则排除。主表提示未确认条数，详情高亮待确认项。主观选项直接展示标题与解释。
