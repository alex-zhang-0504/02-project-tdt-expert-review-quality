# 名单、评分与经理评价使用说明V0.1

## 一次完整操作

2026-09-20：取消手填考核批次，下文批次仅表示系统内部隔离标识。每次确认名单时由系统自动生成；项目经理事实提交按当前年度自动归组。导出文件统一使用「报告名_截止YYYY年MM月DD日前的评审记录.xlsx」，日期为导出当天，不代表系统已验证报告范围完整。同一轮经理问卷仍须来自同一次导入，不同轮次不能混入。

1. 在「读取评审表」导入报告并处理错误。飞书原文件所有者自动对应经理；本地报告逐份填经理唯一编号和姓名，同一经理始终使用同一编号。
2. 导入老板名单Excel（需「姓名」「评审人」或「评审人姓名」列），也可直接横写或逐行粘贴。换行、空格、顿号及中英文逗号、句号、分号均可分隔姓名；重复姓名自动去重，@姓名与纯姓名一致。点「对比名单」查看交集、未匹配及未纳入人员，三类分别成行，不会模糊匹配姓名。
3. 点「读取评分配置」，系统实际读取文件并显示版本、文件、时间及完整SHA256指纹。点同一操作行的「进入评审过程」即确认当前名单并固定配置，无需另点确认；如果读取后配置变化，须重新读取后再进入。未读取成功、交集为空或报告错误未处理均不能继续。需要调整已固定的名单、归属或参数时，重新读取报告建立新批次。
4. 「评审过程表现」通过底部分页切换数据统计与客观评分，顶部不重复分页。确认报告范围后得到基础分、超额意见奖励、输出对策奖励及客观合计；合计可超过30分，不依赖主观评价。客观评分页面及其评分导出不展示代理场次、代理率，代理信息保留在数据统计；点击代理情况查看全部阶段的逐场项目、阶段与代理人，无记录时明确提示。意见提出平均数在页面及Excel中显示一位小数，计算及事实载荷保留原始精度。两个页面均可独立导出Excel。
5. 「专业价值贡献」选择经理，只显示与其有实际项目交集的考核人员。填写六项并保存。切换经理不会覆盖另一位经理的评价；同一经理再次保存会替换自己的旧票。

   界面按经理工具栏、评审人名单／六维问卷、底部分页组织。导出／回收经理问卷集中在工具栏，评分说明可展开查看；选项标题与解释常显。保存栏在问卷底部吸附，进度、保存状态就近展示。当前评审人的排除与恢复操作位于「任务管理」折叠区，底部左侧为分页，右侧为「导出评价结果」。主观评分页使用本页的导出入口；汇总仅通过顶部第四模块进入，不重复设置跳转按钮。
6. 分散填写时，选择经理后「导出经理问卷」，把文件交对应经理填写。只修改「经理问卷」后三列；档位用下拉选项high（高）、medium（中）、low（低）。说明页提供解释及可关联项目，共同项目事实页提供参考。每次修改后再次提交，增加「提交修订」B1的修订号。
7. 汇总人在「回收经理问卷」逐份导入，系统核对批次、名单、配置、经理项目范围及修订。重复文件不会增加票数，旧修订不能覆盖新修订，文件内有错误则整份不接收。
8. 主观第二页显示六维均分、最终分、暂定平均和完成数量。未收齐只给暂定平均，缺失不算0分；全部应评价任务完成才给最终分。确实无需评价的任务填写理由后排除，可恢复，记录随评分导出保留。
9. 「分数统计」汇总客观合计和主观最终分，按配置封顶；奖励只加一次。两个维度及汇总均可分别导出。

名单文件成功导入后，页面保留该文件识别出的原始名单。手动删改后点击文件旁的「还原导入名单」，即可恢复最近一次成功导入的名单并重新比对，无需再次选择文件。新文件成功导入才替换原名单；读取失败不覆盖。名单确认后不可还原，页面刷新后不保留这份临时副本。

## 参数怎么调整

修改`config/scoring-policy-v0.1.json`，不修改脚本。已确认批次不会被参数变更影响；新批次确认时读取新参数。配置格式损坏或数值不合法会阻止确认，没有备用默认值。

| 参数 | 含义 |
|---|---|
| stage_weights | TDR1／2／3权重，默认4／2／4；无应参阶段剔除后归一 |
| components | 阶段内出勤、会签、意见满分，默认5／10／10 |
| opinion_threshold | 每场意见基础要求，默认1；意见基础＝min（平均数÷要求，1）×意见满分 |
| participation | 至少参评场次和前三种数量档分数，默认3场、5／3／0；第三档代表其余人员 |
| subjective | 六维各档分数；档位结构保持不变 |
| excess_opinion_points | 每阶段max（意见数－实参×基础要求，0）×每条奖励，默认每条1分 |
| solution_points | 每条确认含对策意见奖励，默认2分 |
| total_cap | 两维最终总分上限，默认100；不限制独立客观合计 |
| precision | 分数保留的小数位，默认2 |

## 当前边界

经理选择是工作分配，不是登录鉴权；系统仅供授权管理者使用。分析保存在当前服务内存中，页面刷新或服务重启不会自动恢复；离开前导出经理问卷及评分结果。评分结果Excel用于留档，不作为恢复入口。经理问卷须在原导入会话中回收，重新导入会生成新标识，不能用旧问卷恢复评价。新旧配置指纹不同的问卷不能混用。真实人员评价质量、样本公平性仍需业务试用验证。

## 接口与载荷

- `assessment`保存确认名单、未匹配、未纳入、批次、名单指纹、评分配置快照及任务排除理由。原始`sessions`和`experts`保留；对外考核结果仅显示交集。
- `manager_reviews[manager_id][expert_name]`保存问卷、更新时间和修订。同一键只有一票。旧`subjective_reviews`仅保留旧载荷兼容，不能用于新考核的最终主观分。
- `POST /api/assessment/roster-file?analysis_id=…`读取名单Excel；`POST /api/assessment/roster`比对或确认（`confirm=true`）。
- `GET /api/assessment/policy`实际读取评分配置；界面确认时提交`policy_hash`并核对，未提交`batch_id`时使用本次分析标识自动隔离。事实导出`/api/export/dimension-one`同时支持原POST及浏览器直接下载的GET。
- `POST /api/assessment/local-manager`指定本地报告经理；飞书归属不可通过此接口覆盖。
- `GET /api/assessment/tasks`查看任务；`POST /api/assessment/exclude-task`排除／恢复。
- `POST /api/subjective/review`增加必需的`manager_id`；姓名及依据项目均核对实际任务。
- `GET /api/assessment/task-export`和`POST /api/assessment/task-import`用于经理问卷往返。
- `GET /api/statistics/scores/export`的`dimension`可选`objective`／`subjective`／`all`；三者读取同一个配置快照和计分服务。
- 新事实字段`opinion_average`为条数／实参。旧`opinion_rate`仅保留旧载荷兼容，界面和新导出不再使用。
