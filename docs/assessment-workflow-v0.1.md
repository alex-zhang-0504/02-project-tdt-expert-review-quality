# 名单、评分与经理评价使用说明V0.1

## 一次完整操作

2026-09-22全系统备注：先区分用途，再判断长度。不超过6字的辅助短语可保留括号；完整辅助说明放在所属标题、字段或操作旁的圆圈惊叹号，悬停、聚焦或点击展开。状态、实际错误、事实依据、读取凭据及数据发送／费用确认仍直接显示。主观选项卡片解释不折叠。适用范围含方案选择、导入／汇总、客观统计／评分、主观问卷／评分、总分及设置弹窗。

2026-09-22读取界面：扫描文件行只显示错误／提醒数量。蓝色问题汇总区的圆圈惊叹号分别解释「错误项需要先修改再继续」「提醒项建议确认和修改，但不影响继续进行」；支持鼠标悬停、键盘聚焦及点击查看。名单标题左对齐，右侧同类图标说明考核范围；姓名和说明文字保持黑色。「确认均为不同人员」按钮与该问题区域左边界对齐。界面、服务端提示及当前使用说明统一称「评分参数」，文件路径与计分规则保持不变。

2026-09-22：客观数据评价两页底部仅保留居中单按钮「查看客观评分」／「返回客观数据统计」。对策识别用一个长按钮显示进度：识别中点击请求停止，正在停止时暂不可重复点击；当前已发出的有效结果返回后保留，不再发送下一条。已停止或部分失败时点击继续未完成项，全部完成后点击按最新判定配置重新识别全部意见。重识别保留人工计入／不计入选择，失败保留此前有效结论并显示本次失败数量。启动、继续与重识别沿用原有发送及费用确认，不另设停止按钮。

2026-09-20：取消手填考核批次，下文批次仅表示系统内部隔离标识。每次确认名单时由系统自动生成；项目经理事实提交按当前年度自动归组。导出文件统一使用「报告名_截止YYYY年MM月DD日前的评审记录.xlsx」，日期为导出当天，不代表系统已验证报告范围完整。同一轮经理问卷仍须来自同一次导入，不同轮次不能混入。

1. 在「读取评审表」导入报告并处理错误。飞书原文件所有者自动对应经理；本地报告逐份填经理唯一编号和姓名，同一经理始终使用同一编号。
2. 「考核评审人名单」区点击「上传名单单击此处」导入老板名单Excel（需姓名列），上传自动匹配，成功后按钮显示文件名，再点可替换。也可横写或逐行粘贴姓名，点「手动匹配名单」刷新结果；旁边「还原导入名单」恢复原文件识别结果。换行、空格、顿号及中英文逗号、句号、分号均可分隔姓名；重复姓名自动合并，@姓名与纯姓名一致。结果分行显示已匹配、未匹配、未纳入，不模糊匹配。提醒仅建议核对报告、不要求勾选、不阻断；错误和未完成扫描仍阻断。
3. 点居中的「读取评分参数」，真实读取成功后按钮变为「下一步」，旁侧显示版本、读取时间及可展开的完整凭据。再点「下一步」按当前姓名重新匹配、确认名单并固定配置，进入「客观数据评价」；如果读取后配置变化，须重新读取后再进入。未读取成功、交集为空或报告错误未处理均不能继续。需要调整已固定的名单、归属或参数时，重新读取报告建立新考核。
4. 「评审过程表现」通过底部分页切换数据统计与客观评分，顶部不重复分页。确认报告范围后得到基础分、超额意见奖励、输出对策奖励及客观合计；合计可超过30分，不依赖主观评价。客观评分页面及其评分导出不展示代理场次、代理率，代理信息保留在数据统计；点击代理情况查看全部阶段的逐场项目、阶段与代理人，无记录时明确提示。意见提出平均数在页面及Excel中显示一位小数，计算及事实载荷保留原始精度。两个页面均可独立导出Excel。
5. 「专业价值贡献」选择经理，只显示与其有实际项目交集的考核人员。填写后点击「下一步」，系统自动提交实际修改并进入该经理的下一位评审人，跳过已排除任务；最后一位进入主观评分。仅浏览经理或评审人不会提交空问卷。未填完整或缺少必要依据时保留待评价／待补依据状态，不参与完整问卷均分，不强迫用户补填或给零分。

   界面按经理工具栏、评审人名单／六维问卷、底部分页组织。导出／回收经理问卷集中在工具栏，评分说明可展开查看；选项标题与解释常显。「下一步」在问卷底部吸附，进度与去向就近展示。切换经理／评审人／模块、查看评分、导出或回收问卷前自动提交实际修改；成功后继续，失败则定位失败问卷、保留内容并提示重试，不再要求逐份寻找保存入口。同一经理更新只替换自己的旧票。当前评审人的排除与恢复操作位于「任务管理」折叠区，底部左侧为分页，右侧为「导出评价结果」。主观评分页使用本页的导出入口；汇总仅通过顶部第四模块进入，不重复设置跳转按钮。
6. 分散填写时，选择经理后「导出经理问卷」，把文件交对应经理填写。只修改「经理问卷」后三列；档位用下拉选项high（高）、medium（中）、low（低）。说明页提供解释及可关联项目，共同项目事实页提供参考。每次修改后再次提交，增加「提交修订」B1的修订号。
7. 汇总人在「回收经理问卷」逐份导入，系统核对批次、名单、配置、经理项目范围及修订。重复文件不会增加票数，旧修订不能覆盖新修订，文件内有错误则整份不接收。
8. 主观第二页显示六维均分、最终分、暂定平均和完成数量。未收齐只给暂定平均，缺失不算0分；全部应评价任务完成才给最终分。确实无需评价的任务填写理由后排除，可恢复，记录随评分导出保留。
9. 「分数统计」汇总客观合计和主观最终分，按配置封顶；奖励只加一次。两个维度及汇总均可分别导出。

名单文件成功导入后，页面保留该文件识别出的原始名单。手动删改后点击文件旁的「还原导入名单」，即可恢复最近一次成功导入的名单并重新比对，无需再次选择文件。新文件成功导入才替换原名单；读取失败不覆盖。名单确认后不可还原，页面刷新后不保留这份临时副本。

## 参数怎么调整

在客观数据统计表下方右侧点击带矢量锁头的「评分参数」查看参数。默认只读，本机管理员首次设置8至128位密码后解锁，以后输入密码解锁；授权10分钟到期，关闭弹窗或点「结束修改」撤销本次授权。密码由管理员自行设置，无默认密码；仅加盐哈希保存到已忽略的`var/scoring-admin.json`，不入Git。此权限仅保护本地应用写接口，不代替操作系统文件权限。

顶栏不再提供AI设置入口。点击「对策有效性识别」，尚未配置时自动打开连接设置；已有配置时，可在识别确认窗口点击「连接设置」修改或清除连接。底部页面引导按钮统一蓝底白字。

编辑后点「预览修改」核对变更，再点「确认并永久保存」。服务端校验权限、参数及配置指纹，使用文件锁和原子替换写入`config/scoring-policy-v0.1.json`；写后重新读取核验成功才显示永久保存，服务重启后仍有效。遇到其他窗口修改会拒绝覆盖，重新打开后再编辑。已开始考核保留原快照，新考核读取新参数。配置格式损坏或数值不合法会阻止确认，没有备用默认值。保存不会自动提交Git。

模块入口现为「客观数据评价」「主观评价」「总分统计」，文中旧称仍指对应业务维度。

| 参数 | 含义 |
|---|---|
| stage_weights | TDR1／2／3权重，默认4／2／4；无应参阶段剔除后归一 |
| components | 阶段内出勤、会签、意见满分，默认5／10／10 |
| opinion_threshold | 每场意见基础要求，默认1；意见基础＝min（平均数÷要求，1）×意见满分 |
| participation | 至少参评场次和前三种数量档分数，默认3场、5／3／0；第三档代表其余人员 |
| subjective | 六维各档分数；档位结构保持不变 |
| excess_opinion_points | 每阶段max（意见数－实参×基础要求，0）×每条奖励，默认每条1分 |
| solution_points | 每条确认含对策意见奖励，默认2分 |
| total_cap | 两维最终总分上限，默认100；不限制独立客观合计 |
| precision | 分数保留的小数位，默认2 |

## 当前边界

经理选择是工作分配，不是登录鉴权；系统仅供授权管理者使用。分析保存在当前服务内存中，页面刷新或服务重启不会自动恢复；离开前导出经理问卷及评分结果。评分结果Excel用于留档，不作为恢复入口。经理问卷须在原导入会话中回收，重新导入会生成新标识，不能用旧问卷恢复评价。新旧配置指纹不同的问卷不能混用。真实人员评价质量、样本公平性仍需业务试用验证。

## 接口与载荷

- `assessment`保存确认名单、未匹配、未纳入、批次、名单指纹、评分参数快照及任务排除理由。原始`sessions`和`experts`保留；对外考核结果仅显示交集。
- `manager_reviews[manager_id][expert_name]`保存问卷、更新时间和修订。同一键只有一票。旧`subjective_reviews`仅保留旧载荷兼容，不能用于新考核的最终主观分。
- `POST /api/assessment/roster-file?analysis_id=…`读取名单Excel；`POST /api/assessment/roster`比对或确认（`confirm=true`）。
- `GET /api/assessment/policy`实际读取评分参数；界面确认时提交`policy_hash`并核对，未提交`batch_id`时使用本次分析标识自动隔离。事实导出`/api/export/dimension-one`同时支持原POST及浏览器直接下载的GET。
- `POST /api/assessment/local-manager`指定本地报告经理；飞书归属不可通过此接口覆盖。
- `GET /api/assessment/tasks`查看任务；`POST /api/assessment/exclude-task`排除／恢复。
- `POST /api/subjective/review`增加必需的`manager_id`；姓名及依据项目均核对实际任务。
- `GET /api/assessment/task-export`和`POST /api/assessment/task-import`用于经理问卷往返。
- `GET /api/statistics/scores/export`的`dimension`可选`objective`／`subjective`／`all`；三者读取同一个配置快照和计分服务。
- 新事实字段`opinion_average`为条数／实参。旧`opinion_rate`仅保留旧载荷兼容，界面和新导出不再使用。
