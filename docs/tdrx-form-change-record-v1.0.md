## 1．改造目标与结果

目标：在不改变部门现有填表习惯的前提下，让按项目《办法》V0.2 的**评审过程表现 60 分可被AI全自动判定**，人工零干预。

结果：**已达成**。TDR3 sheet 的 11 位评审人全部算出场次过程表现分，无需任何人工补充输入。

## 2．最终结构（TDR3 sheet）

分三个区块，AI 靠区块标题文字定位，不依赖硬编码行号。

### 2.1 评审会基本信息列表

`技术项目+编号`／`项目阶段`／`会议日期`／`技术项目经理`／`评审结论`／`评审意见` 六个键值对，其中「技术项目+编号」写作 `项目名（项目编码）`，「项目阶段」为四值下拉（含 `TDR1+TDR2`）。

相比改造前新增了**技术项目经理**字段与**项目编码**；评审ID 由「项目编码＋项目阶段＋会议日期」自动生成，不单设字段；评审主席由会签列表中角色为 `评审主席` 的行识别。

### 2.2 评审结论和会签列表（维度一计分的唯一入口）

| 列 | 字段 | 关键变化 |
|---|---|---|
| A | 评审角色 | 不变，＝主责范围 |
| B | 评审人 | **改为全名**；改派写 `原专家（代理：代理人）` |
| C | 参会状况 | **新增**，6 值下拉：`正常｜部分参加｜改派（正常）｜改派（部分）｜缺席未改派｜挂会` |
| D | 会签结果 | 枚举统一为 `Go｜Go with Risk｜Redirect`，**新增 `TBD`**（＝未给结论）与三个 `（逾期）` 后缀值，共 7 值 |
| E | 评审依据 | 由原「评审意见」**改名并收窄语义**为判断依据 |

改造前的「缺席人姓名和角色」自由文本行已废除——出勤与改派事实一律以 C 列为准，消除双事实源。

### 2.3 评审问题&建议汇总表（被查证的地方，非入口）

| 列 | 字段 | 关键变化 |
|---|---|---|
| A | 序号 | 改为 `TDR<节点号>-<序号>`，项目内全局唯一 |
| B | 评审人 | **改为全名**；多人共提用顿号分隔 |
| C | 问题描述 | 不变 |
| D | 建议改善措施 | 由原「是否要修正」改名（该列改造前无人填写） |
| E | 验证方式与通过条件 | **新增** |
| F | 进展（技术负责人跟踪） | 由原「反馈/修改说明」改名 |
| G | 问题状态 | 不变 |

**问题等级列已删除**，经核不参与任何计分链路。首行保留为**模板说明行**（`A` 列写 `TDRX-No.`，不匹配编号格式，AI 自动跳过），用于降低填表人的学习成本。

**11 人全部算出，场次分区间 0–60。历史横向均值42.3仅用于确认解析结果完整，不是系统评分指标、分数线锚点或专家考核结果；正式平均分只计算同一专家在同一项目内的有效评审场次。**

校验通过项：枚举合法性、`（代理：X）` 后缀剥离与记录归属、`（逾期）` 后缀剥离、三人共提一条问题的顿号解析、问题编号唯一性、说明行被正确跳过、问题表姓名与会签列表的关联。

抓取策略的实证：`TDR3-2` 由高腾飞提出，但他本场会签为 `Go`，按规则自动归为技术交流类不参与计分——**无需人工标注问题来源类别**。

## 4．模板交付状态

改造当前落地文件为 `docs/TDT技术项目_TDRX评审报告（模板v0.1）_2026-08-11.xlsx`：`TDR(书写示例)` 保留 TDR3 真实数据作范例，`TDR1`／`TDR2`／`TDR3` 为同构空表，每个区块首行为填写说明行，五组下拉齐备。计分时技术项目经理可直接提供本地 Excel 文件，也可上传为飞书云文档后提供 URL；两种输入进入同一套解析与计分流程。

原始 `展锐...xlsx` 中 TDR1／TDR2 两个 sheet 仍是旧结构，作为历史记录保留；若要纳入计分需按以下清单补录：

1. 会议信息区改为六键值对，补 `技术项目经理`；TDR2 的会议日期当前为空，须补录。
2. 会签列表加 `参会状况` 列；`会签结果` 换新枚举；`评审意见` 改名为 `评审依据`。
3. 问题汇总表按 §2.3 改列；序号加节点前缀。
4. 姓名全部改全名——现有简称（如「振岩」「利平」）无法与会签列表关联。
5. TDR1 的问题汇总表当前全空、意见全写在会签行，须按「Go with Risk／Redirect 的意见登记进问题表」补录。
6. TDR2／TDR3 之间存在同一条问题被两个节点各登记一次的情况，同步时按「沿用行保留首次提出节点编号」处理，避免重复计分。

## 6．2026-08-23恢复原始布局后的当前状态

当前线上模板：`https://transsioner.feishu.cn/sheets/RY1cskpEnhP4OxtxX1Jceooanhb?sheet=eHWIEi`

部门决定不再通过新增列改造评审报告，而是在原始布局上补充可解析的填写说明。当前口径如下：

1. 第一区块标题采用`技术项目名（项目编码）-TDRX`，由同一标题提取项目名称、项目编码和TDR阶段；TDR阶段只使用TDR1／TDR2／TDR3。
2. 出勤只读取第一区块“缺席评审人姓名”；只填写缺席人员姓名，未在名单中的当场评审人按出席处理。
3. 个人会签结果与评审意见独立。评审意见仍写在原有意见列，不新增判断依据、改善措施、验证方式或通过条件列。
4. 评审意见填写说明要求写清具体技术对象，并记录与本人评审职责相关的判断、风险、问题或建议；原因、影响、场景、证据缺口和建议动作均可作为具体细节。
5. 问题汇总表保留原有列，只记录需要后续跟踪或闭环的具体问题；问题表不反向决定评审意见档位。
6. `TDR1+TDR2`不再使用；合并评审按TDR2记录。中英文括号、连接符、名单分隔符及标点按同一意图容错识别。
